## 三、P0：照抄必翻车 / 概念教错（6 条）

### P0-1 `pip install -D` 不是 pip 的选项，命令直接失败

- **位置**：`05-模块系统与工程化.md` L184（对比表格）、L194（可复制 bash 块）
- **原文**：
  ```
  | 安装开发依赖 | `pip install -D pkg` | `poetry add -D pkg` | `npm install -D pkg` | ... |
  pip install -D pytest mypy ruff
  ```
- **问题**：`-D` 是 poetry/npm 的写法，pip 从未提供该短选项；表格把三者并列会让读者以为 pip 也有 dev 依赖分组。pip 侧根本没有 dev/prod 分组概念。
- **修复**：表格该格改为 `pip install pytest mypy ruff`（并注明"pip 无 dev 依赖分组，需另建 `requirements-dev.txt`"）；L194 改为 `pip install pytest mypy ruff`。若要保留对比价值，可加一行 `pip install -r requirements-dev.txt`。
- **验证**：`D:\Python\python.exe -m pip install -D pkg --no-index --dry-run` → `no such option: -D`（退出码 2）。**实测确认**。

### P0-2 v4 参考实现的 `index.ts` 用自己的 tsconfig 编译不过（TS1205）

- **位置**：`毕业项目-Python任务管理器/v4-模块化与工程化版.md` L241（正文）、L362（参考实现）
- **原文**：`export { TaskRepository, InMemoryRepository } from "./repository.js";`
- **问题**：`TaskRepository` 是 interface（纯类型），而同篇 L278 的 tsconfig 开了 `"isolatedModules": true`。在 isolatedModules 下再导出类型必须写 `export type`，否则 TS1205。正文 L346 的验收标准却写着"`tsc --noEmit` 零错误"。
- **修复**：
  ```ts
  export type { TaskRepository } from "./repository.js";
  export { InMemoryRepository } from "./repository.js";
  ```
- **验证**：按笔记原文拼装 `src/{types,errors,repository,task-manager,index}.ts` + 同篇 tsconfig，`tsc -p tsconfig.json` → `src/index.ts(4,10): error TS1205: Re-exporting a type when 'isolatedModules' is enabled requires using 'export type'.`（退出码 2）。**实测确认**；加上上述两行后 TS1205 消失。

### P0-3 v4 的"入口演示"把 re-export 当成本地绑定，运行即 ReferenceError

- **位置**：v4 L358-L375（"参考实现：入口演示"折叠块）
- **原文**：
  ```ts
  const repo = new InMemoryRepository();
  const manager = new TaskManager(repo);
  ```
- **问题**：该文件顶部只有 `export { ... } from "..."` 形式的**转导出**，它不会在当前模块创建本地绑定；因此 `InMemoryRepository` / `TaskManager` 在本地作用域里根本不存在。tsc 报 TS2304，编译产物运行报 ReferenceError。学习者执行 `npm run dev` 必崩。
- **修复**：演示块内补本地 import：
  ```ts
  import { InMemoryRepository } from "./repository.js";
  import { TaskManager } from "./task-manager.js";
  ```
  另：该文件用了 `process`，但 v4 的 `package.json` devDependencies 只有 `typescript`/`tsx`，缺 `@types/node`（实测 TS2580），需一并补上。
- **验证**：编译后 `node dist/index.js` → `ReferenceError: InMemoryRepository is not defined at dist/index.js:7`。**实测确认**。

### P0-4 v5 测试从 `repository.ts` 导入不存在的 `TaskError`，测试文件加载失败

- **位置**：`毕业项目-Python任务管理器/v5-测试与发布版.md` L111
- **原文**：`import { InMemoryRepository, TaskError } from "../src/repository.js";`
- **问题**：`TaskError` 定义在 v4 的 `src/errors.ts`，`repository.ts` 只是 `import { TaskError }` 后自用，**没有 re-export**。TS 报 TS2459；ESM 运行时直接 `SyntaxError: The requested module ... does not provide an export named 'TaskError'`，整个测试文件一行都跑不了（L134/L135/L176 三处断言全废）。
- **修复**：`import { InMemoryRepository } from "../src/repository.js";` + `import { TaskError } from "../src/errors.js";`
- **验证**：把 v5 测试放进 v4 工程目录，`tsc --noEmit tests/repository.test.ts` → `error TS2459: Module '"../src/repository.js"' declares 'TaskError' locally, but it is not exported.` **实测确认**。

### P0-5 Flask 示例的 DELETE 路由方法名被写成了带引号的字符串，路由永不匹配

- **位置**：`99-第三周复习检查点.md` L86
- **原文**：`@app.route("/tasks/<int:task_id>", methods=["\"DELETE\""])`
- **问题**：`methods` 列表里的元素是 `"DELETE"`（8 个字符，含两个双引号），不是 HTTP 方法 `DELETE`。Flask/Werkzeug 只是把字符串 upper 后放进允许方法集合，不会替你剥引号，于是该规则允许的方法集合里没有 `DELETE` —— `DELETE /tasks/1` 得到 405/404，而且**不会抛任何异常**，属于最危险的静默语义错误。这一篇是"Flask→Express 迁移"练习的输入，学员照抄就把 bug 带进 TS 对照。
- **修复**：`methods=["DELETE"]`。同时建议在验收标准里加一条"`curl -X DELETE /tasks/1` 返回 204"。
- **验证**：`python 3.14.6` 实测 `repr(m[0]) == '"DELETE"'`、长度 8、`m[0] == "DELETE"` 为 `False`；本机未装 flask/werkzeug，路由注册行为按 Werkzeug `Rule.methods` 语义推理（**部分推理**）。

### P0-6 `tuple[str, ...]` 被映射成 `[string, ...number[]]`，语义完全变了

- **位置**：`01-环境搭建与基础类型对比.md` L259
- **原文**：`| \`tuple[str, ...]\`（可变元组） | \`[string, ...number[]]\` | TS 用展开语法 |`
- **问题**：Python 的 `tuple[str, ...]` 是"任意多个 str"（同构变长），对应 TS 的 `string[]` 或 `[string, ...string[]]`；`[string, ...number[]]` 是"第一个 string，后面全是 number"（异构），Python 里没有直接对应写法。这张表是本路径的核心交付物（Python 锚点映射），教错会直接污染读者的类型直觉。
- **修复**：该行改为 `tuple[str, ...]` → `string[]`（或 `[string, ...string[]]`）；若要表达"首元素 string、其余 number"，Python 侧需用 PEP 646 的 `tuple[str, *tuple[int, ...]]`（3.11+）或退回 `tuple[object, ...]` + 运行时校验，TS 侧才能写 `[string, ...number[]]`。
- **验证**：`const bad: [string, ...number[]] = ["a","b"]` → `error TS2322: Type '[string, string]' is not assignable to type '[string, ...number[]]'`；而 `["a","b"]` 在 Python 侧是完全合法的 `tuple[str, ...]` 值（`get_args` 实测 `(<class 'str'>, Ellipsis)`）。**实测确认**。

## 四、P1：重要缺陷（13 条）

### P1-1 Python `TypeVar` 默认值：三篇三种说法，且 03 的说法是错的

- **位置**：`03` L107、L137；`毕业项目/v2` L269；对照 `00` L17
- **原文**：03「泛型默认值 | ❌ 不支持 | ✅ `<T = string>` | TS 独有」；v2「默认值 | Python 3.12+ 支持」
- **问题**：PEP 696（Type defaults for TypeVar）落在 **Python 3.13**。00 写对了（3.13），03 说"Python 不支持"（对 3.13+ 是错的），v2 说"3.12+"（早了一个版本）。同一能力在三篇里给了三个版本口径，读者无法判断该信谁。
- **修复**：03 改为"Python 3.13+ 支持（PEP 696）`T = TypeVar("T", default=str)`；3.12 及以前不支持"；v2 表改为"Python 3.13+（PEP 696）"；并在 00 的版本基线注记里点明"本路径示例按 3.12 语义书写，3.13+ 可直接写默认值"。
- **验证**：本机 3.14.6 实测 `typing.TypeVar("T", default=int).__default__` → `<class 'int'>`；PEP 696 标注 3.13（python.org/peps/pep-0696）。**实测 + 文档**。

### P1-2 03 断言 `getProperty(user, "email")` 会编译报错，实际完全合法

- **位置**：`03-类型系统进阶-TS独有武器.md` L174
- **原文**：`// getProperty(user, "email");  // ❌ 编译报错`
- **问题**：`User` 的三个键就是 name/age/email，`email` 是合法 key，这行不仅不报错，还是 `keyof` 约束的正例。注释想演示"非法 key 报错"，却把正例标成反例——读者会以为 `keyof` 约束连合法键都拒。
- **修复**：改成 `// getProperty(user, "phone");  // ❌ 编译报错：'phone' 不在 keyof User 中`。
- **验证**：原样编译退出码 0（无任何报错）。**实测确认**。

### P1-3 "TypeScript 6.0 计划把 `--erasableSyntaxOnly` 作为默认"与官方 release notes 不符

- **位置**：`01` L429
- **原文**：「TypeScript 6.0 计划将 `--erasableSyntaxOnly` 作为默认，enum 会被限制。」
- **问题**：`erasableSyntaxOnly` 是 5.8 引入的**可选** flag；TS 6.0（2026-03-23）的实际新默认是 `strict: true`、`module: esnext`、`target: es2025`、`types: []`、`rootDir: .`，官方 6.0 release notes 未把 erasableSyntaxOnly 设为默认。把它写成"6.0 默认"会让读者误判 enum 已被语言层限制。
- **修复**：改为"TypeScript 5.8 引入可选的 `--erasableSyntaxOnly`；开启后带运行时语义的 enum/参数属性/namespace 会报错。Node 23.6+ 原生跑 TS 时默认只支持可擦除语法，新项目建议主动开启该 flag。"
- **验证**：typescriptlang.org/docs/handbook/release-notes/typescript-6-0.html（新默认清单，无 erasableSyntaxOnly）；5-8 release notes（该 flag 为 opt-in）。**官方文档**。

### P1-4 `06` 坑 1 说"Python 的 `or` ≠ TS 的 `||`"，与自己的例子和 99-2 答案直接矛盾

- **位置**：`06` L713-L719；对照 `99-第二周复习检查点.md` L219
- **原文**：06「**坑 1：Python 的 `or` ≠ TS 的 `||`**」；99-2 答案「**A**。Python 和 TS 的 `||` 行为相同」
- **问题**：两侧都是"返回第一个 truthy 操作数，否则返回最后一个"，`0 or "default"` 与 `0 || "default"` 都得到 `"default"`。06 的正文例子恰好证明了它们相同，标题却写"≠"；99-2 的选择题答案又写"相同"。同一概念两处相反。
- **修复**：06 标题改为「**坑 1：Python 的 `or` = TS 的 `||`，但都不等于 `??`**」，正文保留 `0 || "default" → "default"` 与 `0 ?? "default" → 0` 的对比，并补一句"Python 没有 `??` 的等价物，最接近的是 `x if x is not None else y`"。
- **验证**：`0 or "default"`（Python 3.14）与 `0 || "default"`（Node 24）均返回 `"default"`。**实测确认**。

### P1-5 `04` 说 `for await...of` 是"TS 独有"，同页下方就给出了 Python 的 `async for` 等价代码

- **位置**：`04` L521
- **原文**：`// ★ async iterator：异步迭代器（TS 独有 for await...of）`
- **问题**：Python 3.5+ 就有 `async for` / `__aiter__` / `__anext__`，本节 L539-L552 的对照代码正是 `async def fetch_pages(...)` + `async for page in ...`。标成"TS 独有"与自己的例子冲突，也会让读者在面试里说错。
- **修复**：改为"异步迭代器：TS 用 `for await...of` + `Symbol.asyncIterator`，Python 用 `async for` + `__aiter__/__anext__`，概念对等、语法不同"。
- **验证**：Python 3.14 `async for` 可用（同页示例 `py_compile` 通过；顶层 `async for` 属片段问题见 P2-14）。**实测 + 语言规范**。

### P1-6 `04` 的 `Promise.all/allSettled/race/any` 示例签名与 `fetch` 返回类型不符（4 处 TS2322）

- **位置**：`04` L195-L224（块内 L197、L207、L216、L221）
- **原文**：`async function parallelDemo(): Promise<string[]> { const results = await Promise.all([fetch("url1"), ...]) }`
- **问题**：`fetch` 返回 `Promise<Response>`，`Promise.all` 得到 `Response[]`，赋给 `string[]` 直接报错；`allSettled`/`race`/`any` 三例同病。这段是"并发模式对比"的主示例，读者复制后满屏红。
- **修复**：把伪 `fetch` 改名并声明返回类型，例如 `declare function fetchText(url: string): Promise<string>;`，或把返回类型改成 `Promise<Response[]>` 并在注释说明"这里用 Response，取文本要 `await r.text()`"。
- **验证**：`tsc --noEmit --strict --target es2022 --lib es2022,dom` → 4 条 `TS2322: Type 'Response' is not assignable to type 'string'`。**实测确认**。

### P1-7 `06` 单例示例里 `private constructor` 与模块级 `new Database(...)` 不能共存

- **位置**：`06` L132-L156（块内 L137、L144）
- **原文**：`private constructor(public url: string) {}` … `export const db = new Database("postgres://...");`
- **问题**：同一块先给"私有构造 + getInstance"，再给"模块级单例"，但后者在类外 `new`，被 private 构造挡住，TS2673。三个"替代方案"被塞进一个块，互相打架。
- **修复**：拆成两个独立块；模块级单例那块去掉 `private`（或改成 `static create()`），并注明"模块级单例不需要 private 构造，模块缓存本身就是单例"。
- **验证**：编译该块 → `error TS2673: Constructor of class 'Database' is private and only accessible within the class declaration.` **实测确认**。

### P1-8 `07` 的 Python Dockerfile 在只 COPY `pyproject.toml` 时执行 `pip install .`

- **位置**：`07-业务场景实战合集.md` L718-L725（L722）
- **原文**：`COPY pyproject.toml ./` → `RUN pip install --no-cache-dir .`
- **问题**：`pip install .` 要构建**当前目录的包**，此时源码（`app/`）还没 COPY 进来，只有 pyproject.toml。这行要么因找不到包直接失败，要么装出一个不含代码的空包；随后的 `COPY . .` 又不会重装。它既没起到"缓存依赖"的作用，也不是可用的安装步骤（真正让容器跑起来的是 WORKDIR 下的 `app/`，属于"碰巧能跑"）。
- **修复**：改成两段式缓存：
  ```dockerfile
  COPY pyproject.toml ./
  RUN pip install --no-cache-dir poetry && poetry export -f requirements.txt -o requirements.txt --without-hashes && pip install -r requirements.txt
  COPY . .
  ```
  或直接 `COPY . .` 后再 `pip install --no-cache-dir .`（放弃缓存优化，但正确）。
- **验证**：本机无 Docker，未实跑；已实测"仅含 pyproject.toml 的目录无法完成 `pip install .` 的构建准备"（`BackendUnavailable`），且 pip 的构建语义要求项目源码在场。**推理 + 部分实测**。

### P1-9 `v2` 的 Python 对照代码用了不存在的 `Omit[T, "id"]`

- **位置**：`毕业项目/v2-接口与泛型版.md` L58
- **原文**：`def add(self, item: Omit[T, "id"]) -> T:  # Python 无 Omit，需手动`
- **问题**：注释自己都写了"Python 无 Omit"，代码却把 `Omit[T, "id"]` 当作合法注解用。注解求值时会 `NameError: name 'Omit' is not defined`（Python 3.14 因 PEP 649 延迟求值，定义时不炸，但 `get_type_hints` / 任何静态检查都会炸）。这不是"示意"，而是一段任何类型检查器都无法通过的代码。
- **修复**：删掉该行签名里的 `Omit`，改为 `def add(self, item: dict) -> T:` 并注释"Python 用 TypedDict/Protocol 手工表达'除 id 外的字段'，或用 `dataclasses.replace`"；或直接写 `def add(self, item: "TaskCreate") -> T:` 并单独定义 `TaskCreate`。
- **验证**：`typing.get_type_hints(Repository.add)` → `NameError: name 'Omit' is not defined`。**实测确认**。

### P1-10 `v5` 文内 Node 版本矩阵自相矛盾（20/22/24 vs 18/20/22）

### P1-11 `08` Q10 把 `setTimeout(0)` 与 `setImmediate` 的顺序写成确定结论

- **位置**：`08` L282-L285
- **原文**：`// 输出: 3 → 1 → 2`
- **问题**：Node 官方文档明确说：在**主模块**里，`setTimeout(0)` 与 `setImmediate` 的先后"取决于进程启动时的性能"，是不确定的；只有在 I/O 回调内部 `setImmediate` 才总是先。把不确定写成确定，读者换台机器就会发现"例子跑错了"，进而怀疑微任务结论。本机 12 次均得 `3→1→2`，恰恰说明"本机能复现≠语言保证"。
- **修复**：改为"微任务一定先（3 最先）；`setTimeout(0)` 与 `setImmediate` 在主模块中的先后**不确定**，在 I/O 回调里 `setImmediate` 先"，并把示例包进 `fs.readFile` 回调演示确定性版本。
- **验证**：本机 Node 24 循环 12 次均为 `3→1→2`；nodejs.org 文档 "setImmediate vs setTimeout" 明示顶层顺序不确定。**实测 + 官方文档**。

### P1-12 `08` Q16 的装饰器示例是 legacy 签名，在 TS 5.x 默认配置下编译失败

- **位置**：`08` L413-L427（L415）
- **原文**：`function measure(target: any, key: string, desc: PropertyDescriptor) { const original = desc.value; ... }`
- **问题**：这是 `experimentalDecorators: true` 时代的 legacy 方法装饰器签名。TS 5.0 起默认是 Stage 3 标准装饰器，方法装饰器签名是 `(value: Function, context: ClassMethodDecoratorContext)`，`desc.value` 也不存在 → TS1241。而 `00` L17 明确说"默认无需 experimentalDecorators"，等于本篇示例与路径自己的版本口径打架。
- **修复**：改写为标准装饰器：
  ```ts
  function measure<This, Args extends unknown[], R>(
    value: (this: This, ...args: Args) => R,
    ctx: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => R>
  ) { ... }
  ```
  若想保留 legacy 写法，必须在同块标注 `// 需 tsconfig: "experimentalDecorators": true`。（上面是示意：标准方法装饰器返回 `void` 或替换函数，`ctx` 提供 `name`/`kind` 等元数据，不再是 `PropertyDescriptor`。）
- **验证**：默认配置编译 → `error TS1241: Unable to resolve signature of method decorator when called as an expression.` **实测确认**。

### P1-13 `05` 的 "strict 模式开启的 8 项检查" 在 5.6+ 已变 9 项

- **位置**：`05` L308-L319
- **原文**：`### 3.2 strict 模式开启的 8 项检查`
- **问题**：TS 5.6 新增 `strictBuiltinIteratorReturn` 并纳入 `--strict`（内置迭代器的 `TReturn` 从 `any` 变 `undefined`）。教学基线写"5.5+"、又提 6.0，这张表却停在 9 项之前；如果读者拿它去答面试题会被追问。另：`alwaysStrict` 在 6.0 已"永远开启、不可关闭"。
- **修复**：标题改"9 项"，表里补一行 `strictBuiltinIteratorReturn | 内置迭代器 TReturn 为 undefined | 无`，并加注"6.0 起 alwaysStrict 恒为 true、esModuleInterop 恒为 true"。
- **验证**：tsconfig 参考页把 `strictBuiltinIteratorReturn` 列为 strict 家族成员；5.6 release notes "enabled with --strict"。本机 tsc 5.5.4 尚无此 flag（`--help --all` 无此项），故未能本地复现 9 项行为。**官方文档**。
