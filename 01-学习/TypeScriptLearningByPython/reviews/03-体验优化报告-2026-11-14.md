## 三、P1：体验缺陷（3 条）

### E-1 8 篇正文零练习，第一个动手点在 10 小时之后

- **位置**：`01`-`08` 全文（`grep 练习` 命中 0 次）；首个练习在 `99-第一周复习检查点.md` L44
- **原文**：01-08 只有"阅读 + 代码示例 + 常见易错点 + 自检"，没有"你的任务"；99-1 才第一次出现"练习 1：将 Python dataclass 迁移为 TS"
- **问题**：按 00 的学时，学完 01-03 需 10h，这段时间读者全程只读不写。Python 背景的人最容易在"看懂了"和"写得出"之间产生错觉，而 03（最难的 5h）结束后才第一次被检验。项目 v1 的定位是"能不能用 TS 的判定"，本可以更早承担这个角色。
- **修复（低成本方案）**：在每篇末尾、自检之前插入一个 **15-30 分钟"微练习"**，只给任务 + 验收命令，答案放在折叠块：
  | 篇 | 微练习（可验证） | 验收 |
  |----|------------------|------|
  | 01 | 把一段 20 行 Python（含 `Optional`、`dict[str,int]`、`Union`）标注为 TS | `tsc --strict` 0 error |
  | 02 | 把 Python `@dataclass Task` 改成 `interface` + `class`，含 `@property` → getter/setter | `tsc --noEmit` 0 error + 手写 3 条断言 |
  | 03 | 写 `DeepPartial<T>` 与 `PickByValue<T, V>` | 两个类型各自用 2 个正例 + 1 个 `@ts-expect-error` 反例 |
  | 04 | 把 `asyncio.gather` 版本改写成 `Promise.allSettled` + 超时 | 跑通 3 个 mock promise，打印 3 种状态 |
  | 05 | 给现有项目加 `exports`/`types`/`files` 三字段并用 `npm pack --dry-run` 看清单 | 输出包含 dist/index.js 与 .d.ts |
  | 06 | 从 12+15 个特性里挑 3 个，各写 10 行"迁移前后"对照 | 3 组对照各自可运行 |
  | 07 | 场景 1 的 Express 版本加一条 `DELETE /todos/:id` | supertest 断言 204 |
  | 08 | 从 20 问里抽 3 题录音作答，回放找卡壳点 | 每题 ≤90s，含结论/机制/坑 |
- **验证**：`grep -c 练习` 对 01-08 均为 0（实测）。修复方案里的验收命令均可用本机工具链执行。**实测 + 设计建议**。

### E-2 08 的 20 道面试题被压成 3 条自检，等于没有自检

- **位置**：`08` L536-L542
- **原文**：`| 🟢 基础 | 能清晰回答 Q1-Q6（类型系统基础对比） |` / `| 🟡 进阶 | 能清晰回答 Q7-Q10 … 和 Q11-Q14 … |`
- **问题**："能清晰回答 6 个问题"不是一个可判定的单元：答对 4 题算不算通过？没有单题判定点、没有时间限制、没有"答到什么程度算过"的标准。而 08 恰恰是全路径最需要"可自测"的一篇（面试场景）。
- **修复**：改为"按题给判定点"的三级结构（见第五节起草稿），并给出最小通过线（如"🟢：任抽 2 题，90 秒内说出结论+1 个差异+1 个坑；🟡：Q7-Q14 八题各写 3 行提纲，覆盖 ≥6 题；🔴：手写 Q13 并制造一次编译错误"）。
- **验证**：条目可判定性审查（"能清晰回答 Q1-Q6"无观察物）。**推理**。

### E-3 约三成自检项不可判定（"能解释/能对比"没有观察物）

- **位置**：01-08 共 40 条自检项
- **原文（示例）**：02「能解释 `this` 在普通方法和箭头函数中的绑定差异，给出三种解决方案」；04「能解释 Node.js 事件循环中微任务和宏任务的执行顺序」；06「能完整画出 Python→TS 迁移心智模型对比图」
- **问题**：逐条分级后，40 条里约 **12 条（30%）**没有可观察产出——"能解释"可以是背出原文，也可以是理解错误；"能画出对比图"没有覆盖度要求。其余 28 条尚可（能跑命令、能数出 N 个、能写出某类型）。
- **修复**：统一改写成"**产出物 + 判定线**"句式，例如：
  - 02「能解释 this 绑定」→「写出 3 个 `this` 丢失的最小复现（普通方法回调 / 解构赋值 / setTimeout），每个附 1 行修复；3/3 能跑出预期输出」
  - 04「能解释微宏任务」→「给定 6 行混合 `setTimeout`/`Promise.then`/`await` 的代码，先写输出顺序再运行验证，6/6 一致」
  - 06「能画迁移图」→「画出含 3 个维度（类型/并发/工程化）× 各 2 个差异点的对照图，能指着图讲 2 分钟」
- **验证**：40 条逐条分类计数（可跑 9 / 可数 19 / 不可判定 12）。**实测（人工分类）**。
