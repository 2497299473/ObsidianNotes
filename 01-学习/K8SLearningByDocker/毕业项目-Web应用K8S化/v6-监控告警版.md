## 版本目标

在 v5 的 Helm Chart 基础上，集成完整的可观测性栈：**Metrics（Prometheus）+ Dashboard（Grafana）+ Alerting（AlertManager）**。从 Docker 的 `docker stats` / 日志查看，升级到 K8S 的全栈监控。

## Docker 监控回顾

```bash
# Docker 方式：手动查看
docker stats              # CPU/内存/IO（实时，但无历史）
docker logs -f web        # 应用日志
# 无告警系统，无长期存储，无可视化面板
```

```yaml
# Docker Compose + Prometheus（手动配置 scrape 目标）
services:
  prometheus:
    image: prom/prometheus
    ports: ["9090:9090"]
    volumes: ["./prometheus.yml:/etc/prometheus/prometheus.yml"]
  node-exporter:
    image: prom/node-exporter
    pid: host
  grafana:
    image: grafana/grafana
    ports: ["3000:3000"]
```

> [!important] Docker 监控的痛点
> • `docker stats` 只有实时数据，无历史存储
> • Prometheus 需手动配置每个 scrape 目标
> • 新增容器后需手动更新配置
> • 无自动发现机制

## v6 改造：Helm 集成监控栈

**只改一个维度**：在 v5 Helm Chart 中添加可观测性。

| 维度 | v5 | v6 |
|------|-----|-----|
| 部署方式 | Helm Chart | Helm Chart（不变） |
| 监控 | 无 | Prometheus Operator + ServiceMonitor |
| 告警 | 无 | AlertManager 规则 |
| 日志 | kubectl logs | Fluentd DaemonSet → Loki |

## 1. 安装 kube-prometheus-stack

```bash
# 1. 添加 Prometheus 社区仓库
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# 2. 安装完整监控栈（Prometheus + Grafana + AlertManager + Node Exporter）
helm install monitoring prometheus-community/kube-prometheus-stack \
  --namespace monitoring --create-namespace \
  --set grafana.adminPassword=admin123 \
  --set prometheus.prometheusSpec.retention=15d \
  --set prometheus.prometheusSpec.storageSpec.volumeClaimTemplate.spec.resources.requests.storage=10Gi

# 3. 验证监控组件
kubectl get pods -n monitoring
# NAME                                          READY   STATUS
# monitoring-grafana-xxx                        1/1     Running
# monitoring-kube-prometheus-prometheus-xxx     2/2     Running
# monitoring-kube-prometheus-alertmanager-xxx    2/2     Running
# monitoring-kube-prometheus-operator-xxx        1/1     Running
# monitoring-prometheus-node-exporter-xxx        1/1     Running
```

> [!tip] Helm 一键安装 vs Docker 手动配置
> Docker 中安装 Prometheus + Grafana + AlertManager 需要写 Compose 文件 + 手动配置 scrape 目标。K8S 用 Helm 一条命令搞定，且 Prometheus Operator 自动发现 Pod/Service。

## 2. 应用暴露 Metrics 端点

### 2.1 应用侧添加 /metrics 端点

```python
# Flask 应用添加 Prometheus 指标暴露
import time
from flask import Flask, request, g
from prometheus_client import Counter, Histogram, generate_latest

app = Flask(__name__)

# 自定义指标（带 status 标签，告警规则才能按 status=~"5.." 过滤）
REQUEST_COUNT = Counter('flask_request_total', 'Total requests', ['method', 'endpoint', 'status'])
REQUEST_LATENCY = Histogram('flask_request_duration_seconds', 'Request latency', ['method', 'endpoint', 'status'])

@app.route('/metrics')
def metrics():
    return generate_latest(), 200, {'Content-Type': 'text/plain'}

@app.before_request
def before_request():
    g.start = time.time()    # 记录请求开始时间

@app.after_request
def after_request(response):
    # Flask 的 Response 没有 elapsed 属性，需手动计算耗时
    REQUEST_COUNT.labels(method=request.method, endpoint=request.path,
                         status=response.status_code).inc()
    REQUEST_LATENCY.labels(method=request.method, endpoint=request.path,
                           status=response.status_code).observe(time.time() - g.start)
    return response
```

```dockerfile
# Dockerfile 中安装 prometheus-client
FROM python:3.12-alpine
RUN pip install flask prometheus-client
COPY app.py .
CMD ["python", "app.py"]
```

### 2.2 Helm Chart 添加 ServiceMonitor

```yaml
# templates/servicemonitor.yaml —— Prometheus 自动发现
{{- if .Values.monitoring.enabled }}
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: {{ include "myapp.fullname" . }}
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
    release: monitoring    # ★ 必须匹配 kube-prometheus-stack 的 release 标签
spec:
  selector:
    matchLabels:
      {{- include "myapp.selectorLabels" . | nindent 6 }}
  endpoints:
  - port: http             # 采集 Service 的 http 端口（命名端口，见下方说明）
    path: /metrics         # 指标暴露路径
    interval: 15s          # 每 15 秒采集一次
{{- end }}
```

> [!important] `endpoints.port: http` 引用的是 Service 的命名端口
> 它不是端口号，而是 v5 Chart 中 `templates/api-service.yaml` 定义的端口名。需要给该 Service 的端口命名：`ports: [{ name: http, port: 5000, targetPort: 5000 }]`，否则 ServiceMonitor 匹配不到端点，Prometheus 采集不到指标。

```yaml
# values.yaml 添加监控配置
monitoring:
  enabled: true
  port: 5000
  metricsPath: /metrics
  scrapeInterval: 15s
```

## 3. 配置告警规则

```yaml
# templates/prometheusrule.yaml —— 告警规则
{{- if .Values.monitoring.alerts.enabled }}
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: {{ include "myapp.fullname" . }}-alerts
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
    release: monitoring
spec:
  groups:
  - name: myapp-alerts
    rules:
    # 规则 1：API 错误率 > 1%
    - alert: HighErrorRate
      expr: |
        sum(rate(flask_request_total{status=~"5.."}[5m]))
        / sum(rate(flask_request_total[5m])) > 0.01
      for: 5m
      labels:
        severity: critical
      annotations:
        summary: "{{ .Release.Name }} error rate > 1%"
        description: "API 5xx 错误率超过 1%，持续 5 分钟"

    # 规则 2：响应时间 P99 > 1s
    - alert: HighLatency
      expr: |
        histogram_quantile(0.99,
          rate(flask_request_duration_seconds_bucket[5m])) > 1
      for: 10m
      labels:
        severity: warning
      annotations:
        summary: "{{ .Release.Name }} P99 latency > 1s"

    # 规则 3：Pod 重启次数 > 3
    - alert: PodRestart
      expr: increase(kube_pod_container_status_restarts_total[1h]) > 3
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "Pod {{`{{ $labels.pod }}`}} restarted > 3 times"
{{- end }}
```

```yaml
# values.yaml 添加告警配置
monitoring:
  enabled: true
  alerts:
    enabled: true
    errorRateThreshold: 0.01    # 1% 错误率
    latencyThreshold: 1         # P99 1s
```

## 4. 部署与验证

```bash
# 1. 升级 Helm Chart（添加监控）——chart 目录与 v5 统一为 webapp-chart
helm upgrade myapp ./webapp-chart -f values-prod.yaml -n prod

# 2. 验证 ServiceMonitor 被自动发现
kubectl get servicemonitor -n prod
# Prometheus Operator 自动采集 /metrics

# 3. 在 Prometheus 中查询指标
kubectl port-forward -n monitoring svc/monitoring-kube-prometheus-prometheus 9090:9090
# 浏览器 http://localhost:9090
# 查询：rate(flask_request_total[5m])
# 查询：histogram_quantile(0.99, rate(flask_request_duration_seconds_bucket[5m]))

# 4. 在 Grafana 中查看 Dashboard
kubectl port-forward -n monitoring svc/monitoring-grafana 3000:80
# 浏览器 http://localhost:3000  用户名 admin 密码 admin123
# 创建 Dashboard，添加 Panel，查询 flask_request_total 等

# 5. 生成流量测试告警
# 压测地址按 v5 Chart 的实际产物：api Service 名为 myapp-api-svc（Release 名 myapp + 模板 -api-svc），端口 5000
# loadgen 跑在 default 命名空间，跨命名空间访问要用 FQDN：<svc>.<ns>.svc.cluster.local
# （若在 prod 命名空间内压测，短名 myapp-api-svc 即可）
kubectl run loadgen --rm -it --image=busybox:1.36 -- \
  /bin/sh -c "while true; do wget -q -O- http://myapp-api-svc.prod.svc.cluster.local:5000; done"

# 6. 在 Prometheus Alerts 页面查看告警状态
# HighErrorRate / HighLatency / PodRestart

# 7. 清理
helm uninstall myapp -n prod
helm uninstall monitoring -n monitoring
kubectl delete namespace monitoring
```

## 5. 日志收集：Fluentd DaemonSet → Loki

```yaml
# templates/fluentd-daemonset.yaml —— 每节点自动部署日志收集
{{- if .Values.logging.enabled }}
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: {{ include "myapp.fullname" . }}-fluentd
  namespace: kube-system
spec:
  selector:
    matchLabels:
      app: {{ include "myapp.fullname" . }}-fluentd
  template:
    metadata:
      labels:
        app: {{ include "myapp.fullname" . }}-fluentd
    spec:
      containers:
      - name: fluent-bit
        image: fluent/fluent-bit:3.0
        # tail 输入指向 /var/log/containers/*.log（containerd/CRI 的日志软链目录）
        volumeMounts:
        - name: varlog
          mountPath: /var/log
        - name: logcontainers
          mountPath: /var/log/containers
          readOnly: true
        - name: logpods
          mountPath: /var/log/pods
          readOnly: true
      volumes:
      - name: varlog
        hostPath:
          path: /var/log
      - name: logcontainers
        hostPath:
          path: /var/log/containers
      - name: logpods
        hostPath:
          path: /var/log/pods
{{- end }}
```

```bash
# 安装 Loki + Grafana（日志查询）
helm repo add grafana https://grafana.github.io/helm-charts
helm install loki grafana/loki-stack -n monitoring
# 在 Grafana 中用 LogQL 查询日志
# {namespace="prod"} |= "error"
```

## Docker vs K8S 监控对比

| 维度 | Docker | K8S v6 |
|------|--------|--------|
| 指标采集 | `docker stats` 实时 | Prometheus 自动发现 + 长期存储 |
| 指标暴露 | 手动配置 scrape | ServiceMonitor 自动采集 |
| 可视化 | 无内置 | Grafana Dashboard |
| 告警 | 无 | PrometheusRule → AlertManager |
| 日志 | `docker logs` 单容器 | Fluentd DaemonSet → Loki 聚合 |
| 自动发现 | 无 | Prometheus Operator 自动发现 |
| 部署方式 | Compose 手动 | Helm 一键安装 |
