## 版本目标

在 v2（网络层）基础上，**只改一个维度：添加持久化存储**，将 db 从 Deployment 改为 StatefulSet + PVC，确保 Pod 重建后数据不丢失。

## v2 → v3 改造

| 组件 | v2 | v3 | 说明 |
|------|----|-----|------|
| db | Deployment | StatefulSet + PVC | 持久化存储 + 稳定标识 |
| 存储 | 无 | PVC + StorageClass | 动态供给 |
| 网络 | Headless Service | 不变 | 仍用 Headless Service |

## Docker Compose 存储（回顾）

```yaml
services:
  db:
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:  # Docker 管理的 Volume，容器删除后数据保留
```

## K8S YAML（将 db 从 Deployment 改为 StatefulSet）

```yaml
# v3-db-statefulset.yaml
# 先删除 v1 中的 db Deployment：kubectl delete deployment db

apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: db
  labels: { app: db, version: v3 }
spec:
  serviceName: db-svc        # ★ 必须关联 Headless Service（v2 已创建）
  replicas: 1
  selector: { matchLabels: { app: db } }
  template:
    metadata: { labels: { app: db, version: v3 } }
    spec:
      containers:
      - name: postgres
        image: postgres:15-alpine
        env:
        - { name: POSTGRES_USER, value: "user" }
        - { name: POSTGRES_PASSWORD, value: "pass" }
        - { name: POSTGRES_DB, value: "app" }
        - { name: PGDATA, value: "/var/lib/postgresql/data/pgdata" }
        ports: [{ containerPort: 5432 }]
        volumeMounts:
        - { name: data, mountPath: /var/lib/postgresql/data }
        readinessProbe:                    # ★ 生产必备：数据库就绪检测
          exec:
            command: ["pg_isready", "-U", "user"]
          initialDelaySeconds: 10
          periodSeconds: 5
        resources:
          requests: { cpu: "200m", memory: "256Mi" }
          limits:   { cpu: "500m", memory: "512Mi" }
  volumeClaimTemplates:                   # ★ StatefulSet 独有
  - metadata: { name: data }
    spec:
      accessModes: [ReadWriteOnce]
      storageClassName: standard          # minikube 默认 StorageClass
      resources:
        requests:
          storage: 10Gi
```

## 验证步骤

```bash
# 1. 删除旧的 db Deployment
kubectl delete deployment db

# 2. 部署 StatefulSet
kubectl apply -f v3-db-statefulset.yaml

# 3. 验证 StatefulSet 和 PVC
kubectl get statefulset
kubectl get pods -l app=db
# NAME   READY   STATUS    AGE
# db-0   1/1     Running   30s   ← 有序命名！

kubectl get pvc
# NAME          STATUS   VOLUME    CAPACITY
# data-db-0     Bound    pvc-xxx   10Gi       ← PVC 自动创建！

# 4. 验证数据库就绪
kubectl exec -it db-0 -- pg_isready -U user
# /var/run/postgresql:5432 - accepting connections

# 5. 写入测试数据
kubectl exec -it db-0 -- psql -U user -d app -c \
  "CREATE TABLE test (id SERIAL PRIMARY KEY, value TEXT);"
kubectl exec -it db-0 -- psql -U user -d app -c \
  "INSERT INTO test (value) VALUES ('persistent-data');"

# 6. ★ 关键验证：删除 Pod → 重建 → 数据是否保留？
kubectl delete pod db-0
kubectl get pods -l app=db -w   # 观察重建

# 重建后验证数据
kubectl exec -it db-0 -- psql -U user -d app -c "SELECT * FROM test;"
# 应看到：1 | persistent-data
# ★ 数据保留！因为删除 Pod 不会删除 PVC

# 7. 验证稳定 DNS
kubectl run test --rm -it --image=alpine -- sh
nslookup db-0.db-svc.default.svc.cluster.local
# 应解析到 db-0 的 Pod IP
exit

# 8. 验证 api 连接到新 db
kubectl exec -it deployment/api -- sh -c "nc -z db-0.db-svc 5432 && echo 'DB OK'"

# 9. 清理（注意：StatefulSet 删除后 PVC 不会自动删除）
kubectl delete statefulset db
kubectl delete pvc data-db-0
```

## Docker vs K8S 对比

| 维度 | Docker Compose | K8S v3 |
|------|---------------|--------|
| 存储方式 | `volumes: pgdata`（简单） | StatefulSet + PVC + StorageClass |
| Pod 名 | 随机 | 稳定（`db-0`） |
| DNS | 服务名 | `db-0.db-svc.default.svc.cluster.local` |
| 动态供给 | 无 | StorageClass 自动创建 PV |
| 数据保护 | Docker Volume 删除危险 | PVC 不会随 Pod 自动删除 |

## 🎯 本版自检

| 层次 | 检查项 |
|------|--------|
| 🟢 基础 | StatefulSet 创建成功，PVC 自动创建并绑定，数据库正常启动 |
| 🟡 进阶 | 删除 Pod 后重建，验证数据保留（`SELECT * FROM test` 仍能看到数据） |
| 🔴 挑战 | 解释为什么 StatefulSet 删除后 PVC 不会自动删除（`reclaimPolicy` 的作用） |
