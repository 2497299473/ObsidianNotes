## 问题清单

### P1-1 生命周期（`'a` 标注与省略规则）全路径缺课，借用教学链在最高危处断开

- **位置**：`阶段一-语言基础与所有权/03-函数与所有权.md` §4「引用与借用」（L198-237）；
  全路径无一处出现 `<'a>`
- **原文**：`03.md:237`「新版 Rust 采用 NLL（Non-Lexical Lifetimes），借用的生命周期在**最后一次使用处**结束」
  / `03.md:262` `fn first_word(s: &String) -> &str {`（省略规则未讲）
- **问题**：03 课只讲了「借用合法性」（&/&mut 规则、NLL），完全没讲「引用能活多久」——
  即 `'a` 标注、生命周期省略三条规则、`struct Foo<'a>` 场景。可后果已在别处显形：
  - `毕业项目/v2-所有权建模版.md:61` 用一句「若用 &str 就得给结构体加生命周期参数」带过，
    学生此时没有任何 `'a` 语法基础；
  - `code/v2/main.rs:38` `pub fn status_mark(&self) -> &'static str` 用了 `'static`，正文零解释；
  - `阶段三/03-异步编程与Tokio.md:64` `async fn fetch_user() -> &'static str` 同样如此。
  - 阶段二 01 的 `fn largest<T: PartialOrd>(list: &[T]) -> &T`（`01-泛型与Trait.md:44`）也依赖省略规则。
- **修复建议**：在 03 课 §5 之后新增一节「§6 引用的寿命：省略与标注」（建议 2h）：
  ① 省略三规则（每输入引用一个生命周期参数；只有一个输入则输出取它；`&self` 则输出取 self）；
  ② 一个必须手写的反例 `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`；
  ③ `struct Excerpt<'a> { part: &'a str }` 一段；④ 过渡到 `'static` 与「为什么 String 更省心」。
  同步在 `00-Rust学习路径总索引.md` 的学时与 99-阶段1 知识图谱补节点。
- **验证方式与结果**：全文 grep（`生命`/`'[a-z]`）——4 处命中全为旁及
  （v2 md 1 处、v3 md「进程生命周期」1 处、03 md NLL 1 处、阶段三01「生命周期足够长」1 处），
  **无一处 `<'a>` 语法出现**；`code/v2`、`阶段三03` 的 `&'static str` 由 `cargo check` 确认存在。

### P1-2 毕业项目不是累积演进：v5 起丢弃 v3/v4 的持久化、AppError 与 Storage 抽象

- **位置**：`毕业项目-Rust任务管理器/v5-多线程并发版.md:27`、`code/v5/main.rs:1`、
  `code/v6/main.rs:1`、`code/v7/main.rs:116-120`
- **原文**：`v5.md:27`「让任务管理器迈入并发…对应阶段三…多线程并发的知识」
  / `code/v5/main.rs:1`「v5-多线程并发版（纯 std，rustc main.rs 即可编译）」
- **问题**：「基于上一版本代码，完成以下改造」在 v5/v6/v7 名义上成立，实质上能力回退：
  - v3 建立 JSON 持久化 + `AppError` + `?` 传播；v4 建立 `Storage` trait 双后端；
  - v5 改为纯 std，`TaskStore` 回到 `Vec + next_id`，**无 serde、无 AppError**；
  - v6 仍纯 std，虽然补了测试，但同样没有持久化；
  - v7 用 `Arc<Mutex<Vec<Task>>>` 从空表启动，只预置 1 条示例任务，仍无持久化。
  学员按 v1→v7 做完，最终产物比 v4 弱（不能存盘、没有错误类型、没有后端抽象），
  与 README「毕业项目版本递进」的承诺不符，也让 v3/v4 的投入失去落点。
- **修复建议**：二选一，并在 v5 篇首明写——
  ① **保线**：v5/v6/v7 继续用 v4 的 `Storage`（`Box<dyn Storage>`）注入，并发/测试/异步只是叠加；
  ② **降级但说明**：在 v5 篇首加「⚠️ 版本分叉说明：v5-v7 为聚焦并发/测试/异步，暂以内存存储演示，
     持久化线在 v7 的 sqlx 扩展方向中回归」，并把 v1-v7 一览表加一列「本版保留的能力」。
  推荐 ②（改动小、不动已验收代码），但一览表必须有，否则「递进」是空话。
- **验证方式与结果**：`cargo check` 依赖清单实测——v5/v6 的 `Cargo.toml` 无任何依赖即通过
  （`Finished dev profile`）；v7 依赖仅 tokio/axum/serde/serde_json，且 `main` 里
  `Arc::new(Mutex::new(vec![Task{...}]))` 为运行时初始值，无读盘代码。

  毕业项目 3+3+4+4+4+4+6=**28h**；合计 **90h**。

- **验证方式与结果**：逐篇读取 frontmatter `estimated_hours` 后求和（19/21/22/28，总 90）；
  与 `00` 索引 L28-30 三行数字对照。

## 结构维度的成立之处（避免只列问题）

1. **模板一致性高**：22 篇教学/项目篇统一为「⬅️前置 → ➡️后续 → 🔗关联 → 🎯学习目标 →
   正文 → 常见陷阱 → ✏️综合练习 → 🎯自检 → 📊通过标准」，读者换篇零学习成本。
2. **闭环真实存在**：3 个阶段检查点各带 mermaid 图谱 + 串联问答题 + 错题回顾表；
   七版项目每版都有「改造任务 / 验收标准 / 参考实现 / 完整参考路径」，且 `code/` 下确有可编译实现。

   与 3 个 99 的「⬅️ 前置知识」清单逐一吻合。
4. **冗余控制得当**：`String/&str` 在 阶段一03 与 阶段二03 两次出现，属螺旋加深（前者讲所有权，
   后者讲 UTF-8 索引与容量），不是复制粘贴；`parallel_stats` 在 v5/v6 各写一遍，是「单文件自包含」的
   刻意选择，可接受。
