## 🎯 v3 目标

让数据跨越进程生命周期：引入 serde + serde_json，把任务保存为 `tasks.json` 并在启动时加载；设计统一错误类型 `AppError`（Io / Json / NotFound）并实现 `From`，让 `main` 返回 `Result<(), AppError>`，全链路用 `?` 传播错误。核心关注点是错误处理与序列化，对应阶段二（核心机制与标准库）中 Option/Result、生态工具链的知识。

---

## 📋 改造任务

### 1. 任务说明
基于上一版本代码，完成以下改造：
1. 引入 serde 依赖（Cargo.toml 见下），为 `Task` 派生 `Serialize` / `Deserialize`
2. 实现 `tasks.json` 的保存与加载；文件不存在时视为首次运行，返回空存储
3. 定义 `enum AppError { Io(std::io::Error), Json(serde_json::Error), NotFound(u64) }`，并实现两个 `From`
4. 把 `main` 改为 `-> Result<(), AppError>`，IO / JSON / 业务错误全部用 `?` 传播
5. 确保 add / list / done 行为与之前一致（现在数据可以跨运行保留），不被破坏
6. 提供最小可运行步骤（`cargo run -- add 买牛奶` 等）

```rust
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, Deserialize)]
struct Task {
    id: u64,
    title: String,
    done: bool,
}

/// 统一错误类型：聚合程序中可能出现的三类错误
#[derive(Debug)]
enum AppError {
    Io(std::io::Error),
    Json(serde_json::Error),
    NotFound(u64),
}

// 有了这两个 From，? 运算符就能自动把底层错误转换成 AppError
impl From<std::io::Error> for AppError {
    fn from(e: std::io::Error) -> Self { AppError::Io(e) }
}
impl From<serde_json::Error> for AppError {
    fn from(e: serde_json::Error) -> Self { AppError::Json(e) }
}

impl TaskStore {
    fn load(path: &Path) -> Result<Self, AppError> {
        let data = match fs::read_to_string(path) {
            Ok(content) => serde_json::from_str(&content)?,
            Err(e) if e.kind() == ErrorKind::NotFound => {
                FileData { next_id: 1, tasks: Vec::new() } // 首次运行
            }
            Err(e) => return Err(e.into()),
        };
        Ok(TaskStore { data, path: path.to_path_buf() })
    }
}

/// main 返回 Result：出错时自动打印 Err 并以非零码退出
fn main() -> Result<(), AppError> {
    let mut store = TaskStore::load(Path::new("tasks.json"))?;
    // ... store.finish(id)?;   store.save()?;
    Ok(())
}
```
