## 🎯 v2 目标

以"所有权"为主线重构 v1 代码：拆分为 models / cli / store 三个模块（单文件用 `mod` 模拟，真实项目拆成 `src/` 多文件），审视结构体字段与方法签名中 `String`（拥有数据）与 `&str` / `&Task`（借用）的取舍，为 `Task` / `TaskStore` 实现方法封装内部状态，并检查全链路消除不必要的 `clone`。核心关注点是所有权设计与模块组织，对应阶段一（语言基础与所有权）的知识。

---

## 📋 改造任务

### 1. 任务说明
基于上一版本代码，完成以下改造：
1. 把 v1 的单文件代码拆成 `mod models`、`mod cli`、`mod store` 三个模块，理清职责边界
2. `TaskStore` 的字段设为私有，外部统一通过方法（`add` / `finish` / `list` / `count_where`）访问
3. 审视并注释每处 `String` 与 `&str` 的取舍：结构体字段、方法参数、返回值各选什么、为什么
4. 检查调用链，确认没有不必要的 `clone`（如 `Command::Add(String)` 的标题应直接移动进 store）
5. 确保 add / list / done 功能与 v1 一致，不被破坏
6. 提供最小可运行步骤

### 2. 验收标准

| 检查项 | 方式 |
|--------|------|
| 功能完整 | 运行并通过手动测试 |
| 代码规范 | 符合 Rust 社区最佳实践（cargo fmt/clippy） |
| 可复现 | 提供最小运行步骤 |

```rust
mod models {
    /// title 用 String：结构体是"数据拥有者"。
    /// 若用 &str 就得给结构体加生命周期参数，且数据不能活得比借用来源久，
    /// 因此"程序自己拥有的长期数据"用 String
    pub struct Task {
        pub id: u64,
        pub title: String,
        pub done: bool,
    }
}

mod store {
    use crate::models::Task;

    pub struct TaskStore {
        tasks: Vec<Task>, // 私有字段：外部只能通过方法访问
        next_id: u64,
    }

    impl TaskStore {
        /// add 按值接收 String：调用方移交所有权，函数内零额外分配。
        /// 另一种习惯写法是 add(&str) + 内部 to_string()（多一次分配）；
        /// 本程序的 Command::Add 已持有 String，直接 move 更省
        pub fn add(&mut self, title: String) -> u64 { /* ... */ }

        /// 查找返回 Option<&mut Task>：用借用暴露数据，而不是 clone 一份
        fn find_mut(&mut self, id: u64) -> Option<&mut Task> { /* ... */ }
    }
}

mod cli {
    use crate::store::TaskStore;

    /// store 以 &mut 借用传入：函数只是"使用"，所有权仍在调用方
    pub fn run(commands: Vec<Command>, store: &mut TaskStore) {
        for command in commands {
            match command {
                // title 是 Command::Add 拥有的 String，直接 move 进 store，无 clone
                Command::Add(title) => { store.add(title); }
                Command::List => store.list(),
                Command::Done(id) => { store.finish(id); }
                Command::Help => print_help(),
            }
        }
    }
}
```
