## 🎯 v5 目标

让任务管理器迈入并发：先用 `thread::scope` 对一大批任务做分片并行统计（各线程统计自己分片的 done/pending 数量，经 `mpsc` 通道汇总）；再构建"单工作线程串行执行命令、主线程接收用户输入"的并发模型——`Arc<Mutex<TaskStore>>` 保证唯一写者，命令经通道传递，体会"不要通过共享内存来通信，而要通过通信来共享内存"。核心关注点是消息传递与共享状态，对应阶段三（并发、异步与工程化）中多线程并发的知识。

## 📋 改造任务

### 1. 任务说明
基于上一版本代码，完成以下改造：
1. 实现 `parallel_stats`：把任务分片，`thread::scope` 起多个线程统计 done/pending，`mpsc` 通道汇总结果
2. 定义 `WorkerCommand` 枚举（Add / Done / List / Shutdown），理解通道消息必须 `'static + Send`（标题用 `String` 而非 `&str`）
3. 工作线程持有 `Arc<Mutex<TaskStore>>` 串行消费命令；主线程读 stdin 解析输入并发送命令
4. 保证优雅退出：输入 quit 或 stdin 结束时发送 Shutdown 并 join 工作线程
5. 确保并行统计结果与串行结果一致，已有功能不被破坏
6. 提供最小可运行步骤

### 2. 验收标准

| 检查项 | 方式 |

| 功能完整 | 运行并通过手动测试 |
| 代码规范 | 符合 Rust 社区最佳实践（cargo fmt/clippy） |

use std::sync::mpsc;
use std::sync::{Arc, Mutex};
use std::thread;

/// 并行统计：分片 + 作用域线程 + mpsc 汇总，返回 (done, pending)
fn parallel_stats(tasks: &[Task], workers: usize) -> (usize, usize) {
    let workers = workers.max(1);
    let chunk_size = (tasks.len() + workers - 1) / workers; // 向上取整
    let (tx, rx) = mpsc::channel::<(usize, usize)>();

    thread::scope(|s| {
        for piece in tasks.chunks(chunk_size) {
            let tx = tx.clone(); // 每个线程持有自己的 Sender 克隆
            // 作用域线程可以直接借用 tasks：scope 保证函数返回前
            // 所有线程都已 join，借用不会比数据活得久，无需 Arc
            s.spawn(move || {
                let done = piece.iter().filter(|t| t.done).count();
                let _ = tx.send((done, piece.len() - done));
            });
        }
    });
    drop(tx); // 丢完所有 Sender，rx 读完结果后迭代自然结束

    let (mut done, mut pending) = (0, 0);
    for (d, p) in rx { done += d; pending += p; }
    (done, pending)
}

/// 通道消息必须 'static + Send：title 用 String 移交所有权，不能用 &str
enum WorkerCommand { Add(String), Done(u64), List, Shutdown }
