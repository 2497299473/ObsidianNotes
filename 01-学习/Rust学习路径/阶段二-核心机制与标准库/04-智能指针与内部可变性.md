## 1. Box<T>：堆分配与递归类型

`Box<T>` 把数据放到堆上，栈上只留一个指针。最常见的必需场景是**递归类型**：下面 `List` 的 `Cons` 分支直接包含 `List` 自身，大小无法在编译期确定；包一层 `Box` 后大小变为「i32 + 一个指针」。

```rust
#[derive(Debug)]
enum List {
    Cons(i32, Box<List>),
    Nil,
}

use List::{Cons, Nil};

fn main() {
    let b = Box::new(5); // 5 分配到堆上，b 离开作用域时释放
    println!("b = {b}");

    let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
    println!("list = {list:?}");

    match &list {
        Cons(head, _rest) => println!("head = {head}"),
        Nil => println!("空表"),
    }
}
```

其他用途：转移大对象所有权（只拷贝指针）、trait 对象 `Box<dyn Trait>`（第 1 课已见）。

## 2. Deref 与 Drop

**Deref**：让自定义指针支持 `*` 解引用，并参与「解引用强制转换」（如 `&String → &str`）。

**Drop**：值离开作用域时自动调用，用于释放资源；需要手动提前释放用 `std::mem::drop`（不能直接调用 `x.drop()`，因为编译器随后还会再 drop 一次）。

```rust
use std::ops::Deref;

struct MyBox<T>(T);

impl<T> MyBox<T> {
    fn new(x: T) -> Self {
        MyBox(x)
    }
}

impl<T> Deref for MyBox<T> {
    type Target = T;
    fn deref(&self) -> &T {
        &self.0
    }
}

struct Guard {
    name: String,
}

impl Drop for Guard {
    fn drop(&mut self) {
        println!("释放资源: {}", self.name);
    }
}

fn main() {
    let x = 5;
    let y = MyBox::new(x);
    assert_eq!(5, *y); // *y 实际是 *(y.deref())

    let s: &str = &String::from("hello"); // Deref 强制转换
    assert_eq!(s, "hello");

    let g = Guard { name: String::from("锁A") };
    drop(g); // 提前释放：所有权移入 drop，g 此后不可用
    println!("main 结束前");
}
```

## 3. Rc<T>：引用计数共享所有权

所有权规则下每个值只有一个所有者；但图、树等结构需要「多处共享同一份数据」。`Rc<T>`（Reference Counting）记录引用数，计数归零才释放。

```rust
use std::rc::Rc;

#[derive(Debug)]
struct Task {
    title: String,
}

fn main() {
    let task = Rc::new(Task { title: String::from("准备发布") });
    let view_a = Rc::clone(&task);
    let view_b = task.clone(); // clone 等价于 Rc::clone，只增加计数

    println!("引用计数 = {}", Rc::strong_count(&task)); // 3
    println!("{task:?} / {view_a:?} / {view_b:?}");
    // main 结束时计数递减到 0，Task 被释放一次
}
```

> 💡 习惯写 `Rc::clone(&task)` 而非 `task.clone()`，表达「只是复制共享句柄、成本 O(1)」的语义。`Rc` 只提供不可变共享；且 `Rc` **不是线程安全的**（计数操作非原子）。

## 4. RefCell<T>：内部可变性

借用规则在编译期检查：不可变数据不能再被可变借用。`RefCell<T>` 把检查推迟到**运行时**——即使只持有 `&RefCell`，也能通过 `borrow_mut()` 修改内部值；违反规则时运行时 `panic`。

```rust
use std::cell::RefCell;

fn main() {
    let data = RefCell::new(vec![1, 2, 3]); // data 本身声明为不可变

    data.borrow_mut().push(4); // 运行时可变借用，语句结束即归还
    data.borrow_mut().push(5);

    let view = data.borrow(); // 运行时不可变借用
    // let bad = data.borrow_mut(); // 若与 view 同时存活 → 运行时 panic
    println!("{view:?}");
}
```

**Rc + RefCell 组合**：多个所有者 + 可变内容。这是单线程下「共享且可变」的标准答案。

```rust
use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Task {
    title: String,
    done: bool,
}

fn main() {
    let task = Rc::new(RefCell::new(Task {
        title: String::from("编写发布说明"),
        done: false,
    }));

    let board_view = Rc::clone(&task);   // 看板持有
    let report_view = Rc::clone(&task);  // 报表也持有

    board_view.borrow_mut().done = true; // 任一处修改，所有视图可见

    println!("task = {:?}", report_view.borrow());
    println!("引用计数 = {}", Rc::strong_count(&task));
}
```

**Arc 预告**：`Arc<T>` 是 `Rc` 的原子版本（atomic），可跨线程共享，代价是计数操作带同步开销；与 `Mutex` 搭配的细节在阶段三第 1 课展开。

## 5. 内存泄漏与循环引用

`Rc` 的引用计数有个盲点：**循环引用**会让计数永远无法归零，导致内存泄漏（Rust 里内存泄漏是「安全但不该发生」的）。

```rust
use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Node {
    value: i32,
    next: RefCell<Option<Rc<Node>>>,
}

fn main() {
    let a = Rc::new(Node { value: 1, next: RefCell::new(None) });
    let b = Rc::new(Node { value: 2, next: RefCell::new(Some(Rc::clone(&a))) });

    *a.next.borrow_mut() = Some(Rc::clone(&b)); // a <-> b 互相引用

    println!("a 计数 = {}", Rc::strong_count(&a)); // 2
    println!("b 计数 = {}", Rc::strong_count(&b)); // 2
    // main 结束时两者计数各减 1，仍为 1，都无法释放：泄漏
}
```

解法是**弱化其中一个方向**：`Weak<T>` 不增加强计数。典型模型是树：父→子用 `Rc`（父拥有子），子→父用 `Weak`（子只是观察父，不拥有）。

```rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

#[derive(Debug)]
struct TreeNode {
    value: i32,
    parent: RefCell<Weak<TreeNode>>,
    children: RefCell<Vec<Rc<TreeNode>>>,
}

fn main() {
    let leaf = Rc::new(TreeNode {
        value: 3,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![]),
    });

    let branch = Rc::new(TreeNode {
        value: 5,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![Rc::clone(&leaf)]),
    });

    *leaf.parent.borrow_mut() = Rc::downgrade(&branch); // 弱引用，不阻止释放

    if let Some(parent) = leaf.parent.borrow().upgrade() {
        println!("leaf 的父节点 value = {}", parent.value);
    }
    println!(
        "branch strong = {}, weak = {}",
        Rc::strong_count(&branch),
        Rc::weak_count(&branch)
    );
}
```

**四种类型对比**：

| 类型 | 所有权 | 可变性 | 线程安全 | 典型场景 |
|------|--------|--------|----------|----------|
| `Box<T>` | 唯一所有者 | 编译期借用规则 | 可 `Send`（随 T） | 堆分配、递归类型、大对象转移 |
| `Rc<T>` | 引用计数多所有者 | 仅不可变共享 | 否（非原子计数） | 单线程图/树共享 |
| `Arc<T>` | 原子引用计数多所有者 | 需配合 `Mutex` 才可写 | 是（`Send + Sync`） | 跨线程共享（阶段三） |
| `RefCell<T>` | 唯一所有者 | 运行时检查的内部可变 | `Send`（随 T）但**非 `Sync`** | 外不可变、内需变的场景（缓存、观察者） |

## 常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| Rc 循环引用 | 程序不崩但内存持续增长 | 反向边用 `Weak` + `upgrade`；定期打印 `strong_count` 自查 |
| RefCell 运行时 panic | `BorrowMutError`/`BorrowError`，编译期查不出 | 缩短 `borrow`/`borrow_mut` 的存活范围，用完即弃 |
| 跨线程使用 Rc | 编译错误（`Rc` 既非 `Send` 也非 `Sync`） | 换 `Arc`（+ `Mutex`），阶段三详解 |
| 跨线程共享 `&RefCell` | 编译错误（`RefCell` 是 `Send` 但非 `Sync`，可 move 进线程但不可共享引用） | 跨线程改数据用 `Mutex`/`RwLock` |
| 滥用内部可变性 | 任何地方都能改数据，bug 难定位 | 优先编译期借用；仅在接口确实需要「外不可变内可变」时用 |
| 手动调用 `x.drop()` | 编译错误 | 用 `drop(x)`（`std::mem::drop`）转移所有权提前释放 |
