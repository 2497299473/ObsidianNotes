## 1. Vec：常用操作与遍历中修改的借用冲突

```rust
fn main() {
    let mut tasks: Vec<String> = vec!["写文档".to_string(), "评审代码".to_string()];
    tasks.push("发布".to_string());

    if let Some(last) = tasks.pop() {
        println!("弹出: {last}");
    }

    for (i, t) in tasks.iter().enumerate() {
        println!("{i}: {t}");
    }

    // 条件删除：retain 是遍历中过滤的标准做法
    let mut nums = vec![1, 2, 3, 4, 5];
    nums.retain(|n| n % 2 == 0);
    assert_eq!(nums, [2, 4]);
}
```

**遍历中修改会报错**——遍历持有不可变借用，`push` 需要可变借用：

```rust
// 反例（无法编译）：
// let mut v = vec![1, 2, 3];
// for x in &v {
//     v.push(*x); // error: cannot borrow `v` as mutable because it is also borrowed as immutable
// }
```

正确做法：先做一份快照，再修改原集合。

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let snapshot = v.clone();
    for x in snapshot {
        v.push(x * 10); // 此时只借用了 snapshot，v 可以自由修改
    }
    println!("{v:?}"); // [1, 2, 3, 10, 20, 30]
}
```

## 2. String 与 &str 再深入

`String` 是堆上可变、拥有所有权的 UTF-8 字节缓冲；`&str` 是对一段 UTF-8 字节的借用视图。

```rust
fn main() {
    let hello = String::from("你好 Rust");
    println!("字节长度 = {}", hello.len());     // 11：每个汉字占 3 字节
    println!("字符数   = {}", hello.chars().count()); // 7

    // let c = hello[0];      // 编译错误：String 不支持索引取字符
    // let s = &hello[0..1];  // 运行时 panic：可能切在多字节字符中间

    let first = hello.chars().next().unwrap();
    println!("第一个字符: {first}");

    let mut s = String::with_capacity(32);
    s.push_str("Hello, ");
    s.push('世');
    s.push_str("界");
    let full = format!("{s}!"); // format! 返回新 String，不修改原值
    println!("{full}");
}
```

为什么不能索引？UTF-8 中每个字符占 1~4 字节，「第 n 个字节」未必是字符边界，也无法在 O(1) 内定位第 n 个字符。要按字符处理用 `chars()`，按「字位簇」处理用 `unicode-segmentation` crate。

| 对比 | `String` | `&str` |
|------|----------|--------|
| 所有权 | 拥有，随作用域释放 | 借用，指向别处的字节 |
| 可变性 | 可变（`push_str`/`push`） | 不可变视图 |
| 典型来源 | `String::from` / `to_string` / `format!` | 字符串字面量、`&string[..]` |
| 使用场景 | 需要持有或拼接文本 | 只读参数、避免拷贝 |

> 💡 函数参数优先写 `&str`：既能接字面量也能接 `&String`（Deref 强制转换）。

## 3. HashMap 与 entry API

```rust
use std::collections::HashMap;

fn main() {
    let mut counts: HashMap<String, u32> = HashMap::new();

    let tasks = ["周报", "评审", "周报", "发布", "评审", "周报"];
    for t in tasks {
        // entry：键存在返回可变引用，不存在先插入 0 再返回
        *counts.entry(t.to_string()).or_insert(0) += 1;
    }

    counts.entry("迁移".to_string()).or_insert(0); // 初始化占位

    for (name, n) in &counts {
        println!("{name}: {n}");
    }

    let reviews = counts.get("评审").copied().unwrap_or(0);
    assert_eq!(reviews, 2);
    assert!(counts.contains_key("发布"));
}
```

entry API 的价值：一次哈希查找完成「查 + 插」，避免先 `contains_key` 再 `insert` 的两次查找。

## 4. 迭代器核心：Iterator trait 与两类适配器

迭代器是惰性的：构建 `map`/`filter` 链时什么都没发生，直到被消费。

```rust
fn main() {
    let v = vec![10, 20, 30];
    let mut it = v.iter(); // Iterator::Item = &i32
    assert_eq!(it.next(), Some(&10));
    assert_eq!(it.next(), Some(&20));
    assert_eq!(it.next(), Some(&30));
    assert_eq!(it.next(), None); // 耗尽后一直返回 None
}
```

```rust
fn main() {
    // 迭代器适配器：惰性、可链式
    let squares: Vec<u32> = (1..=10)
        .map(|n| n * n)
        .filter(|n| n % 2 == 0)
        .collect();
    assert_eq!(squares, vec![4, 16, 36, 64, 100]);

    let first_three: Vec<i32> = (1..=100).take(3).collect();
    assert_eq!(first_three, vec![1, 2, 3]);

    // 消费适配器：驱动迭代到结束并产出结果
    let total: u32 = (1..=5).sum();
    assert_eq!(total, 15);
    assert!(squares.iter().any(|n| *n > 90));
    assert!(squares.iter().all(|n| *n >= 4));
    assert_eq!(squares.iter().find(|&&n| n == 36), Some(&36));
}
```

| 类别 | 例子 | 说明 |
|------|------|------|
| 适配器（惰性） | `map` / `filter` / `take` / `enumerate` / `cloned` | 返回新迭代器，不消费 |
| 消费适配器（急切） | `collect` / `sum` / `any` / `all` / `find` / `fold` | 消费迭代器产出值 |

**综合示例：用迭代器链处理任务列表**——过滤已完成、统计数量、拼接标题：

```rust
#[derive(Debug)]
struct Task {
    title: String,
    done: bool,
}

fn main() {
    let tasks = vec![
        Task { title: "买车票".into(), done: true },
        Task { title: "写周报".into(), done: false },
        Task { title: "代码评审".into(), done: true },
        Task { title: "整理桌面".into(), done: false },
    ];

    // 统计已完成数量
    let done_count = tasks.iter().filter(|t| t.done).count();

    // 未完成任务标题拼接成一行
    let pending_titles = tasks
        .iter()
        .filter(|t| !t.done)
        .map(|t| t.title.as_str())
        .collect::<Vec<_>>()
        .join(", ");

    // 所有标题的总字符数
    let total_chars: usize = tasks.iter().map(|t| t.title.chars().count()).sum();

    println!("已完成 {done_count} 项；剩余: {pending_titles}；标题共 {total_chars} 字符");
}
```

## 5. 闭包：Fn / FnMut / FnOnce 与 move

闭包会按需捕获环境变量，编译器据「捕获方式 + 调用次数要求」推导出它实现的最弱 trait：

| Trait | 捕获方式 | 可调用次数 | 典型场景 |
|-------|----------|------------|----------|
| `Fn` | 不可变借用 | 任意次 | 只读环境，如 `filter` 判断 |
| `FnMut` | 可变借用 | 任意次 | 累积结果，如 `for_each` 收集 |
| `FnOnce` | 取得所有权 | 一次 | 消费捕获的值 |

```rust
fn call_once(f: impl FnOnce() -> String) -> String {
    f()
}

fn main() {
    let tasks = vec![String::from("写周报"), String::from("评审")];

    // Fn：只读捕获 prefix
    let prefix = String::from("任务");
    let labeled: Vec<String> = tasks.iter().map(|t| format!("{prefix}: {t}")).collect();

    // FnMut：每次调用都向 log 追加
    let mut log = Vec::new();
    tasks.iter().for_each(|t| log.push(t.clone()));

    // FnOnce：title 被移进闭包并消费
    let title = String::from("发布版本");
    let note = call_once(|| title);
    // println!("{title}"); // 编译错误：title 已移动

    println!("{labeled:?} / {log:?} / {note}");
}
```

`move` 把变量的所有权强制移入闭包，常用于闭包活得比变量长的场景：

```rust
fn main() {
    let title = String::from("准备发布材料");
    let make_note = move || format!("TODO: {title}");

    // println!("{title}"); // 编译错误：title 已移入闭包
    println!("{}", make_note());
    println!("{}", make_note()); // 闭包拥有 title，可反复调用
}
```

**迭代器 vs 手写循环**：迭代器是零成本抽象——编译后与手写循环性能相当（无需逐元素边界检查，且更易被自动向量化）。书中原话的精神：你不需要为了性能放弃表达力。

## 常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| 按字节索引 `String` | `&s[0..1]` 遇汉字运行时 panic；`s[0]` 直接编译错误 | 用 `chars()` 遍历；字位簇用 unicode-segmentation |
| 遍历 `Vec` 时删除/追加元素 | 编译期借用冲突 | 过滤用 `retain`；追加先 `clone` 快照再遍历 |
| `collect` 不标注类型 | 编译错误「type annotations needed」 | `let v: Vec<_> = ...` 或 `collect::<Vec<_>>()` |
| 忘记迭代器是惰性的 | 写了 `map` 链却没任何效果 | 末尾加 `collect`/`sum`/`for_each` 等消费适配器 |
| `v.iter()` 后修改元素失败 | `iter()` 给出 `&T`，不能改 | 用 `iter_mut()` 获得 `&mut T` |
