## 1. 结构体：定义、实例化与更新语法

```rust
struct Task {
    title: String,
    done: bool,
    priority: u8,
}

fn main() {
    let task = Task {
        title: String::from("学习 Rust 所有权"),
        done: false,
        priority: 1,
    };
    println!("任务：{}（P{}）", task.title, task.priority);
}
```

### 字段 init 简写

参数名与字段名相同时可以简写，常用于构造函数：

```rust
fn build_task(title: String, done: bool, priority: u8) -> Task {
    Task { title, done, priority } // 等价于 title: title, done: done, ...
}
```

### 结构体更新语法

从已有实例「继承」未指定的字段（注意：**未指定的字段是从源实例 move 过来的**）：

```rust
fn main() {
    let base = Task {
        title: String::from("学习所有权"),
        done: false,
        priority: 1,
    };

    let extended = Task {
        done: true,
        ..base // title（String，move）与 priority（u8，Copy）来自 base
    };

    // println!("{}", base.title); // 编译错误：base 的 title 已被 move
    println!("{} 已完成：{}", extended.title, extended.done);
}
```

> 💡 提示：结构体更新语法中，源实例里被「继承」的非 Copy 字段（如 `String`）会触发 move，源实例随之失效。这完全符合 [[03-函数与所有权]] 的所有权规则。

### 元组结构体与单元结构体

```rust
struct Color(u8, u8, u8);   // 元组结构体：字段无名，按位置访问
struct Meters(f64);         // 用于区分语义相同、类型不同的值
struct Marker;              // 单元结构体：零大小，常作标记/占位类型

fn main() {
    let red = Color(255, 0, 0);
    let width = Meters(3.5);
    let _m = Marker;
    println!("{}, {}", red.0, width.0);
}
```

## 2. 方法与关联函数：impl

方法定义在 `impl` 块中，第一个参数是 self 的三种形态之一；**关联函数**（无 self）用 `Type::name` 调用，常用于构造函数。

```rust
struct Task {
    title: String,
    done: bool,
    priority: u8,
}

impl Task {
    // 关联函数（构造函数）：没有 self 参数
    fn new(title: &str, priority: u8) -> Self {
        Task {
            title: title.to_string(),
            done: false,
            priority,
        }
    }

    // &self：不可变借用，只读
    fn summary(&self) -> String {
        format!("[P{}] {}", self.priority, self.title)
    }

    // &mut self：可变借用，可修改字段
    fn complete(&mut self) {
        self.done = true;
    }

    // self：获取所有权，调用后实例被 move（常用于 into_xxx 转换）
    fn into_title(self) -> String {
        self.title
    }
}

fn main() {
    let mut t = Task::new("写 CLI 待办程序", 2);
    println!("{}", t.summary());
    t.complete();
    let title = t.into_title(); // t 被 move，之后不能再用 t
    println!("标题：{}", title);
}
```

| 第一个参数 | 含义 | 典型用途 |
|-----------|------|----------|
| `&self` | 不可变借用 | 查询、格式化（如 `summary`） |
| `&mut self` | 可变借用 | 修改自身（如 `complete`） |
| `self` | 获取所有权 | 消费式转换（如 `into_title`） |

> 💡 提示：方法名写 `self` 还是 `&self` 直接决定调用方要不要交出所有权。新手最容易漏写 `&`，导致一调用方法实例就被 move 走。

## 3. 枚举：携带数据的变体

Rust 的 enum 每个变体可以携带不同类型、不同数量的数据，是建模「多种情况之一」的利器：

```rust
enum Command {
    Add { title: String, priority: u8 }, // 结构体风格
    Done(usize),                         // 元组风格
    List,                                // 无数据
    Quit,
}

fn main() {
    let cmd = Command::Add {
        title: String::from("复习借用"),
        priority: 1,
    };
    println!("收到命令（具体内容交给 match 处理）");
    let _ = cmd;
}
```

### Option<T>：Rust 为什么没有 null

null 的问题：「可能是 null」这件事没有体现在类型里，忘判空就崩。Rust 用枚举表达「值可能缺失」：

```rust
enum Option<T> {
    Some(T),
    None,
}

fn main() {
    let some_num: Option<i32> = Some(5);
    let absent: Option<i32> = None;

    // let sum = some_num + 1; // 编译错误：Option<i32> 与 i32 不能直接相加
    let sum = match some_num {
        Some(n) => n + 1,
        None => 0,
    };
    println!("sum = {}, absent = {:?}", sum, absent);
}
```

`Option<T>` 与 `T` 是**不同类型**：编译器强制你先处理 None 的可能，「忘记判空」从运行时炸弹变成编译错误。

## 4. 模式匹配：match、if let、while let

### match：必须穷尽所有可能

```rust
struct Task {
    title: String,
    done: bool,
    priority: u8,
}

impl Task {
    fn new(title: &str, priority: u8) -> Self {
        Task { title: title.to_string(), done: false, priority }
    }
    fn complete(&mut self) { self.done = true; }
    fn summary(&self) -> String {
        format!("[P{}]{}", self.priority, self.title)
    }
}

enum Command {
    Add { title: String, priority: u8 },
    Done(usize),
    List,
    Quit,
}

fn dispatch(tasks: &mut Vec<Task>, cmd: Command) {
    match cmd {
        Command::Add { title, priority } => {
            tasks.push(Task::new(&title, priority));
            println!("已添加：{}", title);
        }
        Command::Done(i) => {
            if let Some(t) = tasks.get_mut(i) {
                t.complete();
                println!("任务 {} 完成", i);
            } else {
                println!("没有编号 {} 的任务", i);
            }
        }
        Command::List => {
            for t in tasks.iter() {
                println!("{}", t.summary());
            }
        }
        Command::Quit => println!("再见"),
    }
}

fn main() {
    let mut tasks: Vec<Task> = Vec::new();
    dispatch(&mut tasks, Command::Add { title: String::from("学习 match"), priority: 1 });
    dispatch(&mut tasks, Command::Done(0));
    dispatch(&mut tasks, Command::List);
    dispatch(&mut tasks, Command::Quit);
}
```

要点：
- match 的分支**必须穷尽**所有可能。对 `Option<T>` 漏掉 `None` 分支会直接编译错误（non-exhaustive patterns）
- `_` 通配符接住其余所有情况：`_ => println!("其他")`
- match 分支本身是表达式，也可以整体返回值

### if let / while let：只关心一种模式时的语法糖

```rust
fn main() {
    let config_max: Option<u8> = Some(3);

    // 等价于只写 Some 分支的 match
    if let Some(max) = config_max {
        println!("最大重试次数：{}", max);
    }

    // while let：循环直到模式不再匹配
    let mut stack = vec![1, 2, 3];
    while let Some(top) = stack.pop() {
        println!("弹出：{}", top);
    }
}
```

> 💡 提示：只处理一种模式用 `if let`；需要穷尽处理（尤其是多个变体的 enum）用 `match`。后面还会学到 `map`、`unwrap_or` 等组合子，让 `Option` 越用越顺手。

## 常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| match 分支不穷尽 | 编译错误 `non-exhaustive patterns`（处理 `Option` 时最常遇到） | 补齐缺失变体，或明确用 `_` 接住其余情况 |
| 方法第一个参数忘写 `&` | 方法签名成 `self`，一调用实例就被 move | 查询用 `&self`，修改用 `&mut self`，只有消费式转换才用 `self` |
| Option 用起来嫌麻烦，想绕回 null 思维 | 到处 `.unwrap()`，把编译期保护又变回运行时 panic | 用 `match` / `if let` / `unwrap_or` 明确处理 None 分支 |
| 结构体更新语法意外 move | `..base` 后 base 不能再访问 | 意识到未指定字段会被 move；需要保留就显式 clone |
