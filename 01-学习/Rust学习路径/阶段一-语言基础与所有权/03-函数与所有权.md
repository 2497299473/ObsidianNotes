## 1. 函数：语句与表达式

函数定义必须显式标注参数类型；返回值写在 `->` 后，**函数体最后一个表达式的值就是返回值**（也可以提前 `return`）。

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b // 没有分号：这是表达式，作为返回值
}

fn early_return(x: i32) -> i32 {
    if x < 0 {
        return 0; // 提前返回用 return + 分号（此时是语句）
    }
    x * 2
}

fn main() {
    println!("{}", add(2, 3));        // 5
    println!("{}", early_return(-1)); // 0
}
```

**语句**执行动作但不返回值；**表达式**求值并产生结果。块 `{}` 本身就是一个表达式：

```rust
fn main() {
    let y = {
        let x = 3;
        x + 1 // 块的求值结果
    };
    println!("y = {}", y); // 4
}
```

> 💡 提示：`if`、`loop`（带 break 值）、块都是表达式，所以都能出现在 `let` 右侧。但注意：在块末尾加上分号（`x + 1;`），它就变成了语句，整个块的类型变成 `()`，赋值时就会报类型错误。这是新手最常见的编译错误之一。

## 2. 所有权：三条规则

所有权是 Rust 内存安全的根基，三条规则：

1. **每个值都有且只有一个所有者**（owner）
2. **同一时刻只能有一个所有者**
3. **所有者离开作用域时，值被丢弃**（`drop`，自动释放内存）

### String 与 &str：为什么需要讲所有权

整数等类型存在栈上，复制成本极低；而 `String` 为了支持可变文本，数据分配在**堆**上：

```rust
fn main() {
    let mut s = String::from("hello"); // 堆上分配，栈上记录 ptr/len/capacity
    s.push_str(", rust");              // 可变
    println!("{}", s);

    let literal: &str = "hello"; // 字面量编译进二进制，是只读的字符串切片视图
} // s 离开作用域，堆内存自动 drop
```

| 类型 | 存储 | 可变性 | 说明 |
|------|------|--------|------|
| `String` | 堆 | 可变 | 拥有堆数据的所有权 |
| `&str` | 视图 | 只读 | 对某段字符串的借用切片，不拥有数据 |

## 3. move、Copy 与 Clone

### move 语义

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;               // 移动（move）：栈上的元数据被复制，堆数据不动
    // println!("{}", s1);     // 编译错误：borrow of moved value: `s1`
    println!("{}", s2);        // OK
}
```

move 前后的内存示意（堆数据不复制，只有栈上的指针元数据复制，且 s1 失效）：

```
赋值前：
  栈                            堆
  +---------------+
  s1 | ptr  ------------------>  [ h | e | l | l | o ]
     | len = 5      |
     | capacity = 5 |
  +---------------+

let s2 = s1; 之后：
  栈                            堆
  +---------------+
  s1 | (已失效)     |
  +---------------+
  +---------------+
  s2 | ptr  ------------------>  [ h | e | l | l | o ]
     | len = 5      |
     | capacity = 5 |
  +---------------+
```

这样设计的原因：如果复制指针而不失效 s1，两者离开作用域时会**双重释放**同一块堆内存。Rust 直接在编译期让 s1 失效，代价为零且杜绝了 double free。

### Copy：栈上小类型的隐式复制

实现了 `Copy` trait 的类型（整数、浮点、bool、char、仅含 Copy 类型的元组）赋值时是**复制**而不是移动：

```rust
fn main() {
    let x = 5;
    let y = x; // Copy，x 仍然可用
    println!("{}, {}", x, y);
}
```

| 类型 | 行为 |
|------|------|
| `i32`、`f64`、`bool`、`char` | `Copy`，赋值即复制 |
| `String`、`Vec<T>` | move，原变量失效 |
| `(i32, bool)` | 元素都 Copy，则整体 Copy |

> 💡 提示：`String` 不实现 `Copy` 是**有意为之**——如果隐式复制堆数据，性能陷阱无处不在。需要复制时显式调用 `clone`，让深拷贝的代价显形。

### Clone：显式深拷贝

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone(); // 深拷贝堆数据
    println!("s1 = {}, s2 = {}", s1, s2); // 两者都可用
}
```

### 函数传参与返回值也会 move

```rust
fn takes_ownership(s: String) {
    println!("{}", s);
} // s 在这里被 drop

fn gives_ownership() -> String {
    String::from("yours") // 所有权移给调用者
}

fn takes_and_gives_back(s: String) -> String {
    s // 原样还回，所有权转出
}

fn main() {
    let s1 = gives_ownership();
    let s2 = String::from("hello");
    let s3 = takes_and_gives_back(s2);

    takes_ownership(s1);
    // println!("{}", s1); // 编译错误：s1 已 move 进函数
    // println!("{}", s2); // 编译错误：s2 已 move
    println!("{}", s3);     // OK
}
```

可见：「传入再传出」的写法很笨拙——这正是**引用**存在的意义。

## 4. 引用与借用

`&` 创建引用：借用而不获取所有权，函数结束不 drop 借来的值。

```rust
fn calc_len(s: &String) -> usize { // 借用，不获取所有权
    s.len()
}

fn main() {
    let s = String::from("hello");
    let len = calc_len(&s); // 传引用
    println!("{} 的长度是 {}", s, len); // s 依然可用
}
```

### &mut 与借用规则

借用规则（同一时刻）：

1. 可以有**任意多个**不可变引用 `&T`
2. 只能有**一个**可变引用 `&mut T`
3. 不可变引用与可变引用**不能同时存在**

```rust
fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    let r2 = &s; // OK：多个不可变引用共存
    println!("{}, {}", r1, r2);
    // 到这里 r1、r2 的最后一次使用结束（NLL），借用解除

    let r3 = &mut s; // OK：现在可以独占可变借用
    r3.push_str(" world");
    println!("{}", r3);
}
```

> 💡 提示：新版 Rust 采用 NLL（Non-Lexical Lifetimes），借用的生命周期在**最后一次使用处**结束，而不是作用域末尾。所以上例中 `&s` 与 `&mut s` 看似先后出现却不冲突。

### 悬垂引用为何被编译期阻止

```rust
// fn dangle() -> &String {
//     let s = String::from("hello");
//     &s // 编译错误：s 在函数结束时被 drop，引用将悬垂
// }
//
// 正确做法：直接返回值，转移所有权
fn no_dangle() -> String {
    String::from("hello")
}
```

C 里的 use-after-free 在 Rust 中根本编译不过：编译器保证任何引用指向的数据一定还活着。

## 5. 切片（slice）：不拥有数据的连续视图

字符串切片 `&str` 是对 `String` 或字符串字面量中某段连续内容的引用：`&s[start..end]`（左闭右开）。

经典例子：查找第一个单词。如果返回下标，调用方之后修改了字符串，下标就失效了；返回切片则不同——切片持有对原字符串的不可变借用，**任何修改都会与之冲突**：

```rust
fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }

    &s[..] // 没有空格，整个字符串就是一个单词
}

fn main() {
    let s = String::from("hello world");
    let word = first_word(&s);

    // s.clear(); // 编译错误：word 的不可变借用还活着，不能可变借用 s
    println!("第一个单词：{}", word);
}
```

| 写法 | 含义 |
|------|------|
| `&s[0..5]` | 前 5 字节 |
| `&s[..]` | 整个字符串 |
| `&s[2..]` / `&s[..3]` | 到末尾 / 从头开始 |

> 💡 提示：切片按**字节**索引，在多字节 UTF-8 字符中间切片会 panic。中文处理要按 `char_indices` 或使用专门的 crate。另外 `&String` 大多数场景应写成 `&str`，后者更通用（能同时接受 `String` 和字面量）。

## 常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| 想同时读写同一数据 | `let r = &v; let m = &mut v;` 编译报错 | 重排代码：先用完不可变借用，再取可变借用；或拆分数据 |
| 迭代中修改集合 | `for x in &v { v.push(...); }` 编译报错 | 先收集结果（`collect`）再统一修改，或用下标分段处理 |
| 从函数返回局部变量的引用 | `&local_var` 编译报错（悬垂引用） | 返回拥有所有权的值（`String` 而非 `&String`），或传入借用由调用者持有 |
| move 之后继续使用原变量 | `let s2 = s1;` 后还用 `s1` 报错 | 理解 move 语义；需要保留就用 `clone()` 或传引用 |
| 把 `&str` 与 `String` 混用导致类型不符 | 函数要 `&str` 却传 `String` | `String` 传参时用 `&s`（自动解引用为 `&str`） |
