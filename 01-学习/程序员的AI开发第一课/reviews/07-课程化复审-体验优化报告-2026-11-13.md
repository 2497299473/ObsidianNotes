## 三、25 篇「本文学完自检」逐篇结论

判定口径（方法论第五节 + 本轮追加）：
- 🟢 必须是**可独立完成且可验证**的动作，不能是「理解了 X」；概念篇允许「复述+举例」，但必须带可核对对象。
- 🟡 必须组合**本篇**多个知识点，且当篇内容足以支撑（不能暗中依赖后面才教的 API）。
- 🔴 必须跨篇或含**独立判断**；若只是把正文的论证再讲一遍，属「复述」，不算挑战。

### 4.2 三条关键问题

**（1）选择题把答案标在正确选项后，自测功能失效。** 4 个检查点全部如此，形如：

```
- B. 仅当前会话（纠错信息进上下文，权重不变）✅
```

读者一眼看到答案，5 题变成 5 行阅读。改法：答案移入题末 `<details><summary>答案与解析</summary>…</details>`，或整段折叠（20min，4 个文件同批）。

**（2）C 的 v5 验收标准「结果=42」与教材示例冲突。** `13｜从头实现一个Agent.md:287–293` 实际输出是 `Observation: 22` / `Answer: … 22`，并在 `:293` 加了勘误说明（3kg 被模型读成 1kg）。学习者照 13 篇原样跑，很可能得 22，然后按检查点判定「v5 未通过」。改法（10min）：

> **v5**：水果价格题在 max_turns 内收敛；**正确结果 = 42**。若得到 22，说明模型改写了题意（见 13 篇 `:293` 勘误）——这正是本版要学的：验收必须核对「结果与题意是否一致」。

**（3）阶段 C→D 的项目线衔接断裂。** 梯表宣称「同一个命令行聊天机器人的 7 次单点增量」，实际代码是：

| 版本 | 实际内容 | 是否含前版能力 |
|------|---------|--------------|
| v1–v4 | 09 §1→§3 + 11 RAG | 累积 ✅（v4 保留了 history/trim/prompt） |
| v5 | ReAct Agent（手写/LangChain） | 不含 RAG、不含角色设定 ❌ |
| v6 | 孔子机器人 + mem0 | 回到 09 §3 的形态，**不含 v5 的 Agent** ❌ |
| v7 | `model.invoke` + 语义缓存 + 网关 | 只剩单轮调用，**不含 v1–v6 任何能力** ❌ |

后果：D 检查点的「重启后仍记得偏好」实际验收的是一个和 v5 无关的新应用，学习者会觉得「前面白做了」。两种修法见 P0-3。

## B.4 统一注记格式

三条铁律：
1. 前缀固定 `> [!note] 📮 库内出口：`（便于脚本幂等判断）。
2. **一句话**，不评价原文、不说「原文有问题」。
3. 不修改、不改写、不删除原句，只在其后**空一行**插入。

模板：

```markdown
> [!note] 📮 库内出口：本库没有{{留言区|评论区}}——{{把成果落到哪里}}，{{怎么算完成}}。
```

## B.5 执行步骤（建议脚本化，先 dry-run）

**不要**用「查找替换」批改（13/14、15/16/18、19/20/21 的句子互相雷同，易串行改错）。按**行号插入**：

```python
# insert_exit_notes.py —— dry-run 默认，--apply 才写
import io, sys, pathlib, shutil, datetime

BASE = pathlib.Path(r"D:\Notes\My-First-Obsidian\01-学习\程序员的AI开发第一课")
NOTE = "> [!note] 📮 库内出口："          # 幂等标记
MAP = [  # (文件名, 行号, 注记正文)
 ("01｜用户视角：你应该知道的LLM基础知识.md", 155, "..."),
 # … 20 行，正文见 B.3 表
]

def main(apply=False):
    if apply:
        bak = BASE / f".reviews_bak_{datetime.datetime.now():%Y%m%d%H%M%S}"
        bak.mkdir(exist_ok=True)
    log = []
    for fn, ln, text in MAP:
        p = BASE / fn
        lines = p.read_text(encoding="utf-8").split("\n")
        idx = ln - 1                      # 原句所在下标
        anchor = lines[idx]
        if "留言区" not in anchor and "评论区" not in anchor:
            log.append(f"SKIP(mismatch) {fn}:{ln}"); continue
        if idx + 1 < len(lines) and NOTE in lines[idx + 1]:
            log.append(f"SKIP(already) {fn}:{ln}"); continue
        assert lines[idx + 1].strip() == "", f"{fn}:{ln} 后不是空行，人工确认"
        lines[idx + 2:idx + 2] = [text, ""]
        if apply:
            shutil.copy2(p, bak / fn)
            p.write_text("\n".join(lines), encoding="utf-8")
        log.append(f"{'WRITE' if apply else 'DRY'} {fn}:{ln}")
    print("\n".join(log))

if __name__ == "__main__":
    main("--apply" in sys.argv)
```

执行顺序：
1. `git status` 确认工作区干净 → 2. dry-run（应输出 20 行 `DRY`，0 行 `SKIP`）→ 3. `--apply` → 4. 跑 B.6 校验 → 5. 按仓库规则提交（提交信息只写「为 20 篇剪藏追加库内出口注记，替代不存在的留言区入口；离线校验……」）。

> ⚠️ 若某篇行号因后续编辑漂移，脚本会输出 `SKIP(mismatch)`，**不要**猜行号——重新 `grep -n "留言区\|评论区"` 取新行号再跑。
