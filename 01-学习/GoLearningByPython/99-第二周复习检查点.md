## 一、理论问答

1. **Go 的接口为什么叫"隐式实现"？有什么优势？**

   > 类型只要实现了接口要求的方法，就自动满足该接口，无需显式声明 `implements`。优势是解耦、测试友好、可扩展性强。

2. **Go 的 `error` 是什么？如何处理错误？**

   > `error` 是一个接口，包含 `Error() string`。函数返回 `(result, error)`，调用方用 `if err != nil` 检查，使用 `fmt.Errorf("...: %w", err)` 包装错误。

3. **goroutine 和 Python 的 asyncio 协程有什么本质区别？**

   > asyncio 是单线程协作式调度；goroutine 由 Go 运行时多核调度，可真正并行。Go 没有 GIL。

4. **channel 的缓冲区和无缓冲区有什么区别？分别适合什么场景？**

   > 无缓冲 channel 要求发送和接收同步，适合同步场景；有缓冲 channel 允许异步发送，适合解耦。

5. **select 在 Go 中的作用是什么？**

   > select 可以同时监听多个 channel 操作，选择第一个就绪的分支执行，常用于超时控制、优雅退出、多路复用。

6. **Go 有继承、异常、装饰器、推导式吗？没有的话如何替代？**

   > 没有。继承用 struct embedding + interface；异常用 `return error`；装饰器用函数组合/中间件；推导式用 `for` 循环 + `append`。

## 二、代码练习

### 练习 1：接口多态

定义 `Shape` 接口，实现 `Circle` 和 `Rectangle`，编写 `TotalArea()` 函数。

```go
package main

import (
    "fmt"
    "math"
)

// Shape 接口定义（小而精，1 个方法）
type Shape interface {
    Area() float64
}

// Circle 圆形（隐式实现 Shape）
type Circle struct {
    Radius float64
}

func (c Circle) Area() float64 {
    return math.Pi * c.Radius * c.Radius
}

// Rectangle 矩形（隐式实现 Shape）
type Rectangle struct {
    Width, Height float64
}

func (r Rectangle) Area() float64 {
    return r.Width * r.Height
}

// TotalArea 计算所有形状的总面积
// shapes []Shape 是接口 slice，可以容纳任何实现 Shape 的类型
// 对比 Python: 用 Protocol + isinstance 检查
func TotalArea(shapes []Shape) float64 {
    var total float64
    for _, s := range shapes {
        total += s.Area()  // 多态调用：运行时根据实际类型调用对应方法
    }
    return total
}

func main() {
    // 接口 slice 可以容纳不同类型（多态）
    shapes := []Shape{
        Circle{Radius: 5},
        Rectangle{Width: 3, Height: 4},
        Circle{Radius: 1},
    }
    fmt.Printf("总面积: %.2f\n", TotalArea(shapes))
}
```

**注释**：`Circle` 和 `Rectangle` 都不需要声明 `implements Shape`，只要拥有 `Area() float64` 方法就自动满足接口。这是 Go 的隐式接口实现——比 Python 的 Protocol 更简洁，比 Java 的 `implements` 更解耦。

### 练习 2：并发下载

使用 goroutine + channel 实现并发下载 5 个 URL，统计总字节数。

```go
package main

import (
    "fmt"
    "io"
    "net/http"
    "sync"
)

// fetchSize 并发获取 URL 内容长度
func fetchSize(url string, wg *sync.WaitGroup, results chan<- int) {
    defer wg.Done()  // 确保 WaitGroup 计数减一

    resp, err := http.Get(url)
    if err != nil {
        results <- 0  // 失败返回 0
        return
    }
    defer resp.Body.Close()  // defer 确保关闭响应体

    body, _ := io.ReadAll(resp.Body)
    results <- len(body)  // 发送结果到 channel
}

func main() {
    urls := []string{
        "https://httpbin.org/json",
        "https://httpbin.org/html",
        "https://httpbin.org/xml",
        "https://httpbin.org/uuid",
        "https://httpbin.org/ip",
    }

    var wg sync.WaitGroup
    // 缓冲 channel：大小 = URL 数，避免发送阻塞
    results := make(chan int, len(urls))

    // 启动 goroutine 并发下载
    for _, url := range urls {
        wg.Add(1)
        go fetchSize(url, &wg, results)
    }

    // 等待所有 goroutine 完成
    wg.Wait()
    close(results)  // 关闭 channel，通知 range 结束

    // 收集结果并统计总字节数
    total := 0
    for size := range results {
        total += size
    }
    fmt.Printf("5 个 URL 总字节数: %d\n", total)
}
```

**注释**：对比 Python 的 `asyncio.gather(*[fetch(url) for url in urls])`，Go 用 `sync.WaitGroup` 等待。`close(results)` 必须在 `wg.Wait()` 之后——确保所有发送者都完成了发送。`defer resp.Body.Close()` 和 `defer wg.Done()` 是 Go 并发编程的标准模式。

### 练习 3：Worker Pool

实现固定 3 个 worker 的并发任务处理器，处理 20 个任务。

```go
package main

import (
    "fmt"
    "sync"
    "time"
)

// worker 从 jobs channel 读取任务，处理后将结果发送到 results channel
func worker(id int, jobs <-chan int, results chan<- string, wg *sync.WaitGroup) {
    defer wg.Done()
    // range channel：自动读取直到 close(jobs)
    for job := range jobs {
        time.Sleep(100 * time.Millisecond)  // 模拟任务耗时
        results <- fmt.Sprintf("worker-%d 处理了任务-%d", id, job)
    }
}

func main() {
    const numWorkers = 3
    const numJobs = 20

    jobs := make(chan int, numJobs)
    results := make(chan string, numJobs)
    var wg sync.WaitGroup

    // 启动 3 个 worker（扇出）
    for w := 0; w < numWorkers; w++ {
        wg.Add(1)
        go worker(w, jobs, results, &wg)
    }

    // 发送 20 个任务
    for j := 0; j < numJobs; j++ {
        jobs <- j
    }
    close(jobs)  // 关闭 jobs channel，通知 worker 没有更多任务

    // 等待所有 worker 完成
    wg.Wait()
    close(results)

    // 收集结果（扇入）
    for r := range results {
        fmt.Println(r)
    }
    fmt.Printf("完成: %d 个任务, %d 个 worker\n", numJobs, numWorkers)
}
```

**注释**：Worker Pool 是 Go 并发编程的经典模式——`jobs` channel 分发任务，`results` channel 收集结果，`close(jobs)` 通知退出。对比 Python 的 `ThreadPoolExecutor(max_workers=3)`，Go 的模式更显式但也更灵活，可以精确控制任务流和退出时机。
