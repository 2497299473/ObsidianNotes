## 一、模拟面试题

### 题 1：用三段式回答：Go 的 goroutine 为什么比 Python 的线程轻量？

> **🐍 Python 对比**：Python 线程由操作系统调度，每个线程约 8MB 栈空间，受 GIL 限制无法真正并行。
>
> **🔵 Go 标准回答**：goroutine 是用户态轻量级线程，初始栈约 2KB，可动态增长。由 Go 运行时的 GMP 调度器管理，利用多核 CPU 真并行，无 GIL。一个程序可轻松创建数十万个 goroutine。
>
> **⭐ 加分点**：GMP 模型中，G（Goroutine）→ M（OS 线程）→ P（逻辑处理器）。`runtime.GOMAXPROCS` 控制并行度。goroutine 栈可动态伸缩，不像线程固定大小。

### 题 2：用代码说明 Go 的 interface 是如何实现隐式多态的？

> **🐍 Python 对比**：Python 用 Protocol（PEP 544）或 ABC，需要显式继承或 mypy 检查。
>
> **🔵 Go 标准回答**：Go 的接口是隐式实现的——类型只要拥有接口要求的所有方法，就自动实现了该接口。

```go
type Writer interface { Write([]byte) (int, error) }
type File struct{}
func (f *File) Write(data []byte) (int, error) { return len(data), nil }
var w Writer = &File{}  // ✅ 隐式实现，无需 implements 关键字
```

> **⭐ 加分点**：解耦优势——实现者不需要知道接口的存在。空接口 `interface{}`（别名 `any`）可以接受任何类型。接口值由 `(type, value)` 对组成。

### 题 3：如何设计一个支持优雅退出和超时控制的 Go 后台服务？

> **🔵 Go 标准回答**：

```go
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()
// 用 select 同时监听工作 channel 和 ctx.Done()
select {
case result := <-work():
    return result
case <-ctx.Done():
    return ctx.Err()  // 超时或取消
}
```

> **⭐ 加分点**：用 `os.Signal` 捕获 `SIGINT`/`SIGTERM`，触发 context 取消。用 `sync.WaitGroup` 等待所有 goroutine 完成后再退出。`context` 是 Go 中传递截止时间和取消信号的标准方式。

### 题 4：Go 的错误处理与 Python 的异常相比，优劣各是什么？

> **🐍 Python 对比**：Python 用 `try/except`，错误可以隐式向上传播，代码简洁但传播路径不明确。
>
> **🔵 Go 标准回答**：Go 用显式错误返回值（`if err != nil`），错误处理路径清晰可见。代价是代码冗长（大量 `if err != nil`）。
>
> **⭐ 加分点**：`errors.Is` 和 `errors.As` 检查错误链，`fmt.Errorf("...: %w", err)` 包装错误。Go 1.20+ 的 `errors.Join` 合并多个错误。

### 题 5：如何把一个 Python FastAPI 服务迁移到 Go？需要关注哪些点？

> **🔵 Go 标准回答**：
> 1. 路由：FastAPI 装饰器 → `net/http` 或 `gin` 路由
> 2. JSON：Pydantic 自动校验 → `json.Unmarshal` + struct tag
> 3. 并发：asyncio 协程 → goroutine
> 4. 错误：HTTPException → `http.Error()` + error 返回值
> 5. 部署：Python 环境 → 单个二进制文件
>
> **⭐ 加分点**：Go 的 `sync.RWMutex` 保护并发 map（Python 靠 GIL 天然安全）。Go 编译成单个二进制文件，部署比 Python 简单得多。

## 二、综合实战

### 项目：URL 健康检查器

**需求**：

1. 从配置文件读取多个 URL
2. 每 5 秒检查一次这些 URL 是否可达
3. 并发检查所有 URL
4. 记录每次检查的结果（URL、状态码、耗时、时间戳）
5. 支持优雅退出（收到 Ctrl+C 后等待正在进行的检查完成）
6. 将结果写入 CSV 文件

```go
package main

import (
    "context"
    "encoding/csv"
    "encoding/json"
    "fmt"
    "net/http"
    "os"
    "os/signal"
    "sync"
    "syscall"
    "time"
)

// Config 配置结构体
type Config struct {
    URLs    []string `json:"urls"`
    Interval int      `json:"interval"`  // 检查间隔（秒）
}

// Result 检查结果
type Result struct {
    URL        string
    StatusCode int
    Duration   time.Duration
    Timestamp  time.Time
}

// checkURL 检查单个 URL 的可达性
func checkURL(ctx context.Context, url string, results chan<- Result, wg *sync.WaitGroup) {
    defer wg.Done()

    // 创建带超时的请求（等价 Python 的 timeout 参数）
    req, err := http.NewRequestWithContext(ctx, "GET", url, nil)
    if err != nil {
        results <- Result{URL: url, StatusCode: 0, Timestamp: time.Now()}
        return
    }

    start := time.Now()
    resp, err := http.DefaultClient.Do(req)
    duration := time.Since(start)

    if err != nil {
        results <- Result{URL: url, StatusCode: 0, Duration: duration, Timestamp: time.Now()}
        return
    }
    defer resp.Body.Close()

    results <- Result{
        URL:        url,
        StatusCode: resp.StatusCode,
        Duration:   duration,
        Timestamp:  time.Now(),
    }
}

func main() {
    // 1. 读取配置文件
    data, err := os.ReadFile("config.json")
    if err != nil {
        fmt.Println("读取配置失败:", err)
        return
    }
    var cfg Config
    if err := json.Unmarshal(data, &cfg); err != nil {
        fmt.Println("解析配置失败:", err)
        return
    }
    if cfg.Interval == 0 {
        cfg.Interval = 5  // 默认 5 秒
    }

    // 2. 准备 CSV 输出
    csvFile, err := os.Create("results.csv")
    if err != nil {
        fmt.Println("创建 CSV 失败:", err)
        return
    }
    defer csvFile.Close()
    writer := csv.NewWriter(csvFile)
    defer writer.Flush()
    writer.Write([]string{"URL", "StatusCode", "Duration", "Timestamp"})

    // 3. 设置信号监听（优雅退出）
    // 等价 Python 的 signal.signal(signal.SIGINT, handler)
    ctx, cancel := context.WithCancel(context.Background())
    defer cancel()
    sigChan := make(chan os.Signal, 1)
    signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)

    // goroutine 监听信号
    go func() {
        <-sigChan
        fmt.Println("\n收到退出信号，正在优雅退出...")
        cancel()
    }()

    // 4. 定时检查循环
    ticker := time.NewTicker(time.Duration(cfg.Interval) * time.Second)
    defer ticker.Stop()

    for {
        select {
        case <-ctx.Done():
            fmt.Println("退出完成")
            return
        case <-ticker.C:
            // 并发检查所有 URL
            var wg sync.WaitGroup
            results := make(chan Result, len(cfg.URLs))

            for _, url := range cfg.URLs {
                wg.Add(1)
                go checkURL(ctx, url, results, &wg)
            }

            // 等待所有检查完成
            wg.Wait()
            close(results)

            // 写入 CSV
            for r := range results {
                writer.Write([]string{
                    r.URL,
                    fmt.Sprintf("%d", r.StatusCode),
                    r.Duration.String(),
                    r.Timestamp.Format(time.RFC3339),
                })
                fmt.Printf("[%s] %s → %d (%v)\n",
                    r.Timestamp.Format("15:04:05"),
                    r.URL, r.StatusCode, r.Duration)
            }
            writer.Flush()
        }
    }
}
```

**Go 技术点覆盖**：

| 技术点 | 对应代码 | Python 等价 |
|--------|---------|------------|
| JSON 配置读取 | `json.Unmarshal` | `json.load` |
| goroutine 并发 | `go checkURL()` | `asyncio.gather` |
| context 超时取消 | `context.WithCancel` | `asyncio.timeout` |
| HTTP 请求 | `http.NewRequestWithContext` | `aiohttp.get` |
| CSV 写入 | `csv.NewWriter` | `csv.writer` |
| 信号处理 | `signal.Notify` | `signal.signal` |
| defer 资源清理 | `defer csvFile.Close()` | `with open()` |
| select 多路复用 | `select { case ... }` | `asyncio.wait` |
| sync.WaitGroup | `wg.Wait()` | `asyncio.gather` |

**注释**：这个综合项目覆盖了第三周的所有核心知识点。特别注意：`context.WithCancel` 创建可取消的 context，`signal.Notify` 捕获系统信号后调用 `cancel()` 触发优雅退出。`select` 同时监听 `ctx.Done()`（退出信号）和 `ticker.C`（定时触发），哪个先就绪就执行哪个。这是 Go 并发编程的经典模式。
