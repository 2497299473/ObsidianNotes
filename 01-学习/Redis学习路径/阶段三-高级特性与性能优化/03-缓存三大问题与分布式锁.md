## 📖 核心内容

### 缓存三大问题对比

| 问题 | 现象 | 根因 |
|------|------|------|
| **穿透** | 查不存在的数据，绕过缓存打 DB | 恶意攻击或查询不存在的 key |
| **击穿** | 热点 Key 过期瞬间，大量请求打 DB | 热点 key 过期 |
| **雪崩** | 大量 Key 同时过期，DB 压力骤增 | 过期时间集中 |

### 缓存穿透

**解决方案**：布隆过滤器、缓存空值

```python
# 缓存空值
value = r.get(key)
if value is None:
    value = db.query(key)
    if value is None:
        r.setex(key, 60, "EMPTY")  # 短过期空值
    else:
        r.setex(key, 300, value)
elif value == "EMPTY":
    return None  # 防穿透
```

### 缓存击穿

**解决方案**：互斥锁、逻辑过期

```python
# 互斥锁重建缓存
lock_key = f"lock:{key}"
lock = r.set(lock_key, "1", nx=True, ex=10)
if lock:
    try:
        value = db.query(key)
        r.setex(key, 300, value)
    finally:
        r.delete(lock_key)
else:
    # 未抢到锁，短暂等待后重试
    time.sleep(0.1)
    return get_with_cache(key)
```

### 缓存雪崩

**解决方案**：过期时间加随机值、多级缓存、熔断降级

```python
import random
expire = 300 + random.randint(0, 60)  # 过期时间打散
r.setex(key, expire, value)
```

### 分布式锁

**核心要求**：互斥性、避免死锁、可重入、容错性

```python
import uuid

# 最简分布式锁（SET NX EX 一条命令保证原子性）
def acquire_lock(key, expire=30):
    token = str(uuid.uuid4())
    ok = r.set(f"lock:{key}", token, nx=True, ex=expire)
    return token if ok else None

# 安全释放（Lua 保证比对+删除原子性）
unlock_script = """
if redis.call('GET', KEYS[1]) == ARGV[1] then
    return redis.call('DEL', KEYS[1])
else
    return 0
end
"""
def release_lock(key, token):
    r.eval(unlock_script, 1, f"lock:{key}", token)

# 使用
token = acquire_lock("order:1001")
if token:
    try:
        # 业务逻辑
        pass
    finally:
        release_lock("order:1001", token)
```

### Redlock 算法

Redlock 在多个独立 Redis 节点上申请锁，过半成功才认为加锁成功。

**争议**：
- 实现复杂
- 需要多个独立 Master
- 时钟漂移可能导致问题
- 业界常用单节点 `SET NX EX` + 看门狗续期（如 Redisson）

## 💻 代码示例

完整的缓存+锁方案：

```python
import redis
import time
import random
import uuid

r = redis.Redis(decode_responses=True)

def get_with_cache(key, db_query, ttl=300):
    """带互斥锁的缓存读取"""
    value = r.get(key)
    if value and value != "EMPTY":
        return value

    lock_key = f"lock:{key}"
    token = str(uuid.uuid4())
    lock = r.set(lock_key, token, nx=True, ex=10)

    if lock:
        try:
            value = db_query(key)
            if value:
                expire = ttl + random.randint(0, 60)  # 防雪崩
                r.setex(key, expire, value)
            else:
                r.setex(key, 60, "EMPTY")  # 防穿透
            return value
        finally:
            # Lua 原子释放锁
            r.eval("""
                if redis.call('GET', KEYS[1]) == ARGV[1] then
                    return redis.call('DEL', KEYS[1])
                else
                    return 0
                end
            """, 1, lock_key, token)
    else:
        time.sleep(0.1)
        return get_with_cache(key, db_query, ttl)
```

## ⚠️ 常见陷阱

| 陷阱 | 后果 | 解决方案 |
|------|------|---------|
| SETNX + EXPIRE 分两步 | 可能死锁 | 用一条 `SET NX EX` |
| 锁过期但业务未完成 | 并发问题 | 设置合理过期时间，用看门狗续期 |
| 删除锁不判断 owner | 误删他人锁 | 用唯一 token + Lua 验证 |
| 缓存空值不设置过期 | 内存浪费 | 短过期时间 |
| 雪崩不加随机过期 | 集中过期打 DB | 过期时间加随机值 |
