# 02-内存管理与性能调优

> 📍 **前置**：[[01-事务与Lua脚本]] → 本笔记 → [[03-缓存三大问题与分布式锁]]

## 🎯 学习目标

1. 理解 Redis 内存占用结构
2. 掌握过期键的三种删除策略
3. 能配置和选择 maxmemory 淘汰策略
4. 能诊断和优化大 Key、热 Key

---

## 📖 核心内容

### 内存结构

```
内存 = 数据 + 对象系统开销 + 缓冲区 + 持久化缓冲 + 复制缓冲 + 碎片
```

```bash
redis-cli INFO memory
# used_memory: 1.2G         # 实际数据
# used_memory_rss: 1.5G     # OS 分配（含碎片）
# mem_fragmentation_ratio: 1.25  # >1.5 需关注
# maxmemory: 2gb
```

### 过期键删除策略

| 策略 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 定时删除 | 到期立即删除 | 内存释放及时 | CPU 开销大 |
| 惰性删除 | 访问时检查过期 | CPU 友好 | 过期键残留 |
| 定期删除 | 周期性抽样删除 | 折中 | 有漏网之鱼 |

Redis 使用**惰性删除 + 定期删除**的组合策略。

### maxmemory 淘汰策略

```bash
# redis.conf
maxmemory 2gb
maxmemory-policy allkeys-lru
```

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| noeviction | 不淘汰，内存不足时拒绝写入 | 持久化存储 |
| allkeys-lru | 所有 Key 中淘汰最近最少使用 | 通用缓存 |
| allkeys-lfu | 所有 Key 中淘汰使用频率最少 | 热点数据 |
| volatile-lru | 带 TTL 的 Key 中淘汰 LRU | 缓存+持久混合 |
| volatile-lfu | 带 TTL 的 Key 中淘汰 LFU | 短期热点 |
| volatile-ttl | 淘汰 TTL 最短的 Key | 短期数据 |
| allkeys-random | 随机淘汰 | 无热点特征 |
| volatile-random | 带 TTL 的 Key 中随机淘汰 | 无热点特征 |

### 大 Key 治理

```bash
# 查找大 Key
redis-cli --bigkeys

# 分析某个 Key 内存
redis-cli MEMORY USAGE user:1

# 扫描内存大的 Key
redis-cli --memkeys

# 异步删除大 Key（不阻塞）
UNLINK bigkey
```

| 危害 | 表现 | 治理 |
|------|------|------|
| 阻塞 | 操作慢 | 拆分或删除 |
| 内存不均 | Cluster 节点内存倾斜 | 迁移或分片 |
| 删除阻塞 | DEL 大Key 卡顿 | 用 `UNLINK` |

### 热 Key 诊断

```bash
# 开启热点 Key 监控（需 LFU 策略）
redis-cli CONFIG SET maxmemory-policy allkeys-lfu
redis-cli --hotkeys
```

### 性能分析工具

```bash
# 1. INFO：综合状态
redis-cli INFO all
redis-cli INFO cpu        # CPU 使用
redis-cli INFO stats      # 命中/未命中、连接数

# 2. SLOWLOG：慢查询日志
redis-cli CONFIG SET slowlog-log-slower-than 10000  # >10ms 记录
redis-cli CONFIG SET slowlog-max-len 128
redis-cli SLOWLOG GET 10
redis-cli SLOWLOG RESET

# 3. 内存分析（--bigkeys / --memkeys 是 redis-cli 侧扫描，不是 MEMORY 子命令）
redis-cli --bigkeys
redis-cli --memkeys

# MEMORY 的子命令只有 USAGE / STATS / DOCTOR / MALLOC-STATS / PURGE（外加 HELP），没有 ANALYZE
redis-cli MEMORY STATS      # 内存分项：dataset.bytes / overhead / fragmentation
redis-cli MEMORY DOCTOR     # 一句话体检建议
```

### 安全基线（最小可用）

内存调优的前提是“服务没裸奔”。`protected-mode` 默认 `yes`：未配 `bind`/密码时只接受本机回环连接；一旦为图方便改成 `no` 或 `bind 0.0.0.0`，等于把无鉴权的 Redis 直接暴露到网络。

```bash
# redis.conf —— 最小安全基线
bind 127.0.0.1           # 只监听本机（多网卡内网部署则写内网 IP），禁止 0.0.0.0 裸奔
protected-mode yes       # 无 bind 且无密码时拒外连接，不要关
requirepass <强口令>      # 旧式全局口令；新项目优先用 ACL
```

ACL（6.0+，替代单一 `requirepass` 的细粒度方案）：

```bash
# 建一个只能访问 cache:* 、只能跑读命令的用户
ACL SETUSER app_read on >S3cret ~cache:* +@read -@dangerous
ACL LIST        # 看规则
ACL WHOAMI      # 当前连接身份
# 客户端：redis-cli --user app_read --pass S3cret；redis-py: Redis(username='app_read', password='S3cret')
```

> 三条铁律：① 永远不要 `bind 0.0.0.0` + 空密码 暴露公网；② `protected-mode no` 只在有防火墙/安全组兜底时临时用；③ 密码与 ACL 规则走环境变量/密钥管理，不写进仓库（本路径示例里的 `<password>` 全是占位符）。

## 💻 代码示例

```bash
# 查看内存使用
redis-cli INFO memory

# 查看慢查询
redis-cli SLOWLOG GET 10

# 查看大 Key
redis-cli --bigkeys

# 生产推荐配置
redis-cli CONFIG SET maxmemory 2gb
redis-cli CONFIG SET maxmemory-policy allkeys-lru
redis-cli CONFIG SET slowlog-log-slower-than 10000

# 启用活跃碎片整理（Redis 4.0+）
redis-cli CONFIG SET activedefrag yes
```

## ⚠️ 常见陷阱

| 陷阱 | 后果 | 解决方案 |
|------|------|---------|
| maxmemory-policy 默认 noeviction | 写入 OOM | 按业务改为 lru/lfu |
| 大 Key 阻塞 | 慢查询 | 拆分、UNLINK |
| 热 Key 单点压力过大 | 性能瓶颈 | 本地缓存、读写分离 |
| 内存碎片化严重 | RSS 远大于 used_memory | 重启或启用 active defrag |
| 不监控慢查询 | 问题发现晚 | 配置 slowlog-log-slower-than |

## 🎯 本文学完自检

| 层次 | 检查项 |
|------|--------|
| 🟢 基础 | `CONFIG GET maxmemory-policy` 读出当前值；把它改成 `allkeys-lru` 后 `CONFIG GET` 复核；`INFO memory` 里找到 `used_memory` / `used_memory_rss` / `mem_fragmentation_ratio` 三行并说出三者关系 |
| 🟡 进阶 | `CONFIG SET maxmemory 50mb` + `allkeys-lru` 后灌入超过 50MB 的数据，`INFO stats` 的 `evicted_keys` 从 0 增长；`CONFIG SET slowlog-log-slower-than 0` 后执行 `KEYS *`，`SLOWLOG GET 1` 能拓到它；`redis-cli --bigkeys` 输出最大 key 名与类型 |
| 🔴 挑战 | 用 `MEMORY STATS` 记下 `mem_fragmentation_ratio`，`CONFIG SET activedefrag yes` 前后各测一次并写对比；再用 `ACL SETUSER app_read on >口令 ~cache:* +@read -@dangerous` 建用户， `redis-cli --user app_read --pass 口令 SET a 1` 被拒、`GET` 放行，并记下两种报错原文 |
