# 02-内存管理与性能调优

> 📍 **前置**：[[01-事务与Lua脚本]] → 本笔记 → [[03-缓存三大问题与分布式锁]]

## 🎯 学习目标

1. 理解 Redis 内存占用结构
2. 掌握过期键的三种删除策略
3. 能配置和选择 maxmemory 淘汰策略
4. 能诊断和优化大 Key、热 Key

---

## 📖 核心内容

### 内存结构

```
内存 = 数据 + 对象系统开销 + 缓冲区 + 持久化缓冲 + 复制缓冲 + 碎片
```

```bash
redis-cli INFO memory
# used_memory: 1.2G         # 实际数据
# used_memory_rss: 1.5G     # OS 分配（含碎片）
# mem_fragmentation_ratio: 1.25  # >1.5 需关注
# maxmemory: 2gb
```

### 过期键删除策略

| 策略 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 定时删除 | 到期立即删除 | 内存释放及时 | CPU 开销大 |
| 惰性删除 | 访问时检查过期 | CPU 友好 | 过期键残留 |
| 定期删除 | 周期性抽样删除 | 折中 | 有漏网之鱼 |

Redis 使用**惰性删除 + 定期删除**的组合策略。

### maxmemory 淘汰策略

```bash
# redis.conf
maxmemory 2gb
maxmemory-policy allkeys-lru
```

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| noeviction | 不淘汰，内存不足时拒绝写入 | 持久化存储 |
| allkeys-lru | 所有 Key 中淘汰最近最少使用 | 通用缓存 |
| allkeys-lfu | 所有 Key 中淘汰使用频率最少 | 热点数据 |
| volatile-lru | 带 TTL 的 Key 中淘汰 LRU | 缓存+持久混合 |
| volatile-lfu | 带 TTL 的 Key 中淘汰 LFU | 短期热点 |
| volatile-ttl | 淘汰 TTL 最短的 Key | 短期数据 |
| allkeys-random | 随机淘汰 | 无热点特征 |
| volatile-random | 带 TTL 的 Key 中随机淘汰 | 无热点特征 |

### 大 Key 治理

```bash
# 查找大 Key
redis-cli --bigkeys

# 分析某个 Key 内存
redis-cli MEMORY USAGE user:1

# 扫描内存大的 Key
redis-cli --memkeys

# 异步删除大 Key（不阻塞）
UNLINK bigkey
```

| 危害 | 表现 | 治理 |
|------|------|------|
| 阻塞 | 操作慢 | 拆分或删除 |
| 内存不均 | Cluster 节点内存倾斜 | 迁移或分片 |
| 删除阻塞 | DEL 大Key 卡顿 | 用 `UNLINK` |

### 热 Key 诊断

```bash
# 开启热点 Key 监控（需 LFU 策略）
redis-cli CONFIG SET maxmemory-policy allkeys-lfu
redis-cli --hotkeys
```

### 性能分析工具

```bash
# 1. INFO：综合状态
redis-cli INFO all
redis-cli INFO cpu        # CPU 使用
redis-cli INFO stats      # 命中/未命中、连接数

# 2. SLOWLOG：慢查询日志
redis-cli CONFIG SET slowlog-log-slower-than 10000  # >10ms 记录
redis-cli CONFIG SET slowlog-max-len 128
redis-cli SLOWLOG GET 10
redis-cli SLOWLOG RESET

# 3. MEMORY ANALYZE
redis-cli --bigkeys
redis-cli --memkeys
```

## 💻 代码示例

```bash
# 查看内存使用
redis-cli INFO memory

# 查看慢查询
redis-cli SLOWLOG GET 10

# 查看大 Key
redis-cli --bigkeys

# 生产推荐配置
redis-cli CONFIG SET maxmemory 2gb
redis-cli CONFIG SET maxmemory-policy allkeys-lru
redis-cli CONFIG SET slowlog-log-slower-than 10000

# 启用活跃碎片整理（Redis 4.0+）
redis-cli CONFIG SET activedefrag yes
```

## ⚠️ 常见陷阱

| 陷阱 | 后果 | 解决方案 |
|------|------|---------|
| maxmemory-policy 默认 noeviction | 写入 OOM | 按业务改为 lru/lfu |
| 大 Key 阻塞 | 慢查询 | 拆分、UNLINK |
| 热 Key 单点压力过大 | 性能瓶颈 | 本地缓存、读写分离 |
| 内存碎片化严重 | RSS 远大于 used_memory | 重启或启用 active defrag |
| 不监控慢查询 | 问题发现晚 | 配置 slowlog-log-slower-than |
