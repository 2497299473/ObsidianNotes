# 99-阶段3复习检查点

> 🎯 阶段验收口径：三行全绿即视为阶段三过关；每行都要有命令输出或时序记录作为证据。

---

## 🎯 本文学完自检

| 层次 | 检查项 |
|------|--------|
| 🟢 基础 | `MULTI` 里放一条必错的 `INCR k`（`k` 是字符串）→ `EXEC` 后该条报错、其余生效（证明无回滚）；`EVAL "return redis.call('SET',KEYS[1],ARGV[1])" 1 k v` 返回 `OK`；`SET lock:o1 t1 NX EX 30` 连发两次：首次 `OK`、再次 `(nil)` |
| 🟡 进阶 | `CONFIG SET maxmemory 50mb` + `allkeys-lru` 灌满后 `INFO stats` 的 `evicted_keys` 从 0 增长；`CONFIG SET slowlog-log-slower-than 0` 后跑 `KEYS *`，`SLOWLOG GET` 能拓到它；穿透/击穿/雪崩 各给一个可观察现象（空值缓存命中时 DB 计数不再增 / 20 并发只 +1 / 同批 key 的 TTL 分散而不集中） |
| 🔴 挑战 | 给定“1000 件库存、1 万并发秒杀”：用 Lua 扣库存 + token 锁 + fencing token 写 6 行方案，说明为何不能只用 `MULTI`、锁过期后旧持有者靠什么兑底，并给出一个能证伪该方案的压测指标（如“成功扣减次数 ≠ 1000 即不通过”） |
