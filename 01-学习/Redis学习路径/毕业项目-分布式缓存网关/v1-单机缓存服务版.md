# v1-单机缓存服务版

> 📍 **前置**：[[../阶段一-数据结构与命令/01-Redis基础与字符串命令]]
> 📍 **路线**：v1（本版本） → [[v2-多数据结构组合版]]

## 🎯 本版本目标

用 Python + redis-py 实现基础缓存 API：GET/SET/DELETE，支持 TTL，实现：**缓存服务跑起来**。

---

## 💻 核心实现

```python
from flask import Flask, request, jsonify
import redis
import json

app = Flask(__name__)
r = redis.Redis(host='localhost', port=6379, decode_responses=True)

@app.route('/cache/<key>', methods=['GET'])
def get(key):
    value = r.get(key)
    return jsonify({"key": key, "value": value, "exists": value is not None})

@app.route('/cache/<key>', methods=['PUT'])
def put(key):
    data = request.get_json()
    value = data.get('value')
    if value is None:
        # 约定：value 缺失/为 null 一律 400，不把字符串 "null" 写进缓存
        return jsonify({"error": "'value' is required"}), 400
    if not isinstance(value, str):
        value = json.dumps(value, ensure_ascii=False)  # 只有非字符串才序列化
    ttl = data.get('ttl', 300)
    r.setex(key, ttl, value)
    return jsonify({"status": "ok", "ttl": ttl})

@app.route('/cache/<key>', methods=['DELETE'])
def delete(key):
    r.delete(key)
    return jsonify({"status": "deleted"})

if __name__ == '__main__':
    # 只监听本机：示例无鉴权，bind 0.0.0.0 等于把无密码缓存暴露到局域网/公网
    # 生产必须前置鉴权（API Key / 网关鉴权），并且只在内网监听
    app.run(host='127.0.0.1', port=5000)
```

```bash
pip install flask redis
python app.py

# 测试
curl -X PUT http://localhost:5000/cache/user:1 \
  -H "Content-Type: application/json" \
  -d '{"value":"alice"}'
curl http://localhost:5000/cache/user:1
curl -X DELETE http://localhost:5000/cache/user:1
```

> ⚠️ 别把 `json.dumps()` 的结果再交给 `jsonify`：`json.dumps("alice")` 得到的是 `"\"alice\""`，前端拿到的是**带引号**的值。本篇约定：非字符串值才序列化，`GET` 原样返回；`value` 缺失直接 400，不写字符串 `"null"`（否则 `exists` 恒为 true）。

## ✅ 验收标准

- [ ] GET/PUT/DELETE API 正常工作
- [ ] TTL 过期后数据不可访问
- [ ] 20 个并发 PUT 全部返回 200（用下条命令实测，而非“看起来无异常”）

```bash
# 并发验收：20 个并发 PUT 同一 key，统计 HTTP 状态码，并核对最终值不带多余引号
seq 20 | xargs -P20 -I{} curl -s -o /dev/null -w "%{http_code}\n" \
  -X PUT http://localhost:5000/cache/conc \
  -H "Content-Type: application/json" -d '{"value":"ok"}' | sort | uniq -c
curl -s http://localhost:5000/cache/conc     # value 应为 ok（而不是 "ok"）
```

## 🎯 本文学完自检

| 层次 | 检查项 |
|------|--------|
| 🟢 基础 | `curl -X PUT localhost:5000/cache/k -H "Content-Type: application/json" -d '{"value":"ok"}'` 后 `GET /cache/k` 返回 `"value": "ok"` 与 `"exists": true`；`DELETE` 后再 `GET` 为 `"exists": false` |
| 🟡 进阶 | `PUT …/cache/t` 带 `"ttl": 2`，`key` 即时存在；等 3 秒再 `GET` 得 `exists: false`；`PUT` 不传 `value` 时返回 400，而不是写入字符串 `null` |
| 🔴 挑战 | 用本文的 `seq 20 \| xargs -P20` 并发 PUT 同一 key：20 个响应全为 `200`，再 `GET` 拿到的值**不带多余引号**（不是 `"ok"`），并说清 `json.dumps` + `jsonify` 为何会造成双重编码 |
