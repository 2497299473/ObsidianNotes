# 02-主从复制与哨兵

> 📍 **前置**：[[01-RDB与AOF持久化]] → 本笔记 → [[03-Cluster分片集群]]

## 🎯 学习目标

1. 理解 Redis 主从复制的工作原理（全量 + 增量）
2. 能搭建主从复制架构并配置读写分离
3. 理解哨兵的故障检测与自动转移
4. 能搭建哨兵集群实现高可用

## 📖 核心内容

### 主从复制架构

```
      ┌─────────────┐
      │   Master    │  读 + 写
      │   6379      │
      └──────┬──────┘
             │
    ┌────────┴────────┐
    │                 │
┌───┴───┐         ┌──────┐
│ Replica│         │ Replica│  只读
│ 6380  │         │ 6381  │
└───────┘         └───────┘
```

### 搭建主从复制

```bash
# 方式一：配置文件
# replica.conf
replicaof 127.0.0.1 6379
masterauth <password>        # 如果 Master 有密码

# 方式二：运行时命令
redis-cli -p 6380 REPLICAOF 127.0.0.1 6379
redis-cli -p 6380 REPLICAOF NO ONE  # 提升为主

# 从节点只读
replica-read-only yes
```

### 复制原理

```
1. Replica 发送 PSYNC 命令
2. Master 判断是否需要全量同步
   ├── 首次/无法增量 → FULLRESYNC → BGSAVE → 发送 RDB → 发送缓冲区命令
   └── 可以增量 → 发送积压缓冲区数据
3. 后续：Master 每条写命令自动异步同步给 Replica
```

```bash
# 查看复制状态
redis-cli -p 6379 INFO replication
# role:master
# connected_slaves:2
# slave0:ip=127.0.0.1,port=6380,state=online,offset=1234
```

### 读写分离

```python
from redis.sentinel import Sentinel

# Master 用于写
master = sentinel.master_for('mymaster', socket_timeout=0.5)
master.set('key', 'value')

# Replica 用于读
replica = sentinel.replica_for('mymaster', socket_timeout=0.5)
replica.get('key')
```

### 哨兵（Sentinel）

哨兵负责监控 Master 健康，Master 宕机时自动选举新 Master。

```
Sentinel1  Sentinel2  Sentinel3   ← 3 个哨兵（奇数）
    │          │          │
    └──────────┴──────────┘
               │
          Master ←→ Replica1, Replica2
```

### 哨兵配置

```bash
# sentinel.conf
port 26379
sentinel monitor mymaster 127.0.0.1 6379 2   # 2 = 多数投票
sentinel down-after-milliseconds mymaster 5000  # 5s无响应判定下线
sentinel parallel-syncs mymaster 1              # 同时同步的 Replica 数
sentinel failover-timeout mymaster 60000        # 故障转移超时
sentinel auth-pass mymaster <password>           # Master 密码
```

### 启动哨兵

```bash
redis-sentinel sentinel.conf
# 或
redis-server sentinel.conf --sentinel
```

### 故障转移流程

```
1. 哨兵每秒 PING Master
2. 5s 无响应 → 标记主观下线（SDOWN）
3. 询问其他哨兵 → 多数同意 → 标记客观下线（ODOWN）
4. 选举 Leader 哨兵
5. Leader 选举新 Master（优先级 → 复制偏移量 → runid）
6. 通知所有 Replica 同步新 Master
7. 通知客户端新 Master 地址
```

### 客户端连接哨兵

```python
from redis.sentinel import Sentinel

sentinel = Sentinel([
    ('127.0.0.1', 26379),
    ('127.0.0.1', 26380),
    ('127.0.0.1', 26381),
], socket_timeout=0.5)

# 获取 Master 连接（自动故障转移后自动切换）
master = sentinel.master_for('mymaster', socket_timeout=0.5)
master.set('key', 'value')

# 获取 Replica 连接
replica = sentinel.replica_for('mymaster', socket_timeout=0.5)
replica.get('key')
```

## 💻 代码示例

```bash
# 启动主节点和从节点
redis-server redis-master.conf
redis-server redis-slave1.conf  # replicaof 127.0.0.1 6379
redis-server redis-slave2.conf  # replicaof 127.0.0.1 6379

# 启动 3 个哨兵
redis-sentinel sentinel1.conf  # port 26379
redis-sentinel sentinel2.conf  # port 26380
redis-sentinel sentinel3.conf  # port 26381

# 查看主从状态
redis-cli -p 6379 INFO replication
redis-cli -p 26379 SENTINEL masters
redis-cli -p 26379 SENTINEL get-master-addr-by-name mymaster

# 模拟 Master 故障
redis-cli -p 6379 SHUTDOWN

# 观察哨兵日志
tail -f /var/log/redis/sentinel.log
# +sdown master mymaster 127.0.0.1 6379
# +odown master mymaster 127.0.0.1 6379 #quorum 2/2
# +switch-master mymaster 127.0.0.1 6379 127.0.0.1 6380

# 验证新 Master
redis-cli -p 26379 SENTINEL get-master-addr-by-name mymaster
```

## ⚠️ 常见陷阱

| 陷阱 | 后果 | 解决方案 |
|------|------|---------|
| 哨兵只有 1 个 | 无法客观下线 | 至少 3 个哨兵（奇数） |
| 复制延迟大 | 读到旧数据 | 监控复制偏移量，必要时强制走主 |
| masterauth 未配 | Replica 无法连接有密码的 Master | 配置 masterauth |
| 网络分区导致脑裂 | 双主写入冲突 | 配置 `min-replicas-to-write` |
| 客户端不连哨兵 | 故障转移后连旧 Master | 用 Sentinel API |
