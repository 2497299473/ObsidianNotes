## 基础原理类（10 题）

### 1. Docker 是什么？和虚拟机有什么区别？

> **结论**：Docker 是基于 Linux 内核特性（Namespace + Cgroups + UnionFS）的容器运行时，本质是隔离的进程，不是虚拟机。

展开：
- 共享内核：容器不需要 Guest OS，直接用宿主内核
- 进程级隔离：Namespace 隔离进程视图，Cgroups 限制资源
- 镜像分层：UnionFS 让镜像可复用、增量构建

对比表：启动速度：容器秒级 vs VM 分钟级；资源开销：容器 MB 级 vs VM GB 级；隔离级别：进程级 vs 硬件级；密度：单机数百容器 vs 10-20 个 VM

**加分点**：提到容器逃逸风险和 Rootless 模式。

---

### 2. 容器是怎么实现隔离的？

> **结论**：通过 Linux 内核的 Namespace 实现隔离，Cgroups 实现资源限制，UnionFS 实现镜像分层。

Namespace 六种：PID（进程 ID）、NET（网络栈）、MNT（文件系统）、UTS（主机名）、IPC（进程间通信）、USER（用户 ID 映射）

Cgroups：cpu、memory、blkio、pids 四个核心子系统

**加分点**：提到 User Namespace 默认未启用是安全隐患。

---

### 3. Docker 镜像为什么是分层的？

> **结论**：分层基于 UnionFS，每条 Dockerfile 指令生成一个只读层，叠加成最终镜像。

好处：
1. 共享基础层：10 个容器用同一 alpine，磁盘只存一份
2. 增量构建：修改只重建变化层，缓存命中
3. 写时复制：容器修改文件时从镜像层复制到容器层

**加分点**：提到 `docker image history` 和 `dive` 工具查看分层。

---

### 4. docker run 的完整流程是什么？

```
① docker CLI → 发送命令到 dockerd
② dockerd → 检查本地镜像，不存在则 pull
③ dockerd → containerd → containerd-shim → runc
④ runc → 调用 clone() + unshare() 创建 Namespace
⑤ runc → 设置 Cgroups 限制资源
⑥ runc → mount rootfs（UnionFS 叠加）
⑦ 启动容器进程（PID 1）
```

**加分点**：提到 dockershim 移除后 K8S 用 containerd 直接对接。

---

### 5. CMD 和 ENTRYPOINT 的区别？

> **结论**：ENTRYPOINT 是固定入口，CMD 是默认参数。两者配合使用最灵活。

三种组合：
- 只有 CMD → docker run 参数会覆盖 CMD
- ENTRYPOINT + CMD → CMD 作为 ENTRYPOINT 的参数
- 只有 ENTRYPOINT → docker run 参数追加到 ENTRYPOINT

exec 格式 vs shell 格式：exec 让 PID 1 是应用本身，能接收 SIGTERM；shell 让 PID 1 是 /bin/sh，不转发信号。

**加分点**：生产环境必须用 exec 格式，否则 `docker stop` 无法优雅终止。

---

### 6. 容器为什么启动后立即退出？

> **结论**：容器生命周期绑定在 PID 1 进程上。PID 1 退出，容器就退出。

常见原因：CMD 是一次性命令（如 echo hello）、前台进程没起来（如 nginx 以后台 daemon 模式运行）、应用启动失败崩溃。

排查方法：`docker logs <container>`、`docker inspect` 查看 ExitCode。

**加分点**：提到 `docker run -it` 和 `docker run -d` 的区别。

---

### 7. COPY 和 ADD 的区别？

> **结论**：COPY 只复制文件，ADD 额外支持 URL 下载和解压 tar。推荐用 COPY。

COPY：明确、行为可预期。ADD：额外功能但容易出意外（ADD url dest → 下载文件；ADD archive.tar dest → 自动解压）。

**最佳实践**：始终用 COPY，需要解压时手动 `tar -xf`。

---

### 8. 容器内 root 和宿主机 root 是同一个吗？

> **结论**：默认情况下是同一个（UID 0），除非启用 User Namespace。

风险：容器逃逸 → 宿主机 root 权限；容器内可以 mount 宿主机文件系统。

防护措施：USER 指令切换非 root、`--cap-drop ALL`、Rootless 模式、启用 User Namespace（userns-remap）。

**加分点**：提到 Rootless Docker 和 User Namespace 映射。

---

### 9. docker stop 和 docker kill 的区别？

> **结论**：stop 发 SIGTERM 优雅终止，kill 发 SIGKILL 立即杀死。

- stop：发 SIGTERM → 应用清理资源 → 退出，10 秒后超时发 SIGKILL
- kill：直接 SIGKILL，不给应用清理机会，可能丢数据（如数据库未 flush）

**加分点**：提到 PID 1 必须是应用本身才能接收 SIGTERM（exec 格式 CMD）。

---

### 10. Docker 网络有哪几种模式？

> **结论**：五种模式——bridge（默认）、host、none、container、overlay。

- bridge：docker0 网桥，容器间通信
- host：共享宿主网络栈，无隔离
- none：无网络
- container：共享另一容器网络（sidecar）
- overlay：跨主机（Swarm/K8s）

默认 vs 自定义 bridge：默认不支持容器名 DNS，自定义支持容器名互访。

**加分点**：提到 Overlay 用 VXLAN 封装实现跨主机通信。

## Dockerfile 优化类（5 题）

### 11. 如何把镜像从 1GB 减到 50MB？

> **结论**：多阶段构建 + alpine 基础镜像 + .dockerignore + 合并 RUN。

步骤：
1. 选 slim/alpine 基础镜像（1GB → 100MB）
2. 多阶段构建（100MB → 30MB）
3. .dockerignore 排除无关文件
4. 合并 RUN 指令减少层数
5. `--no-install-recommends` 不装推荐包
6. 清理缓存（`rm -rf /var/lib/apt/lists/*`）

**加分点**：提到 dive 工具分析分层，distroless 更安全。

---

### 12. 多阶段构建的原理是什么？

> **结论**：多个 FROM 阶段，最后阶段只 COPY 需要的产物，编译工具和源码不进最终镜像。

```dockerfile
FROM golang:1.22 AS builder  # ~300MB
RUN go build -o server .

FROM alpine:3.20             # ~7MB
COPY --from=builder /app/server /usr/local/bin/
# 最终镜像 ~15MB
```

**加分点**：提到 `--from=builder` 可以引用任意阶段名，可以有多个构建阶段。

---

### 13. 构建缓存为什么失效？如何优化？

> **结论**：某层变化后，该层及后续所有层缓存失效。把最常变的放最后。

缓存失效场景：
1. `COPY . .` → 任何文件变化都失效
2. `apt-get update` 和 install 分开 → update 缓存过期

优化原则：
1. FROM → 系统依赖 → 语言依赖 → 代码
2. 先 COPY requirements.txt 再 COPY . .
3. 用 BuildKit `--mount=type=cache` 跨构建复用缓存

**加分点**：提到 BuildKit 缓存挂载跨构建复用 pip/npm 缓存。

---

### 14. .dockerignore 有什么用？

> **结论**：排除不需要的文件进入构建上下文，减小传输量和镜像大小。

三大作用：
1. 减小上下文：不传 node_modules（几百 MB）
2. 防止缓存失效：不传 .git（每次 commit 变）
3. 防止泄露：不传 .env 中的密钥

---

### 15. 如何在构建时安全使用密钥？

> **结论**：用 BuildKit 的 `--mount=type=secret`，密钥只在构建时存在，不进镜像层。

```dockerfile
# ❌ ARG 留在镜像层
ARG NPM_TOKEN
RUN npm install

# ✅ BuildKit Secret
RUN --mount=type=secret,id=npm_token,target=/root/.npmrc \
    npm install
```

```bash
docker buildx build --secret id=npm_token,src=$HOME/.npmrc -t myapp .
```

## 网络存储与编排安全类（5 题）

### 16. Volume 和 Bind Mount 的区别？

> **结论**：Volume 由 Docker 管理生命周期，Bind Mount 直接挂载宿主目录。

- Volume：Docker 管理，存在 `/var/lib/docker/volumes/`，独立于容器生命周期，适合生产数据（数据库）
- Bind Mount：用户管理，直接挂宿主路径，依赖宿主路径，适合开发环境挂载源码

**加分点**：提到 Volume 备份用 `docker run --rm -v vol:/data alpine tar cvf`。

---

### 17. Docker Compose 的 depends_on 能保证服务就绪吗？

> **结论**：默认不能。depends_on 只等容器启动，不等服务可用。要配 healthcheck + condition。

```yaml
depends_on:
  db:
    condition: service_healthy  # 等健康检查通过
```

---

### 18. Swarm 和 Kubernetes 怎么选？

> **结论**：节点 < 20 选 Swarm，节点 > 50 选 K8S。中间看团队 SRE 能力。

- Swarm 优势：简单、Docker 原生、学习曲线低
- K8S 优势：生态丰富、自动扩缩、云原生标准

**加分点**：提到 Swarm 的 Raft 共识需要奇数 Manager。如果最终要上 K8S，直接学 K8S，别在 Swarm 上浪费时间转型。

---

### 19. 容器安全有哪些最佳实践？

> **结论**：最小权限 + 最小攻击面 + 纵深防御。

10 条清单：
1. 非 root 用户（USER 指令）
2. 镜像扫描（Trivy/Snyk）
3. 资源限制（--memory/--cpus）
4. 只读文件系统（--read-only）
5. 禁止 --privileged
6. --cap-drop ALL + 按需 add
7. --security-opt no-new-privileges
8. Rootless 模式
9. 不在 Dockerfile 写密钥
10. 定期更新基础镜像

**加分点**：提到 cosign 镜像签名和 OPA/Kyverno 准入控制。

---

### 20. 设计一个生产级 Docker 部署方案

> **结论**：从镜像、构建、运行、编排、网络、存储、监控七方面设计。

1. 镜像：多阶段构建、alpine/distroless、Trivy 扫描
2. 构建：CI/CD 流水线、版本化 tag（commit SHA）
3. 运行：资源限制、非 root、read-only、健康检查
4. 编排：Compose（开发）/ Swarm 或 K8S（生产）
5. 网络：自定义 bridge/overlay
6. 存储：Volume 持久化 + 定期备份
7. 监控：日志收集 + 资源监控 + 告警

**加分点**：提到从 Docker 迁移到 K8S 的经验、蓝绿/金丝雀发布策略。
