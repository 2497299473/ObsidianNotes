## 1. 开发环境搭建

### 1.1 安装 Node.js 与 TypeScript

```bash
# 检查 Node.js 版本（需 ≥ 18）
node --version
npm --version

# 全局安装 TypeScript 编译器
npm install -g typescript
tsc --version  # 应显示 5.5+
```

### 1.2 初始化项目

```bash
mkdir ts-learn && cd ts-learn
npm init -y
npm install -D typescript ts-node
npx tsc --init
```

### 1.3 tsconfig.json 最小配置

```jsonc
{
  "compilerOptions": {
    "target": "ES2020",         // 编译目标 JS 版本
    "module": "commonjs",       // 模块系统
    "strict": true,             // 开启所有严格检查（推荐！）
    "esModuleInterop": true,    // 兼容 CommonJS 默认导入
    "outDir": "./dist",         // 编译输出目录
    "rootDir": "./src",         // 源码根目录
    "skipLibCheck": true,       // 跳过 .d.ts 检查加速编译
    "forceConsistentCasingInFileNames": true
  },
  "include": ["src/**/*"]
}
```

> **为什么 `strict: true` 从第一天开始？**
> strict 模式会开启 7 项检查（noImplicitAny、strictNullChecks 等），越早适应，后期越省事。不要用 `any` 绕过类型错误。

### 1.4 第一个 TypeScript 程序

```typescript
// src/hello.ts
function greet(name: string): string {
  return `Hello, ${name}!`;
}

console.log(greet("TypeScript"));
```

```bash
# 方式一：编译为 JS 再运行
npx tsc
node dist/hello.js

# 方式二：用 ts-node 直接运行（免编译）
npx ts-node src/hello.ts
```

## 2. 基本类型（Primitive Types）

### 2.1 七种原始类型

```typescript
// 1. string
const name: string = "Alice";
const template: string = `Hello, ${name}`;

// 2. number（整数和浮点数统一为 number）
const age: number = 25;
const pi: number = 3.14;

// 3. boolean
const isActive: boolean = true;

// 4. null
const empty: null = null;

// 5. undefined
const notSet: undefined = undefined;

// 6. symbol
const id: symbol = Symbol("id");

// 7. bigint
const big: bigint = 9007199254740991n;
```

### 2.2 数组与元组

```typescript
// 数组 —— 两种等价写法
const nums: number[] = [1, 2, 3];
const strs: Array<string> = ["a", "b"];

// 元组 —— 固定长度和类型的数组
const pair: [string, number] = ["age", 25];
const [label, value] = pair; // 解构
```

### 2.3 枚举（Enum）

```typescript
// 数字枚举
enum Direction { Up, Down, Left, Right }
let d: Direction = Direction.Up; // 0

// 字符串枚举（推荐，可读性更好）
enum HttpStatus {
  OK = "200",
  NotFound = "404",
}

// const 枚举 —— 编译时内联，无运行时开销
const enum Status {
  Active = "ACTIVE",
  Inactive = "INACTIVE",
}
```

### 2.4 字面量类型

```typescript
const exact: "hello" = "hello";
// const wrong: "hello" = "world"; // ❌ 报错

// 配合联合类型
type Method = "GET" | "POST" | "PUT" | "DELETE";
```

## 3. 特殊类型：any / unknown / never / void

| 类型 | 含义 | 安全性 | 使用场景 |
|------|------|--------|---------|
| `any` | 关闭类型检查 | ❌ 不安全 | 尽量避免，迁移遗留代码时过渡 |
| `unknown` | 安全的 any，必须先收窄 | ✅ 安全 | 处理不确定类型的数据 |
| `never` | 永不存在的值 | ✅ 安全 | 永不返回的函数、穷尽性检查 |
| `void` | 无返回值 | ✅ 安全 | 不返回值的函数 |

```typescript
// any — 危险
let a: any = "hello";
a.foo(); // 编译通过，运行报错

// unknown — 安全
let u: unknown = "hello";
// u.toUpperCase(); // ❌ 不允许直接调用
if (typeof u === "string") {
  u.toUpperCase(); // ✅ 收窄后可用
}

// never
function throwError(msg: string): never {
  throw new Error(msg);
}
function infiniteLoop(): never {
  while (true) {}
}

// void
function log(msg: string): void {
  console.log(msg);
}
```

## 4. 类型断言与类型推断

### 4.1 类型断言

```typescript
// as 语法（推荐）
const el = document.getElementById("app") as HTMLDivElement;

// const 断言 —— 推断为最精确的字面量类型 + readonly
const point = [1, 2] as const; // readonly [1, 2]
```

> **注意**：断言不会在运行时做检查，仅影响编译时。滥用断言会破坏类型安全。
>
> 📖 类型断言的深入用法（`satisfies`、类型守卫配合断言、`as const` 进阶）详见 [[../阶段二-进阶类型与类型体操/04-类型保护与类型断言]]。

### 4.2 let vs const 的类型推断

```typescript
let x = 10;      // 推断为 number（可变）
const y = 10;     // 推断为 10（字面量类型，不可变）

let s = "hello";  // 推断为 string
const s2 = "hello"; // 推断为 "hello"（字面量类型）
```

### 4.3 最佳实践

```typescript
// 能推断就别注解 —— 冗余
let items = [1, 2, 3]; // ✅ 推断为 number[]
// let items: number[] = [1, 2, 3]; // 冗余

// 但函数参数和返回值必须显式标注
function add(a: number, b: number): number {
  return a + b;
}
```

## 5. 练习

### 练习 1：环境验证

1. 按上文步骤安装 TypeScript 并初始化项目
2. 编写 `src/hello.ts`，导出一个 `greet(name: string): string` 函数
3. 用 `tsc` 编译并运行

**验收标准**：
- `npx tsc --noEmit` 零错误
- `node dist/hello.js` 输出 `Hello, TypeScript!`
- `greet(123)` 在编译时报错

为以下代码补全类型标注（不使用 `any`）：

```typescript
function processData(data, flag, callback) {
  if (flag) {
    return callback(data);
  }
  return data;
}
```

**验收标准**（练习 2）：
- `tsc --strict` 零错误，参数和返回值全部标注
- **参考答案**：`function processData<T>(data: T, flag: boolean, callback: (d: T) => T): T`

### 练习 3：枚举与联合对比

分别用 `enum` 和联合类型定义一周七天，比较两者的优缺点。

**验收标准**：
- 两种写法都通过 `tsc --noEmit`
- 能列出至少 2 个区别（tree-shaking、运行时开销等）
