## 1. Interface（接口）

### 1.1 描述对象形状

```typescript
interface User {
  name: string;
  age: number;
  email?: string;       // 可选属性
  readonly id: number;  // 只读属性
}

const user: User = {
  id: 1,
  name: "Alice",
  age: 30,
};
// user.id = 2; // ❌ 只读属性不可修改
```

### 1.2 方法签名

```typescript
interface Calculator {
  add(a: number, b: number): number;
  subtract(a: number, b: number): number;
}

const calc: Calculator = {
  add: (a, b) => a + b,
  subtract: (a, b) => a - b,
};
```

### 1.3 描述函数类型

```typescript
interface Comparator<T> {
  (a: T, b: T): number;
}

const compare: Comparator<number> = (a, b) => a - b;
```

### 1.4 接口继承（extends）

```typescript
interface Animal {
  name: string;
}

interface Dog extends Animal {
  breed: string;
  bark(): void;
}

const myDog: Dog = {
  name: "Buddy",
  breed: "Golden Retriever",
  bark: () => console.log("Woof!"),
};
```

### 1.5 声明合并（Declaration Merging）

```typescript
// 同名 interface 会自动合并
interface Window {
  customProp: string;
}
interface Window {
  anotherProp: number;
}
// 最终 Window 同时拥有 customProp 和 anotherProp
```

> 这是 interface 独有的能力，`type` 不支持。

## 2. Type Alias（类型别名）

### 2.1 基本用法

```typescript
type ID = string | number;
type Callback = (error: Error | null, data?: string) => void;
type Point = { x: number; y: number };
```

### 2.2 type 能做但 interface 不能做的事

```typescript
// 1. 联合类型
type Status = "active" | "inactive";

// 2. 交叉类型
type Timestamped<T> = T & { createdAt: Date };

// 3. 映射类型（预告，详见阶段二）
type ReadonlyUser = {
  readonly [K in keyof User]: User[K];
};

// 4. 模板字面量类型
type EventName = `on${Capitalize<string>}`;
```

### 2.3 类型别名不支持声明合并

```typescript
// ❌ 同名 type 会报错
// type User = { name: string };
// type User = { age: number }; // Duplicate identifier
```

## 3. Interface vs Type Alias 对比

| 特性 | Interface | Type Alias |
|------|----------|------------|
| 描述对象形状 | ✅ | ✅ |
| 描述函数类型 | ✅ | ✅ |
| 联合/交叉类型 | ❌ | ✅ |
| 元组类型 | ❌ | ✅ |
| 映射/条件类型 | ❌ | ✅ |
| 声明合并 | ✅ | ❌ |
| 扩展（extends） | ✅ 原生支持 | ✅ 用交叉 `&` |
| 性能 | 略优（缓存友好） | 略差 |

**选择原则**：
- 描述对象/类的形状 → 优先 `interface`
- 需要联合、交叉、元组、映射、条件类型 → 用 `type`
- 需要声明合并（扩展第三方库类型） → 用 `interface`

## 4. 索引签名（Index Signatures）

### 4.1 字符串索引

```typescript
interface StringMap {
  [key: string]: string;
}

const dict: StringMap = { name: "Alice", city: "Shanghai" };
```

### 4.2 数字索引

```typescript
interface NumberMap {
  [index: number]: string;
}

const arr: NumberMap = ["a", "b", "c"];
```

### 4.3 混合索引

```typescript
interface MixedMap {
  [key: string]: string | number;
  name: string;   // 已知属性必须兼容索引签名的类型
  age: number;
}
```

> 注意：数字索引签名的返回值必须兼容字符串索引签名的返回值。

### 4.4 模板字面量索引签名（TS 4.4+）

```typescript
interface Options {
  [key: `option_${string}`]: boolean;
}

const opts: Options = {
  option_dark: true,
  option_auto: false,
  // name: "hello" // ❌ 键必须匹配模板
};
```

## 5. 结构类型系统

TypeScript 是**结构类型系统**（鸭子类型），只看形状不看名义：

```typescript
interface Point { x: number; y: number; }
interface Coord { x: number; y: number; }

const p: Point = { x: 1, y: 2 };
const c: Coord = p; // ✅ 结构相同，即使名字不同
```

### 多余属性检查（Excess Property Check）

```typescript
interface User { name: string; age: number; }

// 直接字面量赋值 → 多余属性会报错
// const u: User = { name: "Alice", age: 30, extra: true }; // ❌

// 但通过变量中转就不会报错
const obj = { name: "Alice", age: 30, extra: true };
const u: User = obj; // ✅
```

> **为什么变量中转会绕过检查？** 因为 TS 对字面量直接赋值时做多余属性检查，但变量已经有一个确定的类型，赋值时走的是结构兼容性判断。

## 6. 练习

### 练习 1：为 API 响应建模

为一个 REST API 设计类型：

```typescript
// GET /api/users → { users: User[]; total: number; page: number }
// GET /api/users/:id → User
// POST /api/users → { id: number } （创建成功）
// 要求：用 interface 分层定义 User、UserListResponse、UserResponse、CreateResponse
// data 的类型支持泛型
```

### 练习 2：索引签名实战

设计一个 `Config` 类型，支持任意字符串键，但 `timeout` 必须是 number，`retries` 必须是 number，其他键值为 string。

### 练习 3：interface 还是 type

判断以下场景应该用 `interface` 还是 `type`，并说明理由：

1. 定义一个 HTTP 方法的字面量类型 `"GET" | "POST" | "PUT" | "DELETE"`
2. 定义一个用户信息对象
3. 定义一个 `[string, number]` 元组
4. 需要声明合并的全局配置
