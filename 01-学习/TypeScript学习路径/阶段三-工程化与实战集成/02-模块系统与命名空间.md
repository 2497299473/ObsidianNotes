## 1. ES Modules vs CommonJS

### 1.1 ESM 语法（推荐）

```typescript
// math.ts
export function add(a: number, b: number): number {
  return a + b;
}

export const PI = 3.14159;

// 默认导出
export default function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}

// app.ts
import sum, { add, PI } from "./math";
import * as math from "./math";
```

### 1.2 CommonJS 语法

```typescript
// math.ts
export = function add(a: number, b: number): number {
  return a + b;
};

// app.ts
import add = require("./math");
// 或者启用 esModuleInterop 后用 default import
```

### 1.3 对比

| 特性 | ES Modules | CommonJS |
|------|-----------|----------|
| 语法 | import/export | require/module.exports |
| 加载时机 | 编译时静态分析 | 运行时动态加载 |
| Tree-shaking | ✅ 支持 | ❌ 不支持 |
| 浏览器原生 | ✅ ESM 标准 | ❌ Node.js 独有 |
| Top-level await | ✅ | ❌ |

> **现代项目统一使用 ES Modules**。CommonJS 仅用于兼容旧项目。

## 2. 类型导入与导出

### 2.1 import type（TS 3.8+）

```typescript
// 只导入类型，编译后完全擦除
import type { User } from "./types";

// 混合导入（TS 4.5+）
import { type User, createUser } from "./user";
```

### 2.2 verbatimModuleSyntax（TS 5.0+）

```jsonc
// tsconfig.json
{ "compilerOptions": { "verbatimModuleSyntax": true } }
```

```typescript
// 开启后，类型导入必须显式标记
import { type User, type Config, createApp } from "./lib";
// ✅ createApp 会在输出中保留
// ✅ User/Config 会在输出中擦除
```

### 2.3 重导出类型

```typescript
export type { User } from "./user-types";
export * from "./utils";
export type * from "./types"; // 只导出类型
```

## 3. moduleResolution 策略

| 策略 | 适用场景 | 行为 |
|------|---------|------|
| `node` | module: "commonjs" | 查找 node_modules，支持目录 index |
| `node16` / `nodenext` | 现代 Node.js | 支持 ESM + CJS 混合，package.json exports |
| `bundler` | Webpack/Vite/Rollup | 类似 node，支持路径别名和扩展名省略 |
| `classic` | 历史遗留 | 不推荐 |

### Node16/Nodenext 模式注意

```typescript
// Node16 模式下，相对导入必须写完整扩展名
import { add } from "./math.js"; // ✅ 必须写 .js（不是 .ts）
// import { add } from "./math"; // ❌ 会报错
```

> **为什么是 .js 而不是 .ts？** 因为 TS 编译后输出的是 .js 文件，Node.js 运行时按 .js 路径查找。

## 4. 命名空间（Namespace）

> **注意**：Namespace 是 TypeScript 早期的模块化方案，现代项目几乎不用。但阅读老旧代码、声明文件时仍会见到。

### 4.1 基本用法

```typescript
namespace Geometry {
  export interface Point {
    x: number;
    y: number;
  }

  export function distance(a: Point, b: Point): number {
    return Math.sqrt((a.x - b.x) ** 2 + (a.y - b.y) ** 2);
  }
}

const p1: Geometry.Point = { x: 0, y: 0 };
const p2: Geometry.Point = { x: 3, y: 4 };
console.log(Geometry.distance(p1, p2)); // 5
```

### 4.2 Namespace vs Module

| 特性 | Namespace | Module |
|------|-----------|--------|
| 文件组织 | 可以跨文件 | 一个文件一个模块 |
| 运行时行为 | 打包到全局作用域 | 独立作用域，需导入导出 |
| 现代推荐 | ❌ 不推荐 | ✅ 推荐 |
| Tree-shaking | ❌ 不支持 | ✅ 支持 |
| 使用场景 | 声明文件、老旧代码 | 所有新项目 |

> **现代项目用 ES Modules 替代 namespace**。namespace 主要用于声明文件（`.d.ts`）中为全局对象增加类型。

## 5. 路径别名与运行时处理

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"],
      "@components/*": ["./src/components/*"],
      "@utils/*": ["./src/utils/*"]
    }
  }
}
```

> ⚠️ **关键陷阱**：`tsc` 只做类型检查，**不会在编译输出中转换路径别名**。配置 `paths` 后 `tsc --noEmit` 能通过类型检查，但直接运行 `node dist/index.js` 会报 `Cannot find module '@...'`。三种解决方案：
> • 打包工具（Webpack/Vite/esbuild）处理路径别名
> • 或 `tsc-alias` 工具自动替换路径
> • 或运行时注册（`tsconfig-paths`）

```bash
npm install --save-dev tsc-alias
npx tsc && npx tsc-alias -p tsconfig.json
```

## 6. package.json 中的模块配置

```jsonc
{
  "name": "my-lib",
  "type": "module", // 默认 .js 为 ESM
  "main": "./dist/index.cjs",     // CommonJS 入口
  "module": "./dist/index.mjs",   // ESM 入口
  "types": "./dist/index.d.ts",   // 类型声明入口
  "exports": {
    ".": {
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs",
      "types": "./dist/index.d.ts"
    },
    "./utils": {
      "import": "./dist/utils.mjs",
      "require": "./dist/utils.cjs",
      "types": "./dist/utils.d.ts"
    }
  }
}
```

## 7. 动态导入与循环依赖

### 7.1 动态导入

```typescript
async function loadPlugin(name: string) {
  const mod = await import(`./plugins/${name}`);
  return mod.default;
}
```

### 7.2 循环依赖问题

```typescript
// a.ts
import { b } from "./b";
export const a = "a" + b; // b 此时可能未初始化

// b.ts
import { a } from "./a";
export const b = "b" + a;
```

**解决方案**：提取公共类型到 `types.ts`，用接口而非具体实现，或依赖注入。
