## 一、单例模式（Singleton）⭐⭐⭐

**意图**：确保一个类只有一个实例，提供全局访问点。

**PyQt5 实战**：应用单实例检测。

```python
# 方案一：__new__ 控制（最基础）
class Singleton:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance


# 方案二：QSharedMemory（PyQt5 生产级写法）
from PyQt5.QtCore import QSharedMemory

class SingleInstanceGuard:
    def __init__(self, app_id: str):
        self._memory = QSharedMemory(app_id)

    def is_running(self) -> bool:
        """检测是否有实例已在运行"""
        if self._memory.attach():
            self._memory.detach()
            return True
        return not self._memory.create(1)

# 使用
app = QApplication([])
guard = SingleInstanceGuard("com.myapp.single")
if guard.is_running():
    sys.exit(0)  # 已有实例在跑，退出
```

**Python 中的其他例子**：
- `logging.getLogger()` —— 同名 logger 只创建一次
- Django 的 settings —— 全局唯一配置对象
- 模块本身 —— Python 模块天然单例（import 只执行一次）

## 二、观察者模式（Observer）⭐⭐⭐

**意图**：定义对象间一对多依赖——一个对象状态改变时，所有依赖者自动收到通知。

**PyQt5 实战**：信号槽就是观察者模式的实现！

```python
# PyQt5 信号槽 = 观察者模式
btn.clicked.connect(self.on_clicked)    # 观察者订阅
# 用户点击 → 所有连接的槽都收到通知

# 手动实现（理解原理用）
class Subject:
    def __init__(self):
        self._observers = []

    def attach(self, observer):
        self._observers.append(observer)

    def detach(self, observer):
        self._observers.remove(observer)

    def notify(self, value):
        for obs in self._observers:
            obs.update(value)


class LogObserver:
    def update(self, value):
        print(f"[LOG] Value changed: {value}")


class UIObserver:
    def update(self, value):
        print(f"[UI] Updating display with: {value}")

# 使用
subject = Subject()
subject.attach(LogObserver())
subject.attach(UIObserver())
subject.notify(42)  # 两个观察者都收到通知
```

> 面试话术：PyQt 的信号槽机制本质就是观察者模式——信号是 Subject，槽是 Observer，`connect()` 是 `attach()`。Qt 在其基础上加了类型安全和跨线程支持。

## 三、策略模式（Strategy）⭐⭐

**意图**：定义一族算法，分别封装，使它们可以互相替换。算法变化独立于使用算法的客户端。

**Python 实战**：

```python
# 场景：不同折扣策略
from abc import ABC, abstractmethod

class DiscountStrategy(ABC):
    @abstractmethod
    def apply(self, price: float) -> float:
        ...

class NoDiscount(DiscountStrategy):
    def apply(self, price): return price

class PercentOff(DiscountStrategy):
    def __init__(self, pct): self.pct = pct
    def apply(self, price): return price * (1 - self.pct)


class BuyOneGetOne(DiscountStrategy):
    def apply(self, price): return price * 0.5


class Checkout:
    def __init__(self, strategy: DiscountStrategy):
        self._strategy = strategy

    def set_strategy(self, strategy: DiscountStrategy):
        self._strategy = strategy  # 运行时切换策略

    def total(self, items):
        subtotal = sum(item.price for item in items)
        return self._strategy.apply(subtotal)


# Python 更简洁的写法：函数即策略
def no_discount(price): return price
def half_off(price): return price * 0.5

def checkout(items, discount_fn=no_discount):
    return discount_fn(sum(item.price for item in items))
```

**Python 内置例子**：
- `sorted(data, key=fn)` —— `key` 参数就是策略
- `list.sort(key=fn)` —— 同上
- Django 的认证后端（`AUTHENTICATION_BACKENDS`）

## 四、工厂模式（Factory）⭐⭐

**意图**：不直接 `new`，而是通过工厂方法创建对象——客户端不需要知道具体类名。

```python
# 简单工厂
class ModelFactory:
    @staticmethod
    def create(model_type: str):
        if model_type == "resnet":
            return ResNetModel()
        elif model_type == "yolo":
            return YOLOModel()
        elif model_type == "unet":
            return UNetModel()
        raise ValueError(f"Unknown model: {model_type}")

# 工厂方法模式（子类决定创建什么）
from abc import ABC, abstractmethod

class Exporter(ABC):
    @abstractmethod
    def export(self, data): ...

class PDFExporter(Exporter):
    def export(self, data): return f"PDF: {data}"

class CSVExporter(Exporter):
    def export(self, data): return f"CSV: {data}"

class Report:
    def __init__(self, exporter: Exporter):
        self._exporter = exporter
    def generate(self, data):
        return self._exporter.export(data)

# 使用
Report(PDFExporter()).generate(data)  # 换 Exporter 就换行为
```

**Python 里的实际例子**：
- `pathlib.Path("foo")` → 自动返回 `PosixPath` 或 `WindowsPath`
- `open("file.txt")` → 根据 mode 返回不同的文件对象
- Django ORM 的 `objects.create()` —— 工厂方法创建 model 实例

## 五、命令模式（Command）⭐⭐

**意图**：将请求封装为对象，支持参数化、排队、日志、撤销。

**PyQt5 实战**：QAction + 撤销/重做。

```python
# PyQt5 的 QAction 就是命令模式
undo_action = QAction("撤销", self)
undo_action.triggered.connect(self.undo)     # 命令对象 + 接收者

# 手动实现：支持撤销
from abc import ABC, abstractmethod

class Command(ABC):
    @abstractmethod
    def execute(self): ...
    @abstractmethod
    def undo(self): ...


class InsertText(Command):
    def __init__(self, editor, text, position):
        self.editor = editor
        self.text = text
        self.pos = position

    def execute(self):
        self.editor.insert(self.pos, self.text)

    def undo(self):
        self.editor.delete(self.pos, len(self.text))


class CommandHistory:
    def __init__(self):
        self._history = []
        self._index = -1

    def execute(self, cmd):
        cmd.execute()
        self._history = self._history[:self._index + 1]
        self._history.append(cmd)
        self._index += 1

    def undo(self):
        if self._index >= 0:
            self._history[self._index].undo()
            self._index -= 1

    def redo(self):
        if self._index + 1 < len(self._history):
            self._index += 1
            self._history[self._index].execute()
```

> 面试话术：在桌面应用中，撤销/重做是命令模式的经典应用。每个操作被封装成 Command 对象并放入历史栈，撤销时 pop 出来调用 `undo()`。

## 六、适配器模式（Adapter）⭐

**意图**：将一个接口转换成客户端期望的另一个接口——让不兼容的类能一起工作。

**实际场景**：对接第三方 SDK。

```python
# 场景：你的代码用的是自己的接口，但第三方相机 SDK 是另一套 API

# 你的统一接口
class Camera(ABC):
    @abstractmethod
    def capture(self) -> np.ndarray: ...
    @abstractmethod
    def configure(self, settings: dict): ...

# 某品牌相机的 SDK（你改不了）
class BrandACameraSDK:
    def grab_image(self): ...
    def set_property(self, key, value): ...

# 适配器：把 BrandA 的接口转成你的 Camera 接口
class BrandACameraAdapter(Camera):
    def __init__(self, sdk: BrandACameraSDK):
        self._sdk = sdk

    def capture(self) -> np.ndarray:
        return self._sdk.grab_image()           # 适配

    def configure(self, settings: dict):
        for k, v in settings.items():
            self._sdk.set_property(k, v)        # 适配

# 客户端代码不需要知道底层是哪个品牌
def process(camera: Camera):
    img = camera.capture()
    # ...

process(BrandACameraAdapter(BrandACameraSDK()))
```

> 面试话术：视觉检测软件需要对接不同品牌的相机（Basler、海康、大华），每个 SDK 接口不同。我会定义一个统一的 `Camera` 接口，给每种相机写一个 Adapter——上层业务代码只依赖 `Camera` 接口，换相机只换 Adapter。

## 七、模板方法模式（Template Method）⭐

**意图**：父类定义算法骨架（模板），子类实现具体步骤。

```python
# unittest.TestCase 就是模板方法模式！
import unittest

class MyTest(unittest.TestCase):
    def setUp(self):           # 钩子——子类实现
        self.db = connect_test_db()

    def test_query(self):      # 具体测试
        result = self.db.query("...")
        self.assertEqual(result, expected)

    def tearDown(self):        # 钩子——子类实现
        self.db.close()

# 模板方法：run() 的骨架
# setUp() → test_*() → tearDown()   ← 父类定义顺序，子类填内容


# 另一个例子：数据导入流程
class DataImporter(ABC):
    def import_data(self, filepath):
        """模板方法——定义了导入的步骤"""
        raw = self._read_file(filepath)      # ① 读文件
        parsed = self._parse(raw)            # ② 解析
        validated = self._validate(parsed)   # ③ 校验
        self._save(validated)                # ④ 存储
        self._notify(filepath, len(validated))  # ⑤ 通知

    @abstractmethod
    def _parse(self, raw): ...     # 子类实现具体解析逻辑

    @abstractmethod
    def _save(self, data): ...     # 子类实现存储方式

class CSVImporter(DataImporter):
    def _parse(self, raw): return raw.splitlines()
    def _save(self, data): save_to_db(data)

class ExcelImporter(DataImporter):
    def _parse(self, raw): return parse_excel(raw)
    def _save(self, data): save_to_s3(data)
```

## 八、状态模式（State）⭐

**意图**：对象根据内部状态改变行为——看起来像换了类。

**PyQt5 实战**：按钮的 enabled/disabled 切换。

```python
# 场景：仿真工具的状态机
from abc import ABC, abstractmethod

class SimState(ABC):
    @abstractmethod
    def start(self, context): ...
    @abstractmethod
    def cancel(self, context): ...

class IdleState(SimState):
    def start(self, ctx):
        print("开始仿真")
        ctx.set_state(RunningState())
    def cancel(self, ctx):
        print("当前未运行，无需取消")

class RunningState(SimState):
    def start(self, ctx):
        print("仿真已在运行中")
    def cancel(self, ctx):
        print("取消仿真")
        ctx.set_state(IdleState())

class ErrorState(SimState):
    def start(self, ctx):
        print("上次出错，清除错误后重新开始")
        ctx.clear_error()
        ctx.set_state(RunningState())
    def cancel(self, ctx):
        ctx.set_state(IdleState())


class SimulationContext:
    def __init__(self):
        self._state = IdleState()

    def set_state(self, state: SimState):
        self._state = state

    def start(self):
        self._state.start(self)     # 委托给当前状态

    def cancel(self):
        self._state.cancel(self)    # 委托给当前状态
```

> 面试话术：在仿真工具里，应用有明显状态——空闲、运行中、已取消、错误。用状态模式把每种状态的行为封装成独立类，避免在 MainWindow 里写大量的 `if status == "running": ... elif status == "idle": ...` 分支。

## 面试常见追问速查

| 追问 | 回答 |
|------|------|
| **单例 vs 全局变量有什么区别？** | 单例有可控的创建时机（懒加载）、可继承、可替换（如测试 mock）；全局变量是裸数据 |
| **观察者和发布订阅有什么不同？** | 观察者中 Subject 和 Observer 直接知道彼此；发布订阅多了一个 Broker（消息中间件），双方完全解耦 |
| **工厂和抽象工厂的区别？** | 工厂创建单一产品；抽象工厂创建产品族（如一套 Windows 风格 UI vs Mac 风格 UI） |
| **什么情况不该用设计模式？** | 过度设计——需求简单时引入模式反而增加复杂度。原则：先写简单代码，当 smell（重复、耦合、难扩展）出现时再重构引入模式 |
| **Python 中哪些语言特性让设计模式变得简单？** | 一等函数（策略模式就是传函数）、装饰器（装饰器模式内建）、鸭子类型（不需要接口）、模块即单例 |
