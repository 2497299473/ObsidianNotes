## 3. 升级到最新版

### 方式一：uv 升级（通过 GitHub Release wheel）

> ⚠️ 当前通过 GitHub wheel 安装，`uv tool upgrade` 对非 PyPI 源无效。

对于跨小版本升级（如 0.5.3 → 0.5.4），可以直接重装覆盖当前环境（官方推荐命令）：

```bash
uv tool install --python 3.12 --force --reinstall-package opensquilla \
  "opensquilla[recommended] @ https://github.com/opensquilla/opensquilla/releases/download/v0.5.4/opensquilla-0.5.4-py3-none-any.whl"
```

> 🌏 **国内镜像替代源**：GitHub 直连可能不通（连接建立但 0 字节传输），可用阿里云 OSS 镜像代替 GitHub wheel URL，速度更快：
>
> ```bash
> uv tool install "opensquilla[recommended] @ https://opensquilla-releases.oss-cn-beijing.aliyuncs.com/releases/v0.5.4/opensquilla-0.5.4-py3-none-any.whl"
> ```
>
> OSS 路径规律：`https://opensquilla-releases.oss-cn-beijing.aliyuncs.com/releases/v<版本>/opensquilla-<版本>-py3-none-any.whl`
>
> 💡 也可以先用 `curl` 把 wheel 下载到本地、对照同目录 `SHA256SUMS` 校验后再安装（wheel 文件名必须保持完整的 `包名-版本-py3-none-any.whl` 格式，否则 uv 报 invalid wheel filename）。

如果旧版本跨越较大（如 0.3.x → 0.5.x），建议先卸载再安装：

```bash
uv tool uninstall opensquilla
uv tool install "opensquilla[recommended] @ https://github.com/opensquilla/opensquilla/releases/download/v0.5.4/opensquilla-0.5.4-py3-none-any.whl"
```

> 务必加 `[recommended]`，否则缺失 numpy、jieba 等运行依赖，导致 Squilla Router 本地 ML 路由不可用和中文分词回退。
>
> `uv tool upgrade` 只对 PyPI 源有效。如果通过 GitHub wheel 安装，需要用卸载+重装的方式更新。

## 7. 故障记录 (2026-07-25)

### 故障一：ModuleNotFoundError

**现象**

```bash
$ opensquilla version --check
ModuleNotFoundError: No module named 'opensquilla'
```

**诊断**

| 检查项 | 结果 |
|---|---|
| `~/.local/bin/opensquilla.exe` 存在 | ✅ 46KB 启动桩残留 |
| `uv tool list` 中有 opensquilla | ❌ `Failed find package` |
| Python 虚拟环境 | ❌ 已丢失 |

**根因**

`opensquilla.exe` 只是一个启动桩（stub），实际的 Python 包运行在 `uv tool` 管理的独立虚拟环境中。该虚拟环境被清理后，exe 文件残留但无法找到模块。

**修复**

```bash
uv tool install opensquilla
```

首次重装拿到的是 PyPI 最新版 **0.3.0**，但配置是 0.5.0rc4 时代留下的，导致 Pydantic 校验失败。

---

### 故障二：Gateway 启动 Pydantic 校验失败

**现象**

```bash
$ opensquilla gateway run
ValidationError: 3 validation errors for GatewayConfig
 → skills.coding_mode: Extra inputs are not permitted
 → config_version: Extra inputs are not permitted
 → llm_ensemble: Extra inputs are not permitted
```

**根因**

配置文件中存在 `0.5.x` 才有的字段（`config_version`、`[llm_ensemble]`、`skills.coding_mode`），`0.3.0`
 的 Pydantic 模型不认识，抛出 `extra_forbidden` 错误。

**修复**

升级到 GitHub 稳定版 wheel：

```bash
uv tool install "opensquilla @ https://github.com/opensquilla/opensquilla/releases/download/v0.5.1/opensquilla-0.5.1-py3-none-any.whl"
```

**注意**：PyPI 上最新只有 0.3.0，稳定版 0.5.x 只发布在 GitHub Releases，安装时需指定 wheel URL。

## 8. 升级记录 (2026-08-26)

### OpenSquilla 0.5.3 → 0.5.4

**时间**：2026-08-26
**来源**：GitHub Releases（[v0.5.4](https://github.com/opensquilla/opensquilla/releases/tag/v0.5.4)）
**发布日**：2026-08-25

**主要更新内容**：

- **HTML 文档编辑 beta**：Electron Desktop 支持单文件 HTML 附件/交付物的编辑（Preview / Source / Versions / Changes 四视图、选中元素下指令、Agent 辅助候选编辑）；仅限单文件 UTF-8 HTML，候选修改需审阅后再提交
- **Runtime Packs 与更轻的安装包**：Python / Node.js / Windows Git Bash 改为可选运行时包，在「设置 → 安全与隐私 → 沙箱 → Runtimes」管理；桌面安装包不再捆绑开发者运行时，体积明显缩小；0.5.3 捆绑的运行时不会迁移，升级后需按需安装 Runtime Packs
- **模型路由增强**：每个会话可独立选择 Direct / Router / Ensemble 策略；C3 多模型融合更健壮（固定模型回退、独立图像路由、事务性工具调用）；TokenRhythm 默认模型档位更新（C0 用 DeepSeek V4 Flash 0731，Direct/C1 用 DeepSeek V4 Pro 0813，C2 用 Kimi K2.7 Code，C3 用 GLM 5.2 B5 融合）
- **聊天/任务/附件健壮性**：Web 聊天持久化确认不再阻塞输入；重连与会话切换后活动顺序、滚动位置恢复更一致；Stop 响应更快；大附件路由时使用完整请求容量，上传图片同时可供视觉模型与工作区工具使用
- **Desktop 与平台可靠性**：Desktop 启动与 Gateway 就绪状态解耦；设置页重组为 10 个固定入口（安全与隐私合并、Memory 提升为一级页面）；崩溃恢复更快，macOS Keychain 失败有引导重试，Windows 进程树操作更可靠
- **升级兼容性**：现有 gateway 配置、会话、Agents、记忆、定时任务全部保留，增量数据库迁移自动应用；官方说明 0.5.3 可直接覆盖安装升级

**本次遇到的特殊情况**：

- 检查时发现 uv tool 环境丢失（`opensquilla version` 报 `ModuleNotFoundError`，与 [[#故障一：ModuleNotFoundError]] 同类问题），启动桩残留但包已丢失，直接重装到 0.5.4
- GitHub 直连依旧不通（连接超时），改走 OSS 镜像下载（约 59.8 MB/s），并用官方 `SHA256SUMS` 校验 wheel 一致（`79a8644b…8f3f6`）后才安装
- 顺手清理了 `uv tool` 目录下损坏的 `opensquilla-old` 残留（移入回收站），`uv tool list` 的 malformed tool 警告随之消失

**升级操作**：

```bash
# 1. 确认无 opensquilla 进程残留
# 2. OSS 镜像下载 wheel 并做 SHA256 校验
curl -L -o opensquilla-0.5.4-py3-none-any.whl \
  "https://opensquilla-releases.oss-cn-beijing.aliyuncs.com/releases/v0.5.4/opensquilla-0.5.4-py3-none-any.whl"
sha256sum opensquilla-0.5.4-py3-none-any.whl   # 与同目录 SHA256SUMS 对照
# 3. 从本地 wheel 覆盖安装（文件名必须保持完整规范名，否则报 invalid wheel filename）
uv tool install --python 3.12 --force --reinstall-package opensquilla \
  "opensquilla[recommended] @ <本地wheel路径>/opensquilla-0.5.4-py3-none-any.whl"
```

**验证**：

```bash
opensquilla version
# 输出: 0.5.4
opensquilla version --check
# 输出: You're on the latest version.
```

**状态**：✅ 升级成功，`uv tool list` 干净，官方自检确认最新版
