# i-have-adhd 项目笔记

> 记录日期：2026-08-24 ｜ 最后复核：2026-10-08 ｜ 项目：`ayghri/i-have-adhd`

## 一句话定位

一个让 AI 编码助手（Claude Code 等）**别把答案埋在一堆铺垫和废话里**的输出优化 Skill。灵感来自《The Adult ADHD Tool Kit》，核心目的是让 AI 输出"对 ADHD 友好"——直接、好扫读。

> "No ADHD diagnosis needed!" —— 适用人群不限于 ADHD，所有容易在长回复里走神/刷屏的人都需要。

## 技术要点

- **类型**：Agent 输出风格 Skill（SKILL.md 标准，供 Claude Code / Copilot CLI / Amp 等加载）
- **语言**：Python（本体为 skill 规则文件）
- **协议**：MIT
- **Stars**：约 55.2k（2026-10-08 实测 55,252；2026-08-24 首次记录时约 23k）
- **上游当前状态**：版本 0.4.1（2026-10-06 发布）｜ main commit `5a9244e0` ｜ `skills/i-have-adhd/SKILL.md` 7,201 字符
- **frontmatter 关键项**：`disable-model-invocation: true`（须手动 `/i-have-adhd` 触发，不会自动加载）

## 核心机制

通过一份 `SKILL.md`（output-style skill）注入编码 Agent 的系统提示，强制输出遵循一组规则。常见实现是"无内容隔离审查"（`kind: content_review`），让每个回复在被采用前按规则审查。

## 10 条输出规则（上游原版，供与下方温和版对照）

1. 先给出下一步行动
2. 多步骤任务用编号
3. 结尾给一个具体可执行的下一步（"打开 `src/auth.ts`" 也算）
4. 砍掉与问题无关的跑题内容
5. 长任务中定期重申当前进度
6. 给具体时间估计（分钟，不说"一会儿""很快"）
7. 让进展可见
8. 错误平铺直叙，不渲染情绪
9. 列表缩短（单条最好 ≤5 项）
10. 无开场白、无总结、无结尾寒暄

### 温和版最终生效规则（SOUL.md 固化的版本，2026-10-08 复核）

1. 行动在前——先说结论/下一步，再展开
2. 多步骤任务编号——用最少步数，琐碎步骤合并进上一步
3. 结尾给具体下一步落点
4. 砍掉无关跑题——过程中冒出的问题不算跑题，能自答就并入结果
5. 让进展与成果可见——长任务定期报状态；多步任务用 task/plan 工具维护清单；完成项显性列出
6. 给具体时间估计
7. 错误平铺直叙
8. 列表收窄（只塑形呈现，不裁剪内容）——分组 + 每组 ≤5 项，超出部分内部保留
9. 保留必要礼貌衔接（简短）
10. 短回复不强行套模板
11. 规则持久生效——仅「stop adhd mode / normal mode」可关闭

### 例外与临检（2026-10-08 新增，对应上游两个附加段）

- **六条例外**：① 用户要「解释」就完整展开；② 破坏性操作先确认再动手；③ 连续三轮 debug 仍失败就停止改代码、换假设、只问一个诊断问题；④ 真歧义先问一句；⑤ 规则与任务冲突时任务优先、只保留形状（选项类问题给 2–4 个带一行权衡的排序选项，推荐在前）；⑥ 规则与 harness 冲突时系统提示优先。
- **发前自检**：删开场宣告句、结尾的「还需要别的吗」与复述、与问题无关的旁枝、不携带信息的模糊副词（真实不确定性要留）、比喻与习语；再只读首尾两行验证「下一步做什么 / 刚刚发生了什么」是否清楚。
