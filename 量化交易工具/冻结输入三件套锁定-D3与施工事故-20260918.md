## 一、做了什么

### 1. 新增 `freeze_verify_tool.py`（零网络、只读）

把三件套校验从「agent 自由发挥」变成**工具**（沿用 09-17/09-18 观察链事故的沉淀：
关键判定一律工具化）。

| # | 三件套 | 取值 |
|---|---|---|
| ① | 代码 commit | `git rev-parse HEAD` |
| ② | 样本 sha256 | `samples_frozen_*.jsonl` 的 **LF 归一** sha256 |
| ③ | K 线聚合指纹 | `kline_fingerprint_*.json` 的 `aggregate_sha256` |

**两道闸门刻意分开**（这是本次设计的核心判断）：

- **G-A 内部完整性（硬中止，exit 3）**：样本 sha 与 meta 不符 / 行数不符 / 冻结时带降级征兆
  ⇒ 立即中止整条管线。`exit 4` = 样本或 meta 缺失，同样 fail-closed。
- **G-B 跨版本可比性（软标记，不改退出码）**：K 线指纹漂移只报 `DRIFTED`。
  **理由**：做成硬中止会让任务在正常漂移下彻底跑不动；忽略则让不可比数字蒙混过关。
  漂移是**结论**（本轮与锚定历史轮次不可比），不是运行错误。

### 2. 三个真陷阱（全部实测，非假想）

1. **换行陷阱**：`freeze_samples.py` 用 `Path.write_text` 落盘 ⇒ Windows 下 CRLF，
   但它记录的 sha256 是 **LF 归一**后的。实测 09-10 件：原始字节 `0d59f663…`
   vs meta `be8e55f0…`。**用 `Get-FileHash` / `certutil` 直接校会假失败**，
   并误中止整个重估任务。故一律走工具，并把这条写进任务定义的「三道禁令」。
2. **侧车断链**：09-10 那份 meta **没有** `kline_fingerprint_*` 字段（meta 生成于 09:52，
   指纹接入的提交 `c9630f5` 是 13:13）。属历史断链，不是损坏 ⇒ 工具按日期标签
   回退到兄弟指纹文件，不依赖 meta 字段。
3. **静默回退**（测例抓到）：初版路径解析会「同名文件兜底」，若指定文件缺失就悄悄
   去校**另一个文件**并报 PASS —— 与「钉死输入」的目的直接冲突。已改为 fail-closed。

### 3. `freeze_samples.py` 加 no-clobber

同日冻结件存在即 `exit 2` 拒绝重采。**闸门必须在 `load_samples()` 之前** ——
放在之后等于东财请求已发出去才说不采，既没防住重采、又白烧一次配额。

### 4. `deploy/quarterly_review_task.md` 更新

新增「输入三件套锁定」节 + 阶段 1.5 强制校验 + 三道禁令；报告必须逐字抄录
三件套与 G-A/G-B 结论。

## 二、⚠️ 施工事故（如实记录）

**我做错了一件事**：把 `freeze_samples.py` 当冒烟跑了（本想只做编译检查，
却在同一条命令里连着跑了它）。后果：

| 项 | 实测 |
|---|---|
| 进程 | 60 秒后被工具超时连带杀掉，无残留（已核实） |
| 东财请求 | **已发出** —— `load_samples()` 第 [1] 步先拉 4 基金 × 7 年持仓（`fundf10`，**无缓存**，首发 28 发），21:50:50 已进入第 [2] 步 ⇒ 东财请求确已发出。时间 21:50 **在 11:20 时间盒之外**，撞铁律 7 |
| 个股 K 线 | 重取 **26 只**（腾讯源）。逐行比对（有备份的 000651/000858）：**历史行 0 变化**，仅窗口滚动 —— 新增 09-16/17/18，移除最早 3 行 |
| 聚合指纹 | `4486cc4f…` → `9c20f527…` |
| 冻结件 | **未产生**（`samples_frozen_20260918.jsonl` 不存在） |
| 产物污染 | `forecast_outputs/` 无新增，`f10_raw` 空 |

**两条教训**：
1. **含网络的脚本不得当冒烟跑**。`--help` / `py_compile` 才是零副作用的编译检查。
2. **东财请求必须由人显式授权**（铁律 7），不得被「顺便跑一下」带出去。

> 事后核对口径上的自我纠错：第一次判定「历史段被追溯改写」用的是**截断序列哈希**，
> 而 `_seq_sha` 是全序列哈希 ⇒ 该比对无意义（对照组也 99/215「不一致」，暴露方法错）。
> 改用增量前缀哈希后结论才成立。**方法错会造出假结论**，这与本轮 C2 的主题同源。
