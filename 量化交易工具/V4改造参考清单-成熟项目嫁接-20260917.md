## 1. 参考栈（已核实结构，不是 README 摘要）

### FundVal-Live｜Python + Django 全栈，AGPL-3.0，约 528★ / 103 fork
```
backend/api/sources/
    base.py                # provider 协议
    registry.py            # ← SourceRegistry（1.7KB，核心）
    eastmoney.py           # 30KB，主源
    danjuan.py  sina.py  yangjibao.py  xiaobeiyangji.py  # 4 个旁源
    akshare_estimate.py    # AKShare 适配
    penetration_engine.py  # 持仓穿透估值（14KB）
backend/api/services/      # nav_history / position_history / import_*
backend/api/{tasks,models,views,viewsets,serializers}.py
```
**要害**：它的 fallback 不是写在业务函数里的 if/else，而是 **`sources/` 一个源一个文件 + `registry.py` 统一登记**。
这是最值得借的一层抽象。

### fundviewer｜Python，MIT，仅 24★ / 6 fork（分支 v3）
```
data_sources/{base,fallback,fund,nav,stock,index,bond,portfolio,verify}.py
cache/{memory_cache,disk_cache}.py
```
**要害**：`fallback.py` 单独成文件、`cache/` 内存+磁盘双层。思路可看一眼，但**量级不够当主参考**（见 §3）。

### Qlib｜MIT，约 48.6k★
```
qlib/data/{base,cache,client,data,filter,inst_processor,ops,pit}.py
qlib/data/dataset/{handler,loader,processor,storage,utils,weight}.py
qlib/workflow/{exp,expm,recorder,record_temp,online,task}
qlib/{backtest,strategy,model,rl,contrib}
```
**要害**：`Handler → Dataset → Split` 三段分离 + `workflow/recorder` 把「一次实验」当一等公民存档。
对应你「每加一个实验就多一个 `backtest_xxx.py`」的失控风险。

### FinRL-X (FinRL-Trading)｜Apache-2.0，约 3709★ / 1094 fork，最后推送 2026-05-02
```
src/{backtest,config,data,strategies,tools,trading,utils,web}
src/backtest/backtest_engine.py   # 31KB 单一回测引擎
```
**要害**：**weight-centric**——策略层只输出标准化目标权重向量 `w_t`，回测/下单/生产共用同一契约。
对应你 `decision_engine` → `policy` → `action` 的那条链。

### TimesFM｜代码 Apache-2.0
**要害**：原生多变量 + 过去/未来协变量（3.0）。权限限制见 §3。

### Kronos｜MIT，约 38.9k★，**最后推送 2026-04-13，275 个 open issue**
**要害**：金融 K 线 tokenizer + Transformer，提供 fine-tune 脚本。适合**持仓股票级**，不适合直接预测基金 NAV。

## 3. 三处必须修正的判断

**① FundVal-Live 是 AGPL，不是「裁剪拼接」对象。**
已核实 `/license` 返回 GNU Affero GPL v3。借它的四个模式（源注册表 / 健康检查 / fallback 链 / 来源标记），
**自己写**。见 §0 的条件成立说明。

**② TimesFM 3.0 权重是「非商业 + 非生产」许可。**
仓库 `LICENSE` 确认 Apache-2.0，但 **3.0 的 checkpoint 挂在 `timesfm-non-commercial-license-v1.0` 下**，
明确排除生产部署；2.5 及以前才是 Apache-2.0。且许可**发布后才收紧**，稳定性本身是风险信号。
你本地 `QuantV1-tfm\Lib\site-packages` 已装 **`timesfm 3.0.1`**。
V4 有 shadow / registry / promotion 这条准生产链路，因此：
- 3.0 → **只做离线 benchmark**；
- **禁止**进入 registry 的 promotion 路径；
- 生产候选走 **TimesFM 2.5（Apache-2.0）**。

**③ fundviewer 不到「被大量实践过」的门槛。**
24★ / 6 fork，是个人项目量级。思路可看一眼，**不该与 FundVal-Live 并列为主参考**。

> 方法论补充：原始清单按「功能像不像」排序，**完全没考虑「许可证能不能借」**。对 V4 这种带
> registry/promotion 的项目，许可证是硬约束，不是脚注。

## 5. 二批核实结果（2026-09-17 补，GitHub API `/repos` + `/git/trees` 实拉）

| 项目 | 许可证 | star / 活跃度（实测） | 结论 |
|---|---|---|---|
| MLForecast (Nixtla) | **Apache-2.0**（`pyproject.toml` + API 双确认） | 1.28k★，最后推送 2026-09-15，**活跃** | 可参考、可引依赖。`mlforecast/` 包内 `lag_transforms.py` / `target_transforms.py` / `feature_engineering.py` 是「特征变换可组合」的现成契约，对 forecast_lab 有直接参考价值 |
| RD-Agent (microsoft) | **MIT**（API 确认） | 14.7k★，最后推送 2026-09-15，**活跃** | 实验编排思想可借。`rdagent/{app,components,core,scenarios}` 分层 = 「场景(scenario)与执行引擎(core)分离」，对应你 experiments 目录的失控风险 |
| bt (pmorissette) | **MIT**（API 确认；⚠️ 网上不少文章误写 BSD，以仓库 LICENSE 为准） | 2.98k★，最后推送 2026-09-16，**活跃** | `bt/{core,algos,backtest}.py` 三文件 = Asset/Algo/Backtest 三层，结构干净可借分层思想 |
| Backtrader (mementum) | **GPL-3.0**（API 确认） | 23.3k★，**最后推送 2024-08-19 ≈ 停更 2 年**，已关 issue | ⚠️ **从参考栈剔除**，两条独立理由：① GPL-3.0 传染性（比 AGPL 弱但仍是 copyleft，本地用不触发、一旦分发即传染）；② 停更 2 年 + matplotlib 兼容靠社区补丁——不满足「被大量**且持续**实践」门槛 |
| AKShare (akfamily) | **MIT**（API 确认） | 22.6k★，最后推送 2026-09-17 当日，**极活跃** | ⚠️ **只作数据源适配层候选，不引入为生产依赖**：它本质是「别人接口的聚合器」，东财/新浪上游一改版它就断（断裂史即 its issues）；且引入即背 3.5k+ 传递依赖。V4 的 `netutil + 自写 provider` 路线更可控 |

**二批净结论**：
1. 参考栈里 **`bt` 留下、Backtrader 剔除**（重叠功能，MIT+活跃 vs GPL+停更，无需犹豫）。
2. 许可地图最终版：**全部参考项 MIT / Apache-2.0，唯一 AGPL 仍是 FundVal-Live（只读设计），
   唯一新增 copyleft 风险项 Backtrader 已剔除**——参考栈无遗留许可债。
3. MLForecast 值得升为 forecast_lab 的**第四主参考**（排在 RD-Agent 前）：它解决的是
   「特征工程如何可组合、可复用」，正是你 22 个实验脚本各写各的特征的痛点；
   RD-Agent 解决「编排」，层次更靠上、耦合也更重（LLM 驱动），借思想不借架构。
