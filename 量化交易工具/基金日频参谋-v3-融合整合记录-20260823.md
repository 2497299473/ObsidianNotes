## 四、三处增量手术的技术细节

### 手术 ①：账户面均值项（`core/account.py`）

**问题**：GLM 原版次日区间 = `nav × (1 ± 1.5σ)`，中心恒为最新净值。若近 20 日存在漂移（μ≠0），区间中心系统性偏移——次日净值大概率不在旧净值附近。

**改法**：
- 原 `daily_volatility(navs, window)` → 拆为 `daily_return_stats(navs, window) → (μ, σ)`
- 次日区间因子：`lo_f = 1 + μ - 1.5σ`，`hi_f = 1 + μ + 1.5σ`
- 即 `nav × (1 + μ₂₀ ± 1.5·σ₂₀)`，μ 平移中心，σ 控制宽度
- `positions` 新增 `daily_mean` 字段（百分数，4 位小数）

**报告层**：账户表新增「μ20(%)」列 + 公式脚注 `次日区间 = 净值 × (1 + μ₂₀ ± 1.5·σ₂₀)`

```python
# 改造前（GLM 对称区间，中心=旧净值）
"next_day_range": (nav * (1 - 1.5*sigma), nav * (1 + 1.5*sigma))

# 改造后（融合均值项，中心随漂移偏移）
mu, sigma = daily_return_stats(navs, vol_window)
lo_f = 1 + mu - cfg["next_day_range_sigma"] * sigma
hi_f = 1 + mu + cfg["next_day_range_sigma"] * sigma
"next_day_range": (nav * lo_f, nav * hi_f)
```

> ⚠️ `abnormal` 异常波动告警阈值**未改**——融合只动区间公式，不重新定义异常性判定（`abs(last_change) > 2σ` 保持原口径）。

### 手术 ②：数据降级告警链路（`core/data_loader.py` + `core/signal_engine.py`）

**问题**：GLM 原版缓存命中时不告知用户数据可能非最新；接口失败时直接抛异常或静默降级，信息透明度缺口。

**改法**：`load_fund()` 返回的 fund dict 增加 `_source` 字段，三态标记：

| `_source` 值 | 含义 | 报告层行为 |
|:---|:---|:---|
| `fresh` | 本次运行成功抓取官方接口 | 不提示 |
| `cache` | TTL 内缓存命中 | 轻提示（净值日期可见） |
| `cache:fallback(错误)` | 接口失败降级读缓存 | ⚠️ 显式告警 |

**增强点**：缓存读取包裹 `try/except (json.JSONDecodeError, OSError)`——缓存文件损坏不崩溃，自动走网络重抓。

**透传链路**：`data_loader.load_fund() → fund["_source"] → signal_engine.compute_signals() → signals[code]["_source"] → report_generator._data_source_notice()`

### 手术 ③：报告层透传（`core/report_generator.py`）

新增 `_data_source_notice(signals)` 辅助函数，插入在「因子分解」与「重仓股结构观察」之间：

```markdown
> ⚠️ **数据降级告警**：002112（净值截至 2026-08-22） 本次接口抓取失败，
> 已使用本地缓存，净值可能非最新，结论仅供参考。

<sub>本地缓存复用（TTL 内未重新抓取）：025687（截至 2026-08-22）。</sub>
```
