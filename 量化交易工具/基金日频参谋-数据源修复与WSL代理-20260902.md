# 数据源网络修复 与 WSL 代理配置（2026-09-02）

> 背景：GPT 建议加「板块指数基金层」时，v5 笔记（2026-08-26）的「申万免费源不可用」
> 结论成为阻断项。本次系统性排查该结论是否过期，顺带解决「WSL 要不要靠代理」的疑问。
> 结论先行：**08-26 的阻断结论已过期**——根因是「东财 v6 边缘黑洞 + WSL 死代理注入」，
> 不是接口死了；已用 `core/netutil.py` 修复项目全链路，接口本身可用（有残余抖动，见下）。

## 一、根因（三层，全部实测定位）

### 1. 东财 v6 边缘黑洞（主因，外部因素）
`push2his`/`push2` 均 CNAME 到 `*ipv6*.trafficmanager.cn`（**Azure Traffic Manager
IPv6 优先边缘池**）。实测（2026-09-02 07:50~08:40）：
- v6 端点：TCP 通、TLS 握手成功、**请求后 0 字节即断**（`RemoteDisconnected`）——这就是 08-26 笔记里「SSL 崩溃 / record layer failure」的真身；
- TM 每次只下发**一个 v4 + 一个 v6** 边缘 IP（TTL 10~500s 轮换），v4 边缘也时好时坏
  （103.220.167.80 通 / 140.207.67.156、61.129.129.199 断）；
- CPython 无 happy-eyeballs，`http.client`/`ssl` 走 **C 层 `_socket` 解析 DNS**，
  Python 层 monkeypatch `socket.getaddrinfo` **对其无效**（v1 补丁实测未生效）。
- 对照：`fundf10`/`api.fund`（项目日常基金净值接口，无 trafficmanager）不受影响。

**诚实边界**：v4 边缘节点健康度是东财侧外部因素，本地无法根治；能做的只有
v4 优先 + 逐 IP failover + 重试，把单次请求成功率从「碰运气」提到「大概率」。

### 2. WSL 死代理注入（帮凶，已修）
Windows 系统代理（WinINET）指向 `127.0.0.1:7892`，但**无进程监听**（代理客户端未运行）；
WSL `autoProxy` 默认把它注入 WSL 的 `http_proxy` 环境变量 → urllib 全流量
`Connection refused`。`.bashrc` 里 08-27 已加过 guard（交互式 shell 会清），
但非交互场景（cron、`wsl -d Ubuntu --` 直跑）不一定覆盖。

### 3. 排除项（实测排除）
- 非 UA 屏蔽（浏览器 UA 重试仍 0/4）；非代码 bug（curl 无代理时 clist/tencent 全 200）；
- 非「免费端风控」（当时推测错误，停止该说法）；f128 返回地域板块是**字段语义**
  （行业名只在 f127），不是故障。

## 二、修复：`core/netutil.py`（新增，v3 定稿）

**设计**：
1. `_resolve_candidates()`：自己解析**全部**地址，v4 优先 v6 兜底、去重；
2. `_request_once()`：逐 IP 建连（预置 `conn.sock`，HTTPS 保留 SNI 证书校验），
   命中坏节点（断连/SSL 断/超时）**自动 failover 下一 IP**；4xx/5xx 不 failover；
3. `_open_with_retry()`：连接层瞬断再时间重试（默认 2 次）；ECONNREFUSED 不重试；
4. 主链路完全不走 urllib opener、不读环境代理（数据源全国内，直连即可）；
5. `NO_PROXY_OPENER`：给飞书推送等特殊调用（绕代理、不重试——推送非幂等）；
6. `socket.getaddrinfo` 的 v4 优先补丁保留，仅作第三方库 Python 层兜底。

**接线**（`core/__init__.py` import 时即安装 DNS 补丁）：
- `stock_data.py`：`_http_json`/`_tushare_post` → netutil
- `data_loader.py`：`_http_get` → netutil（基金净值/持仓主链路）
- `real_time.py`：实时行情 → `netutil.http_get_bytes`（GBK 自 decode）
- `lookthrough.py`：持仓历史 → netutil
- `notify.py`：飞书推送 → `NO_PROXY_OPENER`（不重试，失败降级本地落盘）

**验证**：
- `tests/test_netutil.py` 10/10（DNS 排序 / 重试分类 / 死代理绕过 / 瞬断恢复，全离线）
- 全量回归 `python3 -m unittest discover tests`：**206 OK (skipped=3)**（09-02 08:55）
- 真实端点：tencent ETF 5/5、东财 clist（100 板块）通、push2his 有残余抖动（见笔记 2）

## 三、WSL 代理配置（已改，待 `wsl --shutdown` 生效）

1. **`C:\Users\Turn-\.wslconfig`** 加 `autoProxy=false`：不再把 Windows 系统代理
   自动注入 WSL。改后需 `wsl --shutdown`（会重启所有 WSL 实例）。
2. **`~/.bashrc`** 加 `proxy_on` / `proxy_off` 函数：需要代理时手动 `proxy_on`
   （前提：代理客户端已在 Windows 侧运行）；QuantV1 数据层恒直连，不受开关影响。
3. 保留 08-27 的 proxy guard（双保险：即使 autoProxy 残留注入也自动清死代理）。

**日常口径**：QuantV1 全链路不依赖代理（国内源直连）；代理只给需要翻墙的场景
（如以后接海外数据源）手动开。
