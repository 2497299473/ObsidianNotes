## 三、V4.4 本批（2026-09-22）核心变更：14:55 PIT Forecast 契约

### 拍板背景（Summer 定 label 分母口径）

现行 label：`fwd_h = navs[T+h]/navs[T] − 1`，分母是 **T 日最终 NAV**。但用户在 **14:55 决策时 T 日 NAV 尚未公布**（约当日 21~22 点才出）。以"当时看不到的价"作分母，语义不纯。

**拍板：label 分母改为「从 14:55 可观测状态起算」，全量重算。**

### 契约定义（唯一权威，落点 `core/pit1455_contract.py`）

```
nav_hat_1455(T) = navs[T−1] × (1 + est_chg)      # 14:55 时对 T 日 NAV 的最优估计
fwd_from_1455(h) = navs[T+h] / nav_hat_1455(T) − 1
```
- `navs[T−1]`：14:55 时点最后一个**已公布**净值（前一交易日），决策时必可见 → 成立。
- `est_chg`：**fraction 量纲**（0.0123 = 1.23%）。

### 🔴 本批核出的硬 P0：est_chg 量纲错位（100×）

| 侧 | 来源 | 量纲 | \|est_chg\| 范围 |
|:--|:--|:--|:--|
| 训练 / 冻结样本 | `backtest_spread` 用 `closes[j]/closes[j−1]−1` | **小数 fraction** | absmax 0.1798 |
| live / shadow 特征 | 腾讯行情 `parts[32]` 涨跌幅 | **百分数 pct** | 72 条 post 行 absmax 7.89、中位 1.29 |

**后果（实测）**：72 条 live post 行里 **66 条（91.7%）落在训练支撑域之外**；若 /100 归一，越界归零。`forecast_engine.predict` 无任何缩放（直接 `float(v)`）。同一 key 训练/推理差 100× —— 独立于原三 P0 的第四个硬伤。

> 本批**只登记换算桥 `est_chg_from_pct()` 与量纲常量 `EST_CHG_UNIT="fraction"`，未改 run.py / shadow 的现有产出**（避免一把梭）。接入是步 2：届时所有消费点统一过桥，**禁止各自 `*0.01` / `/100`**。

### ② 🔴 本步最关键发现：1455 口径的「机械耦合」——基线必须从 0 换成 −est_chg

契约分母含 `est_chg`，而 `est_chg` 同时是模型输入特征 ⇒ 机械耦合。精确恒等式（实测残差 5e-7，舍入级）：

```
1 + fwd_1455 = (1 + fwd_old) · (1 + a_T) / (1 + est_chg)
```

（`a_T` = T 日真实涨跌。实测 label 位移与 `a_T − est_chg` 的 Spearman = +0.9998 ⇒ 位移几乎全由「est_chg 估偏多少」驱动。）

| 口径 | 诚实基线 | 池级 OOS 基线 IC（T+1/3/5，n=923） |
|:--|:--|:--|
| old | `+est_chg` | −0.013 / +0.025 / −0.009（≈0，与 0 比成立） |
| **1455** | **`−est_chg`** | **+0.1278 / +0.0393 / +0.0567**（必须与它比） |

⇒ 零成本公式「预测分 = −est_chg」不训练就有正 IC。B 轨 1455 IC +0.1139（T+1）看着漂亮，**超额 = −0.0139，跑输该基线**；A/C 轨 T+1 同样不及。**1455 口径下「模型有排序能力」的结论不成立。**

- **契约式一字未改**（分母含 est_chg 正是「14:55 可观测」的定义所在），只把「1455 裁决基线必须是 −est_chg」写进 `core/pit1455_contract.py` 的消费纪律注释。
- **更干净的替代口径（留 Summer 拍板）**：预测目标应仍是 old 口径（T→T+h 真实收益）；1455 只用于「决策时可得的输入」与「相对 14:55 估计价的盈亏核算」，不该塞进 label 分母后再拿模型分与它比。
