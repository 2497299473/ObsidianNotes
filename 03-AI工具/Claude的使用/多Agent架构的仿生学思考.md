## 核心洞见

**AI Agent 架构设计，本质上是在模拟人类的社会分工——是 AI 对人类组织的"仿生学"。**

不理解 Agent 架构选型的时候，对照真实世界的公司组织类比着想一想，思路就有了。

---

## 概念一一映射

以一个 IT 公司为参照，每个 AI Agent 概念都能在组织中找到对应：

| AI Agent 概念 | 公司组织映射 |
|---|---|
| **Agent** | 前台、中台、后台——每一个部门 |
| **Sub-Agent** | 下辖的子部门、具体员工 |
| **Skill** | 员工的职业技能（策划、设计、编程、测试） |
| **Tool** | 生产工具（PPT、Excel、Figma、VSCode、Docker） |
| **Handoffs** | 流水线交接（PM → 设计 → 开发 → 测试 → 运维） |
| **Router** | 需求分析 → 任务分派 → 结果对齐 |
| **Memory** | 经验积累 / 知识库 |

---

## 四种模式是层层递进的组织复杂度

四种 Agent 模式不是并列的选项，而是**自下而上层层递进的关系**——跟公司从创业到壮大的过程一一对照：

```
单打独斗（单 Agent）
  └─ 初创公司：一个人什么都干
      │
  → 会的东西多了，按需切换技能（Skills）
  └─ 自由职业者：能设计、能开发，但一次只切一个身份
      │
  → 人不够用，招人分担（Sub-Agents）
  └─ 小团队：老板 + 各司其职的员工，老板统一协调
      │
  → 流程复杂，需要规范交接（Handoffs）
  └─ 中型公司：部门间有明确的上下游和交付标准
      │
  → 业务线多，加调度层（Router）
  └─ 大公司：有专门的项目管理 / PMO 做资源分配和结果整合
```

这解释了课程里的黄金法则——**"从单 Agent 开始，只在遇到明确瓶颈才升级"**——因为没人会在创业第一天就画百人公司的组织架构图，那是过度设计。

---

## 性能、成本、可控性——三角博弈的人话版

课程里说的"性能、成本、可控性三角博弈"，映射到人身上就非常好懂：

| 维度 | AI 视角 | 人的视角 |
|---|---|---|
| **性能** | 大模型的能力 | 个人能力 |
| **成本** | Token 消耗 | 人员工资 |
| **可控性** | 边界清晰、输出稳定 | 员工有没有责任心、办事靠不靠得住 |

> 选架构 = 选人建团队：任务简单，一个人干就行；任务复杂，才需要拆团队、设流程、加管理层。

---

## 一个反复说到的论断

> **AI 时代，做一个好产品、做成功一番事业，技术不再是壁垒，而是人对真实世界的理解。**

Agent 已经从"玩 Prompt"进入了"拼工程结构"的阶段。而真正决定架构好坏的，不是你对某个框架有多熟，而是你能不能把真实世界中的组织分工逻辑，映射到 Agent 系统的设计中。

**当不知道如何选型时，多问自己：如果这是一家公司，我会怎么建团队、怎么分职责？**
