## 核心问题

CLAUDE.md 的本质是在 Token 有限的情况下尽量少走弯路。那么：**如何形式化地判断某一行该不该存在于 CLAUDE.md 中？**

## 期望值框架

把决策转化为比较两个期望值：

$$E[\text{保留}] = \text{该行本身的 Token 成本（每次对话都支付）}$$

$$E[\text{删除}] = P(\text{出错} \mid \text{缺少这一行}) \times \text{出错时的 Token 成本}$$

**决策规则**：保留当且仅当 $E[\text{保留}] < E[\text{删除}]$。

## 与原文原则的对应

原文的核心原则 "如果你不写，Claude 也大概率会做对，那就不要写" 恰好是这个框架的直觉版——当 $P(\text{出错})$ 趋近于 0 时，$E[\text{删除}]$ 也趋近于 0，必然小于 $E[\text{保留}]$，所以不该写。

期望值框架的优势在于把"大概率"拆成了**概率**和**代价**两个可分别估算的维度。

## 三个关键补丁

### 补丁 1：Prompt Cache 改变了"保留侧"成本

CLAUDE.md 通常被 prompt-cached，边际 token 成本远低于面值。而纠错对话通常不在 cache 中，是全价 token。

→ **Cache 让更多行"值得保留"**，但 cache 容量有上限，超限后成本急剧上升。

### 补丁 2：出错代价不仅是 Token

纠错的真实成本包含三个层次：

| 层次 | 说明 |
|------|------|
| Token 成本 | 纠正对话消耗的 token |
| 质量成本 | **锚定效应** — Claude 沿错误方向走了一段后，纠正回来的方案往往不如一开始就走对方向 |
| 时间成本 | 你阅读、发现、描述问题的时间 |

质量成本解释了为什么安全规则（"禁止硬编码密钥"）即便 $P$ 很低也必须保留——**ErrorCost 极大**。

### 补丁 3：行与行之间不独立（稀释效应）

CLAUDE.md 不是各行独立贡献信号：

- **注意力稀释**：500 行 CLAUDE.md 里第 487 行的影响力趋近于零
- **矛盾风险**：两行分别看都合理，放在一起可能产生歧义

→ 决策不能逐行独立做。**新增一行时，既要算这一行的期望收益，也要扣除它对已有内容的稀释成本。**

## 更完整的决策公式

$$\text{CacheCost}(\text{line}) + \text{DilutionCost}(\text{line}) < P(\text{出错} \mid \text{没有这一行}) \times \text{ErrorCost}$$

其中 $\text{ErrorCost}$ 是 Token 成本 + 质量成本 + 时间成本的综合。

## 实操启发

因为 $P$ 和 ErrorCost 无法精确量化，这个框架更适合作为**决策直觉**：

每次想往 CLAUDE.md 加东西时，问自己三个问题：

1. **概率**：如果我不写这一行，Claude 搞砸的概率有多大？（> 30% 才值得认真考虑）
2. **代价**：搞砸了要花多少 token 和时间来修？（纠正一句话 vs 重写整个模块，差别巨大）
3. **频次**：这类错误在多少比例的任务中会出现？（每次都出现 vs 一年一次）

| 场景 | P(出错) | ErrorCost | 结论 |
|------|---------|-----------|------|
| 技术栈（Fastify + TS） | 高 | 中 | ✅ 必留 |
| "写高质量代码" | ≈ 0 | 低 | ❌ 必删 |
| 安全规则（禁止硬编码密钥） | 低 | 极高 | ✅ 必留 |
| API 响应格式示例 | 中 | 中 | 🤔 看长度 |
| 个人 PPT 偏好（16:9） | 高 | 中 | ✅ 放用户级 CLAUDE.md |

## 边界情况：当 CLAUDE.md 接近 Cache 上限

此时稀释效应急剧放大。决策从"这行本身值不值"变为 **"这行比目前最不值得的那行更值吗？"**——需要做边际替换而非边际新增。
