## 适用场景

Redis、Nginx、RabbitMQ、Kafka、Tomcat 等中间件的配置文件审查。银行内网环境中，中间件配置错误轻则性能退化，重则导致数据丢失或安全漏洞。

## 各中间件常见配置问题

### Redis
| 问题 | 危险配置 | 安全配置 |
|------|---------|---------|
| 无密码 | (空) | `requirepass xxx` |
| 公网绑定 | `bind 0.0.0.0` | `bind 127.0.0.1` |
| 禁用持久化 | `save ""` | `save 900 1 300 10` |
| 危险命令 | (默认全开) | `rename-command FLUSHDB ""` |
| 超时未设 | `timeout 0` | `timeout 300` |

### Nginx
| 问题 | 危险配置 | 安全配置 |
|------|---------|---------|
| 版本泄露 | `server_tokens on` | `server_tokens off` |
| HTTP 方法全开 | (默认) | `limit_except GET POST HEAD { deny all; }` |
| 缓冲区溢出 | 未设 `client_body_buffer_size` | 设置合理的 buffer 限制 |
| 超时过大 | `proxy_read_timeout 600s` | 根据业务设置，一般 ≤ 60s |

### RabbitMQ
| 问题 | 危险配置 | 安全配置 |
|------|---------|---------|
| 默认账号 | `guest/guest` | 删除 guest，创建专用账号 |
| 队列无 TTL | (默认永久) | 设置 `x-message-ttl` |
| 无死信队列 | (默认丢弃) | 配置 `x-dead-letter-exchange` |
| 消费者无超时 | (默认无限) | 设置 `consumer_timeout` |
