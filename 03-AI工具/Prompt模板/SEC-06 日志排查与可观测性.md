## 适用场景

生产环境告警后的快速定位。通过日志上下文、TraceID 串联、异常模式识别，从海量日志中提取关键信息。适用于交易失败排查、批量任务异常、对账差异定位等场景。

## 使用说明

银行系统通常有 ELK/日志平台。将查询到的日志片段粘贴到 `<log_snippet>` 中，让模型辅助分析。**注意：粘贴前必须脱敏**（使用 [[SEC-02 数据离线脱敏与PII规则校验|SEC-02]]）。

### ⚡ 快速定位命令
```bash
# 按 TraceID 串联全链路
grep "trace-abc123" /var/log/app-*.log | sort -t' ' -k1

# 统计异常时间段各服务的错误数
grep "2026-07-12 14:3[5-9]" /var/log/app-*.log | grep -c "ERROR"

# 检查数据库连接池状态
grep "connection" /var/log/app-payment.log | tail -20
```

### 📋 故障排查 Checklist
- [ ] 确认异常时间窗口（精确到分钟）

- [ ] 沿 TraceID 串联上下游日志

- [ ] 检查该时间段的资源使用（CPU/内存/连接池）
- [ ] 检查是否有并发/锁等待
- [ ] 确认是否与最近变更相关
```

## 日志片段粘贴前检查

> ⚠️ **粘贴前必须执行**：使用 [[SEC-02 数据离线脱敏与PII规则校验|SEC-02]] 模板扫描日志中的 PII。

至少检查：
- [ ] 无明文身份证号
- [ ] 无明文银行卡号
- [ ] 无明文手机号
- [ ] 无密码/Token
- [ ] TraceID/GUID 可以保留（不包含个人信息）

## 常见日志异常模式

| 模式 | 特征 | 常见根因 |
|------|------|----------|
| 突然大量超时 | 所有接口同时超时 | 数据库/依赖服务不可用 |
| 波浪形超时 | 周期性恢复又超时 | 连接池打满→释放→再打满 |
| 单接口超时 | 其他接口正常 | 该接口慢查询/死锁 |
| 日志断档 | 一段时间完全没有日志 | Full GC / OOM / 进程被杀 |
| ERROR 数阶梯上升 | 每5分钟更多 | 线程池队列堆积 |
| 全部服务同时异常 | 跨服务雪崩 | 网络故障 / 基础组件故障 |
