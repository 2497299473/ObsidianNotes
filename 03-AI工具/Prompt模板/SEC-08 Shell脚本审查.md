## 适用场景

部署脚本、定时任务脚本、数据清洗脚本、数据库备份脚本、日志轮转脚本的审查。银行内网大量依赖 Shell 脚本做运维自动化，一个没有 `set -e` 的脚本可能静默失败导致数据丢失。

【CHECKLIST】
逐项检查以下维度：

**鲁棒性**
- 是否以 `#!/bin/bash` 开头（指定解释器）
- 是否设置了 `set -euo pipefail`（遇错退出/未定义变量报错/管道失败）
- 是否正确处理了退出码（`$?` 检查）
- 是否有超时保护机制

**安全性**
- 是否包含硬编码的密码/密钥
- 是否使用 `curl ... | bash` 模式（禁止）
- 临时文件是否使用 `mktemp` 创建（而非固定文件名）
- 是否有命令注入风险（用户输入未转义直接拼接到命令中）

**幂等性**
- 重复执行是否安全
- 是否有防重复运行的锁机制（flock / pidfile）

**可观测性**
- 是否有明确的日志输出（开始/结束/关键步骤）
- 错误输出是否重定向到 stderr
- 是否记录了执行耗时

## Shell 脚本安全检查速查

| 危险写法 | 问题 | 安全写法 |
|----------|------|----------|
| `PASSWORD="abc123"` | 硬编码密码 | 从环境变量或 vault 读取 |
| `db_dump > /tmp/backup.sql` | 固定临时文件名 | `mktemp` 生成随机文件名 |
| `curl -s http://x | bash` | 远程代码执行风险 | 禁止，改为下载后校验再执行 |
| `rm -rf $DIR/` (DIR为空时) | 变量为空时 `rm -rf /` | `rm -rf "${DIR:?}"` |
| `[ $? -eq 0 ]` | 容易漏写 | `if command; then` |
| `echo "start"` (无时间戳) | 无法回溯 | `echo "$(date '+%F %T') [INFO] start"` |
