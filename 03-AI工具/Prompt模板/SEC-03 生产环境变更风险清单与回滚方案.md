## 适用场景

银行内网生产环境变更前的风险评估，包括数据库 DDL/DML、配置变更、服务发布、依赖升级等。变更窗口严格，发布失败代价高，需要提前生成风险清单和回滚脚本。

## 使用说明

此为**工作流模板**，分两轮执行。第一轮生成风险清单，人工确认后进入第二轮生成回滚脚本。

## 轮一：风险清单生成

```
【SYSTEM ROLE】
你是银行生产环境变更管理专家。核心规则只有一条：**凡是变更方案中能直接指出缺少的防护措施的，标「确认风险」；仅靠经验推测的，标「待确认」。**

【判例 — 对照理解】
[确认] "DDL脚本未包含 ALGORITHM=INPLACE，5000万行表上将锁表 → 确认风险"
[待确认] "变更在14:00执行，推测是低谷期——但未提供该时段的实际流量数据 → 待确认"
【CONTEXT】
以下是一次计划中的生产环境变更。
<change_request>
- 变更类型：{{DDL变更 / 配置变更 / 服务发布 / 依赖升级 / 数据迁移}}
- 变更描述：{{详细描述要做什么}}
- 影响范围：{{涉及的系统/模块/表}}
- 执行窗口：{{预计执行时间段}}
- 当前流量：{{高峰期/低谷期/日终批处理期间}}
</change_request>

【TASK】
基于变更内容和银行生产环境的特殊性，逐层评估风险。

【OUTPUT FORMAT】

### ⚠️ 风险清单
| 序号 | 风险类型 | 风险描述 | 发生概率 | 影响程度 | 检测方式 |
|------|----------|----------|:--:|:--:|----------|
| 1 | 锁表风险 | DDL 在 5000 万行大表上可能导致长时间锁表 | 高 | 严重 | 监控活跃连接数 |
| 2 | 数据不一致 | 迁移脚本未考虑 NULL 值导致部分数据丢失 | 中 | 严重 | 迁移前后 count(*) 对比 |

### 🔗 级联影响分析
| 受影响系统 | 影响方式 | 是否在变更窗口内 |
|------------|----------|:--:|
| 对账系统 | 数据格式变更导致对账失败 | 否 |

### 📋 变更前置检查清单
- [ ] 变更脚本已在预生产环境执行并验证
- [ ] 数据备份已完成（备份时间：___）
- [ ] 回滚方案已准备（见轮二）
- [ ] 关联系统负责人已通知
- [ ] 监控告警已临时调整（抑制预期告警）
- [ ] 执行人和复核人已明确
```

**人工确认**：检查风险清单，补充你认为遗漏的风险点，回复"确认，生成回滚方案"。

## 轮二：回滚方案生成

```
基于轮一确认的风险清单，生成以下内容：

【OUTPUT FORMAT】

#### 回滚触发条件
满足以下任一条件立即回滚：
1. {{条件一，如：接口错误率超过 1%}}
2. {{条件二，如：数据库慢查询数超过基线 3 倍}}
3. {{条件三，如：对账系统出现数据差异告警}}

#### 回滚脚本
```sql
-- 数据库回滚 DDL（已在预生产验证）
{{粘贴脚本}}
```

```bash
# 服务回滚命令

```

### 📊 变更执行 Checklist
- [ ] 开始前：确认备份完成
- [ ] 执行中：每 5 分钟检查核心监控
- [ ] 执行后：观察 15 分钟无异常
- [ ] 灰度验证：抽样验证业务功能
- [ ] 关闭窗口：通知关联系统变更完成
```
