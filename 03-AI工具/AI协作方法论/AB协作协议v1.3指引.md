## 角色最小集（v1.3）

| 角色 | 约定 | 权限 |
|---|---|---|
| **Agent A** | 审核者 | **只读（纪律约束）**：直读本地代码/测试/文档，禁一切写操作与触网脚本 |
| **Agent B** | 执行者 | 完全访问本地文件系统；修复 + 自测 + commit/push |
| **Summer** | 信使 + 仲裁（人） | A⇄B 原样搬运；冲突裁决；会话开关决策 |

## 工作节奏（一轮 = 三阶段）

**定向审计**（A 在 Summer 圈定范围内出问题单，每条必带验收标准）→ **一次性修复**（B 逐条修复；意见冲突先报 [CONFLICT] 仲裁）→ **分级验收**（P0 五层 / P1 三层 / P2 两层；跑测试归 B，输出落盘进仓库供 A 直读）→ **收敛判定**（全部 ✅ 关闭；每条最多 1 轮定点返工，仍不过则仲裁或降级 backlog）。全域深扫只留给里程碑终审，日常轮次禁用。

## 证据层级铁律（Memory is context, never evidence）

事实效力排序：**当前 SHA 的代码/文件 > 当前测试输出 > 当前文档 > 明确引用的历史提交 > 历史记忆 / 交接卡 / 上一轮结论**。B 的自测结果对 A 永远属「对方报告未独立验证」，除非落盘进仓库。

## 四条铁律（摘要）

1. A 出问题必须带验收标准（没有验收标准的意见 B 有权拒收）；
2. B 的修复未本地 commit 不算完成（A 的验收基线 = 固定下来的 commit diff）；
3. 旧路径必须死亡（语义迁移类修复强制验「新路径成立 + 旧路径不能再制造 PASS」）；
4. 施工前影响面声明（波及的状态/函数/字段/测试/攻击路径写进修复报告）。
